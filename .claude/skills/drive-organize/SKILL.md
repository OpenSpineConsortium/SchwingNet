# Organize a OneDrive

The drive is read through Microsoft Graph under the owner's own Microsoft sign-in, never through a page's or an extension's session and never through the Microsoft 365 connector, whose walk was retired on the owner's word of 2026-10-20 (docs/research/onedrive-direct-graph.md). The owner signs in once on the control panel's Folders tab (Connect OneDrive, then Track, with the private repository that keeps the catalog chosen in the bar), which seals the sign-in into that repository's secret SYMPHONY_DRIVE_REFRESH; no Microsoft token ever reaches a session.

Reading the drive opens a sample of its files, so start the walk only on the owner's word. Nothing in the drive moves or is renamed until the owner, having read MOVES.md, says go in their own words; a word relayed by another session is not that.

Keep every file of this procedure in the session's scratchpad (written $S below): the catalog and the plan name the owner's files and never go into a commit of a public or internal repository, a reply's text or a log. A reply says counts and project titles, never file names, unless the owner asks.

1. Check the sign-in: the private repository the owner names has .github/symphony/drive.json and the secret SYMPHONY_DRIVE_REFRESH, and carries .github/workflows/drive-organize.yml. If either is missing, give the owner the Folders tab's steps (https://openspineconsortium.com/symphony/control/, Folders, Connect OneDrive, then Track) and stop.
2. Walk it: run that repository's workflow "Drive organizer" with the step catalog (Actions, Drive organizer, Run workflow, step catalog). It lists every folder and file through Graph, keeps the folders Microsoft 365's apps keep listed but unread, digests a sample, and commits catalog.json, TREE.md and digests.jsonl on top of the branch drive-catalog, beside what is there. Its summary gives the counts; a folder still refused after Graph's throttling is named as unlisted.
3. Read it: fetch drive-catalog and read TREE.md first, then catalog.json and digests.jsonl.
4. Propose. Write `$S/plan.json` in the shape `python3 tools/drive_organize.py schema` prints, with the workflow's organize prompt as the rules (projects, each with a domain, its folders and files exactly as catalog.json writes their paths, two to six directions, a plan and tasks; personal records left out). Give a project a `repository` (a name, `team` true when students or other people will join it, and why) when it would sooner live in a Symphony repository of its own that people join, each with their own Claude account, than in this one. Then `python3 tools/drive_connector.py check --plan $S/plan.json --catalog catalog.json` and correct every unknown path and problem it names.
5. Show it on the board: push plan.json as one new commit on drive-catalog, never a forced push. To open the proposals as issues, run the workflow with the step open. A repository a project names is the owner's to make, from the link in its issue.
6. Plan the moves: `python3 tools/drive_connector.py moves --plan $S/plan.json --catalog catalog.json --out $S/catalog`. Give the owner the steps of `$S/catalog/MOVES.md` (one folder "Symphony projects" at the drive's top, one folder per project in it, each item moved in) and ask whether to go. Stop here until they answer.
7. Moving through Graph is not built yet (docs/research/onedrive-direct-graph.md, what is left). Until it is, an approved MOVES.md waits; say so to the owner rather than moving by any other route.
8. Propose the next step. Once the owner accepts a project, or says the drive holds none worth one, open one issue labelled decision (`gh label create decision --force` first) titled "Next step: " and the step: one ambitious enough to keep a worker busy for a day or two, following from the projects and their directions. Its body says why in a few lines and ends with "## Options", two to four lines "- **Label**: what happens if chosen" (Accept and Decline among them, labels of at most 40 letters, digits, spaces, hyphens and apostrophes, starting with a letter or digit) and "Recommended: Label". tools/outlook_digest.py puts it in the owner's Outlook digest with one button per option (docs/research/outlook-digest.md); nothing starts before the owner answers.
