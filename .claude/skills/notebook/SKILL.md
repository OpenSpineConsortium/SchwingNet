# A notebook of drive files

A notebook is a few files taken together as one context, as Gemini's NotebookLM has it: a paper, its data and its sources, say. Nothing on the drive moves. The notebook is a private repository that points at its files by the drive's ids, and beside them keeps what Claude makes of them: research/, drafts/ and references.json. tools/notebook.py keeps the shape; docs/research/notebooks.md says why it is shaped this way and where the owner's rules bound it.

$S below is the session's scratchpad, and the catalog is `$S/catalog.json`. Every step that reads files or writes them back spends the owner's Claude usage: start it on the owner's word. Keep the catalog and the proposal in the session's scratchpad and on a private repository's branch drive-catalog only; a reply gives titles and counts, never file names.

1. Catalog the drive with the drive-organize skill's steps 1 to 4, or fetch the catalog a session already pushed to the private repository's branch drive-catalog.
2. Propose. Write `$S/notebooks.json`: `{"notebooks": [{"slug", "title", "summary", "repository", "files": [catalog paths]}], "left_out": [paths]}`. Group by the work a file belongs to; a file may sit in more than one notebook, since none moves; leave personal records (tax, identity, medical, family, household) out. Then `python3 tools/notebook.py check --notebooks $S/notebooks.json --catalog $S/catalog.json` and correct what it names, and `show` for each notebook's counts, which are what the owner sees first.
3. Show it: push notebooks.json beside catalog.json on drive-catalog as one new commit, never forced, where the control panel reads it.
4. Make a notebook's repository once the owner picks the notebook. The repository is the owner's to create, private, with "Add a README" ticked, from https://github.com/organizations/OpenSpineConsortium/repositories/new (or from symphony-template, Use this template, for a notebook other people will join). Then `python3 tools/notebook.py make --notebooks $S/notebooks.json --catalog $S/catalog.json --slug SLUG --out <its clone>` and push the files on a branch, by pull request.
5. References: the owner exports the notebook's references from Mendeley, EndNote or Zotero as BibTeX or RIS into the notebook's folder or attaches the file; `python3 tools/notebook.py refs --export FILE --out <clone>/references.json`. For a Zotero library, save the web API's answer (`https://api.zotero.org/users/$ZOTERO_USER_ID/items/top?limit=100&start=N`, paging by start until Total-Results is reached, the key in the header Zotero-API-Key, from the environment, never a URL) and read it with `refs --zotero ANSWER.json --library users/$ZOTERO_USER_ID`, which keeps each item's URI. To cite in a document, write `$S/cites.json` (`[{"paragraph": N, "after": "the words the citation follows", "refs": [keys]}]`, paragraphs numbered as the review sheet numbers them) and run `python3 tools/docx_cite.py FILE.docx --refs references.json --cite $S/cites.json --out $S/cited.docx --form word`, or `--form zotero` for a document its author cites with Zotero, whose first Refresh in Word asks once for the document's citation style; the copy goes back beside the file as step 7 says. Elsevier's text and the institution token are used only privately, never in a public repository, a log, a URL or browser code.
6. Work in it: read the notebook's files with the Microsoft 365 connector's read_resource on each item's `file:///<drive>/<id>`, write what is found under research/, one file a question opening with its sources, and what is written under drafts/, each by pull request in the notebook's repository.
7. Edit the files themselves through the lens-review skill: tracked changes in a copy `<name> (review).docx` beside the file, never over it unless the owner says so.
8. Behind the scenes: a scheduled Claude task with the Microsoft 365 connector attached runs steps 6 and 7 on a cadence the owner sets, only on the owner's word, since each run spends usage. A worker in GitHub Actions reaches a work or school OneDrive only once its administrator consents to the Folders app, as Wayne State did on 2026-10-19; then a notebook's repository made from the template, its files tracked on the Folders tab, can read them through drive-sync.yml once the owner's live check of the consent has passed, and the connector task is the fallback.
