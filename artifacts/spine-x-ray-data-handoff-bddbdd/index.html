BUU-LSPINE 400-pair subset

On this PC · not ingested
Images400 AP + 400 LAT, 400 patients
AnnotationEdge lines, CSV per image; L1–L5 (AP), L1–S1 (LAT)
Also carriesSpondylolisthesis type per level; L6 (LSTV) sheet, 7 cases
WhereLocal, 889 MB, 1,602 files

Why it was not used: nobody pointed the pipeline at it. The converter was written against the 7,200-image full release on Google Drive, and the training run ingested the 77 files that download managed — 50 AP, 27 LAT — while this complete subset sat in the CTSpinoPelvic1K repo root. The CSV format is identical to what src/converters/buu.py already parses (10 lines AP, 11 lines LAT, x1,y1,x2,y2,flag), and filenames carry the view in the last character (…Y0 AP, …Y1 LAT).

  1. Copy the folder to the grid: 
    scp -r "BUU-LSPINE_400" go2432@grid.wayne.edu:~/spine-detector/data/raw/buu_400/
  2. Run the existing BUU converter over data/raw/buu_400/AP and …/LA. It needs the source tag changed so provenance stays distinct from the partial buu_v1, then python src/build_dataset.py.
  3. BUU-LSPINE_400_report.xlsx has sheets diag_all, L4L6 and normal_disorder — the spondylolisthesis and L6 labels. Ingest these into the manifest as extra columns; the L6 cases are the ones the level head will care about.
  4. Check for overlap with the 77 already-ingested patients by the 4-digit patient ID in the filename before splitting.

Buys: 400 AP images immediately — more than triple the AP the model has ever seen — plus the first LSTV labels in the corpus.

Why the first attempt got 77 files: the full 7,200-image release is a Drive folder, and gdown --folder stops at roughly 50 files per folder. The 2,000-pair subset on the official site is a single zip, which sidesteps the cap entirely.

  1. On the grid:
    pip install -U gdown
gdown 1qFdU420eLo6rSR0lyuWB9M3rfknXFhvm -O BUU-LSPINE_2000.zip
unzip BUU-LSPINE_2000.zip -d data/raw/buu_2000/
  2. If Drive answers "too many users have viewed or downloaded this file recently", open the link in a browser, choose Add shortcut to Drive, then download from your own Drive — the quota is per-file-per-day on the owner's copy.
  3. Same converter, same patient-ID overlap check against the 400 and the 77.

Buys: 2,000 AP images. With the 400 this takes AP from 125 instances to roughly 12,000.

VinDr-SpineXR

Register + sign DUA
Images10,466 images, 5,000 studies, DICOM
ViewsRoughly half lateral, multi-vendor PACS
AnnotationLesion boxes, 13 types — no vertebra labels
LicensePhysioNet Restricted Health Data DUA 1.5.0

Why it was skipped: the report said it needed a credentialed PhysioNet account. That was wrong. PhysioNet has two tiers — credentialed (CITI course, reference, review) and restricted (registered user signs the DUA). VinDr-SpineXR is restricted. The page states: "Only registered users who sign the specified data use agreement can access the files."

  1. Create an account at physionet.org.
  2. Open the project page, sign the DUA at the bottom.
  3. Download on the grid, not a laptop:
    wget -r -N -c -np --user YOUR_PHYSIONET_USER --ask-password \
  https://physionet.org/files/vindr-spinexr/1.0.0/ -P data/raw/vindr/
  4. The DUA forbids redistribution and use on online platforms. It stays on the grid. Never on HuggingFace, never through an API, never in a shared Drive. Each person who touches it signs their own DUA.

Buys: the largest pool of real multi-vendor DICOM laterals available. No vertebra labels, so it is a pretraining / pseudo-label pool and an annotation target, not Stage-1 supervision.

CSXA — Cervical Spine X-ray Atlas

Free login, browser download
Images4,963 lateral cervical PNG + 4,963 JSON
Annotation23 keypoints: 4 corners × C3–C7, C2 lower endplate
Per imageSex, age, mm/px, symptomatic, curvature class

Why there are zero images on disk: the GitHub repo downloaded fine — datasets.xlsx, the pixel-scale script — but the images live on Science Data Bank (doi 10.57760/sciencedb.15391), whose download is a JavaScript UI behind a login. Eight guessed API endpoints were tried (sdb-file/file/list, sdb-core/dataSetFile/list, sdb-open/dataset/… and others); all returned errors. The report's own line: "SciDB listing not obtained; images need a browser session." Nothing about the license blocks it — this is purely that a script cannot drive their web app.

  1. Make a free ScienceDB account and log in in a browser.
  2. Open the record (dataSetId 8e3b3d5e60a348ba961e19d48b881c90, "Cervical Spine X-ray Atlas (CSXA) V3.0") and download the datasets folder — it contains datasets-PNG and datasets-JSON.
  3. Move it to the grid: 
    scp CSXA*.zip go2432@grid.wayne.edu:~/spine-detector/data/raw/csxa/
    The repo with dataset.xlsx is already at data/raw/csxa/CSXA-dataset-main/; you need both, the mm/px table is only in the repo.
  4. If the browser download stalls on 4,963 files, ask ScienceDB support for a bulk zip — the record is CC BY 4.0, so there is no access argument to have.

Buys: the largest annotated lateral spine dataset in existence, with physical scale per image. The report called its absence "the single biggest gap in the corpus."

Two possible causes and gdown cannot tell them apart: the owner restricted the file, or it hit Drive's daily download quota. The repo offers no other host and no contact email.

  1. Open the link in a browser while signed in to Google. If it downloads, scp it to the grid and it is done.
  2. If Drive says the quota is exceeded: Add shortcut to Drive, wait a day if needed, download from your own copy.
  3. If it says access denied: the file is private. Request access through the Drive prompt, and email the authors — paper is Zeng Y, Wang K, … Song B, Electronics 2024;13(11):2137 (Anhui Medical University / CAS Hefei). No corresponding email is in the metadata; the MDPI page has it.

Buys: the only public intraoperative spine radiographs — the one place surgical metal and labeled vertebrae coexist. Small, but nothing else covers fluoroscopy.

    rclone config   # new remote, type drive

Buys: the remaining 1,200 patients and the full LSTV / spondylolisthesis label set.

AASCE / SpineWeb Dataset 16

SpineWeb request form
Images609 standing AP full-spine, EOS
Annotation68 landmarks = 4 corners × 17 vertebrae, T1–L5
AlsoCobb angles (PT / MT / TL), two radiologists
SourceLondon Health Sciences Centre; MICCAI AASCE 2019

Why it was not obtained: SpineWeb gates the archive behind a request form; no script route exists. Its absence is why the corpus has no thoracic levels and no AP full-spine at all.

  1. Request Dataset 16 at spineweb.digitalimaginggroup.ca (Datasets → Dataset 16). Others have documented the process in tensorflow/datasets #974.
  2. Apply the published landmark-ordering exclusion lists before use — the annotations have known ordering errors.
  3. Levels are implicit by index: the top annotated vertebra is assumed T1. Any film not starting at T1, or any 13-rib / L6 spine, shifts every label below it. Spot-check 50 images against rib and sacrum visibility before trusting a level from this source. This is precisely the failure the whole project is about.

Buys: the only AP full-spine source with corner landmarks, and the only thoracic coverage.

Rules that apply to all of it

  • Everything lands on the grid at ~/spine-detector/data/raw/<source>/, never on a laptop or a personal Drive. VinDr in particular may not leave it.
  • Patient-disjoint splits. BUU pairs an AP and a lateral per patient; Mendeley contains BUU patients; NHANES participants have two films. Split by patient ID, never by image.
  • Do not invent levels. Where a source gives positions rather than names (BUU, AASCE), the manifest records level_source = inferred_from_position. That distinction is the project.
  • Do not use: Kaggle "vertebrae X-ray images" (scraped, murky), TrainingDataPro spine sets on HuggingFace (commercial scrape), Kaggle "Lumbar Coordinate Pretraining" (it is RSNA 2024 MRI, routinely miscited as X-ray).
  • Acknowledge every source in anything presented — BUU's terms require it by name.
