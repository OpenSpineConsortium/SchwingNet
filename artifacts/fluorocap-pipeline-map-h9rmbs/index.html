FluoroCap: how the pieces fit

Six lanes, left to right: images come in from every reachable source, are made into documented panels, get every independent line of evidence a model or a reader could use, are decoded into one contiguous run per panel with a written justification, feed the learning loops, and are served. Each card names the tool, why that tool, and what it writes. The second diagram shows what waits for what.

Synchronisation: what waits for what

Every stage is a Slurm job or a login-node orchestrator that polls for a file or a job name. Outputs are JSON lines named by a run tag, so any stage can be rerun and every consumer finds the newest evidence. Nothing shares memory or a database; the filesystem is the contract.
