How a run starts

greg types nothing on the grid. Claude sends one gate word, and the answer comes back as a file Claude reads.

What start submits

One word submits the whole graph with Slurm dependencies. The accented path is version 1, which no longer waits on the multi-day X-ray fetch.

The gate words

These seven words are everything Claude can ask of the grid for SchwingNet. Every word refuses a bad word or argument, a second word sent while one still runs, and a failed squeue.

WordWhat it doesWhat it refuses
startSubmits the whole graph above once. Setup runs only when pixi.lock changed, and the weights job only when the file is missing.Any of the gate's jobs still queued or running (75).
statusLists the gate's newest jobs from sacct, the end of each stage report, and the newest run's checkpoint, W&B link and test table.Nothing; it submits nothing.
leaksRuns the leak checks over every shard on the volume, an array of fingerprint tasks and then a join.An ingest or catalog job still live, the leak checks still live, or no environments yet (75).
v1Submits the version 1 run alone, for a second try after a failure.A version 1 run already live (75); no catalog version or no weights file (2).
latencySubmits the latency jobs for the newest run with a checkpoint, with one recorded C-ArmLSpine sweep.Latency jobs still live or no environments (75); no run with a checkpoint (2).
fetch <id>Fetches one set of grid/fetch-xray.json, then banks and catalogues it. A credentialed set reads greg's ~/.netrc inside the job.An unknown id (64); a missing ~/.netrc or one not mode 600 (2); a fetch holding that set still live (75).
stopCancels the gate's own queued or running jobs and nothing else.Nothing.
0 done 64 refused 75 busy, send again later 2 a file or the checkout missing 1 a submission failed
