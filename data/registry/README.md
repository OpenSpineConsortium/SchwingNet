# The registry

One JSON file per source that enters the training workflow, in the shape schwingnet.catalog.RegistryEntry: the identity level a split must not share, the person-key rule, the access statement, the modality and device class, the regions, the grid root and the shards ingested so far. The dataset inventory under data/sources/ says what a dataset is and how to get it; a registry entry says how it enters the catalog (docs/research/data-catalog.md). `pixi run --locked python tools/catalog.py check` validates every entry against the shape.

The layout the tool holds every entry to (docs/research/data-catalog.md, "Read-only versions, the layout and the accounting"): the file is named `<source>.json` after its `source`; `grid_root` is the source's own folder, `<data root>/<source>`, so the data root lists its sources alphabetically by id; every shard's manifest is at `<grid_root>/shards/<ingest date>-<12 hex>/MANIFEST.json`, where tools/ingest.py writes it; a raw copy a source came with stays where it is and is named in `notes`. A new dataset is one new file here, one folder under the data root and one ingest.
