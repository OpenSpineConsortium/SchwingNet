Every artifact in the claude.ai artifacts gallery of every account of the owner's is kept as files in artifacts/ of the repository its work belongs to, so any account can edit and republish it, less what the export's screen holds back for the owner's decision (an e-mail address, a credential, a person on a screenshot).

The owner asked on 2026-10-22 that all artifacts be pushed into the repositories, editable by anyone, and consolidated across all his accounts continuously. An artifact on claude.ai belongs to one account and only its Share menu, which a session cannot change, lets others see it; a file in a repository is read and changed by every account through pull requests.

- Where: artifacts/ at the repository's root (outside docs/, whose ASCII rule the pages' typography would break). Symphony and Beethoven artifacts go to OpenSpineConsortium/symphony-template; spine, fluoroscopy, SchwingNet and spine-program ones, and anything that might describe SchwingNet's methods, here, the only place SchwingNet's patent material may go; when unsure, here, and the skill sorts by a search of the whole copy, never by the title alone. Nothing here is ever shared by link.
- Shape: one folder per artifact, named in kebab-case after its title; a page as index.html with every other published file beside it at its published path; a Claude Docs document as index.md, exported as Markdown. artifacts/README.md has one row per artifact: title, folder, link, the account that owns the link, what it is.
- How: symphony-template's export-artifacts skill (.claude/skills/export-artifacts there), run once per account from a session on symphony-template with this repository beside it, does all of it. By hand: Artifact tool action list (scope mine) for the account's own artifacts; action read with path index.html, plus a scope files listing and a paths read for the rest; for a Docs document, Claude Docs read of the link, then export of its tab as markdown, written to its file by symphony-template's tools/docs_export.py from the session's own transcript, never retyped. A Design-type artifact's own files are under project/; its index.html is only the type's shell.
- On the grid: after each merge that changes artifacts/ here, the export skill starts symphony-template's .github/workflows/artifacts-grid.yml, which says the gate's job word artifacts (hpcworker tools/grid_gate.sh) and keeps a clone of this repository's artifacts/, and of symphony-template's, in the owner's ~/claude-artifacts (0700), so a grid worker on any of his accounts reads them; it also runs every six hours. Its CLAUDE.md says edits go by pull request from a clone of one's own.
- Ongoing: each new artifact a session makes is added the same way, in the pull request of the work it came from only when the sort sends it to that repository, otherwise here, and a session on another account repeats the export for that account's artifacts. The repository copy is the one to edit; republish from it with the Artifact tool.
