Files a cloud session holds and the grid needs, such as a Claude project's shared folder, which does not follow the owner to another project, reach the grid as a carried folder: a private branch, a record under grid/carry/ and the gate word `fetch <id>`, with no job.

- The session pushes the files to a branch of a private repository as a history of its own whose last commit holds the folder alone with SHA256SUMS over every other file, in commits of about 100 MB: the session's proxy closed a 248 MB push mid-way on 2026-10-28, while pushes of 50 to 164 MB went through.
- A pull request adds grid/carry/<id>.txt (repo, branch, commit, files, bytes, manifest; grid/carry/README.md). Once it is on main, `schwingnet-fetch-<id>` through grid-accounts.yml makes the gate fetch the commit with git on the login node through gh's sign-in, check it, its counts and every file against SHA256SUMS, and land it as the data root's <id>, 0700, with meta/CARRIED, under the size rule's lock (twice the bytes and a fiftieth). A later send checks it again and fetches nothing.
- The first: the project "symphony_4"'s shared folder (gold3-ct, enhance-pet-repair, drr-domain-gap-monitor, mask-free-import; 3,332 files, 1,107,335,194 bytes), on bordercall's branch claude/project-thread-rr7in4, the owner's word of 2026-10-28 17:24 UTC.
- The branch is a carrier: never merged; the owner may delete it once the landing is checked.
