The auto-anatomist screen runs on the grid as the word `autoanatomist <plan>`, the smoke on the owner's count of 2026-10-30 03:20 UTC and the screen's two jobs on his word of 08:56 UTC, each plan sent once.

- The flow is AutoanatomistFlow (flows/autoanatomist.py), a trial or the join of a plan under grid/screens/, held to docs/research/autoanatomist-screen/PREREG.md and to the plan's bytes; the job script is grid/autoanatomist.sbatch and the network bordercall's copy under grid/autoanatomist/ (tools/bordercall_vendor.py copy, never a hand edit).
- grid/gate.sh queues a plan only where AUTOANATOMIST_COUNTED names it, and sends it again only after a fix moved the checkout, after a send Slurm ended before any part started, or on the owner's word in AUTOANATOMIST_RERUNS; gold3_latent_smoke is one GPU job, gold3_latent_screen a GPU array of eight trials and a CPU join afterany it.
- Constraint: the grid's train-gpu Python is 3.11, so the trials' venv pins jax[cuda12] 0.10.2, flax 0.12.8, optax 0.2.8 and orbax-checkpoint 0.12.8 (schwingnet.autoanatomist_screen.PINS, held by tests/test_gate.py).
- Constraint: flows/launch.py reads a relative path parameter from the folder it started in, so the job passes every path absolute, the plan as its own copy's.
- The plans keep one person split with the latent-prior evaluation: every test list of schwingnet.autoanatomist_screen.TEST_LISTS stays out of them, and tools/autoanatomist_plan.py check, in scripts/check.sh under pixi and in the gate lane's tests/schwingnet/test_autoanatomist_screen.py, fails a plan that holds a listed person.
- docs/research/autoanatomist-screen/README.md says where the screen stands.
