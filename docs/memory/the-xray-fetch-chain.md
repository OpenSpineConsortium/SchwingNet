The X-ray datasets and the data platform's unfetched sources reach the grid through grid/: one paste submits two afterany chains of reqp/requeue jobs.

grid/README.md is the owner's paste (issue #38, 2026-10-21). grid/run-xray-chain.sh submits three jobs, 01-fetch (tools/fetch_sources.py over grid/fetch-xray.json, the data platform's reacquire.py helpers, FETCH.json with every file's sha256 at <data root>/<id>/), 02-bank-ingest (tools/bank.py by a recipe grid/banks/<id>.json, then tools/ingest.py per source) and 03-catalog (tools/catalog.py build over every MANIFEST.json under the data root, then split-check), each stage writing a STAGE-REPORT.md under grid/logs/. grid/run-platform-fetch.sh submits one grid/platform-fetch.sbatch per source of spinesurg-ct-nnunet's data_platform/sources.json that is not on the grid, through acquisition_fetch.py (zenodo, s3, hf, idc with a manifest grid/idc_manifest.py writes from idc-index). Both read the volume's free space with df and refuse to submit beyond it minus 5 TB, since acquisition_fetch.sh stops its own job under 5 TB free; CT-RATE (21.3 TB) and MIMIC-CXR-JPG (570 GB) are separate lines the owner runs or skips; the full NLST (2.3 TB) is fetched alone by the gate word fetch idc_nlst since the owner lifted the stopping rule on 2026-10-22, choosing what the volume holds from the tally the gate word status prints first (CephFS ceph.dir.rbytes per set, labels and never paths). PadChest comes from BIMCV's B2DROP share by the nextcloud route (WebDAV listing, the share's own download link, sizes checked), whose link the agreement keeps inside the organisation, so no log prints it. Each open set has a registry entry data/registry/<id>.json; a recipe field spelled "to confirm" stops that source until the page is read; DICOM sources wait for pydicom in pixi.lock; tokens come from mode-0600 files, never a command line. The hf-token route's reacquire.py hf-get reads --include as a glob (fnmatch, as huggingface_hub's allow_patterns), never as the regular expression the acq and zenodo routes read, and returns 0 having verified no file when it matches none, so a whole repository takes no --include and grid/platform-fetch.sbatch fails such a run with exit 3 (issue #158: FluoroSeg's and ReXGradient-160K's `.` and CADS's `CT-TRI/*`, where the tree's folder is 0043_new_ct_tri, each ended COMPLETED with nothing fetched on 2026-10-23).
