The Artifact Textbook is also one private claude.ai artifact, published and republished to the same link from the owner's computer by `python3 tools/textbook_publish.py local`, never by a workflow or a cloud session; it lands in the gallery of the claude.ai account Claude Code is signed in to there, private until that account shares it.

The owner decided on 2026-10-24 (a decision card at 18:15 UTC, issue #236) that the book goes to claude.ai rather than claude.ai coming to the book: a live claude.ai artifact answers content-security-policy frame-ancestors 'self' and two extension ids and serves its content from a per-artifact frame origin, so no other site, the members-only Pages site included, can embed one (docs/research/textbook-as-an-artifact.md). A cloud session's guard refused the publish of the built edition as data exfiltration that day, even with the owner's card, so a cloud session never publishes the book. The owner then chose a GitHub Action, whose first run (2026-10-25, run 40151692244) found its session had no Artifact tool, as Claude Code's documentation says of the GitHub Action, the Agent SDK and `claude -p`, whatever the settings say. On 2026-10-25 at 02:52 UTC the owner chose to publish from the owner's computer, a new edition when the owner wants one, never automatic (#277), and the workflow went.

How it works. tools/textbook_artifact.py turns the site tools/textbook_site.py wrote into the artifact's files: the front page as the Artifact tool's page proper, every other page whole, the figure records left out and "The record" pointing at GitHub at the built commit, an edition line naming the commit and its own date, never the clock, and on every page the Ask Claude box (the runtime's sample capability, on the viewer's own account) with Run as me through the viewer's GitHub connector. `python3 tools/textbook_publish.py local`, run in a clone on the owner's computer (`python -X utf8` where python3 is the Windows Store's stub), fetches main, reads the record, stops where the book's inputs at main's head are already published (--anyway publishes again), builds the site and the edition with that commit's own builders in a worktree inside a work folder beside the clone (SchwingNet-textbook-edition by default, never inside the clone, so the session loads none of the repository's files), plans batches of at most 240 files and 60 MiB, and opens Claude Code there on prompt.txt. The session publishes, writes its marker lines (ARTIFACT_URL=, PUBLISH_INCOMPLETE=, CAPABILITIES_REFUSED, ARTIFACT_TOOL_MISSING) to answer.txt and asks the person to type /exit; the command then records the edition and prints the link. --no-launch, or no `claude` on the path, leaves the folder ready and prints the two steps by hand, ending with `local --record`.

The record is state.json on the branch textbook-artifact: the link, the commit and date the edition was built from, the fingerprint of the inputs (git ls-tree over tools/textbook_publish.py INPUTS, which a test holds to every module the builders import, #269) and every published path's sha256, written as fast-forward commits from a small bare repository in the work folder, since the clone's pre-push hook refuses to push anything but the checked-out tree, and never replacing a branch that holds anything else. A publish cut short records the link with nothing published, so the next one sends the whole edition to the same artifact. The edition of main on 2026-10-25 is 453 files and 108.5 MB in three batches. Nothing of the book is public before the provisional is filed (docs/memory/the-textbook-website.md); the artifact is shared, if at all, from its Share menu by the account that holds it.
