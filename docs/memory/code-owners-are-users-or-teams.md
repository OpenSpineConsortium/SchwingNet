GitHub asks a user or a team for review as a code owner, never an organization, so template-init names the person who made an organization's copy in .github/CODEOWNERS.

GitHub's "About code owners" says a CODEOWNERS line names owners as `@username` or `@org/team-name` (or an email address on a user's account), that users and teams need explicit write access to the repository and a team must be visible, and that a user or team that does not exist or lacks access is not assigned. An organization's name alone is neither a user nor a team, so `* @ORG` asks nobody for review and only GitHub's list of the file's errors says so (`gh api repos/OWNER/NAME/codeowners/errors`, or the file's page on GitHub).

So .github/CODEOWNERS carries its own placeholder, CODE_OWNER, besides OWNER: tools/template_init.py fills it with the owner in a personal copy and, in an organization's copy, with the login of the user who sent the push event that started its run (the person who pressed "Use this template"), read from the event file Actions names in GITHUB_EVENT_PATH, so .github/workflows/template-init.yml did not change. A copy made by an app keeps the organization's name, and the run's log says to replace it. scripts/setup-repo.sh prints GitHub's list of the file's errors as its last step; docs/setup/github.md, section 7, says how to name a team instead.

Learned during the crowd mode end-to-end run on 2026-10-10. GitHub's page was read from its source in the github/docs repository, since docs.github.com was unreachable; the behaviour has not yet been seen on a live organization's copy.
