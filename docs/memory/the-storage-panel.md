The textbook's storage panel (docs/textbook/figures/22/, chapter 22) is built by tools/storage_panel.py from a committed snapshot of spine-datasets' feed, PLAN.json on its branch storage-feed: the lab volume's and the owner's home's use, every set the feed knows, the combinations that fit under the target, and a selection the page dispatches only through spine-datasets' storage.yml, whose run opens a request pull request, so nothing is fetched, moved or removed before the owner merges it.

The owner asked on 2026-10-24 at 20:34 UTC to know the drive usage from the artifact, to trial combinations of datasets under 20 TB, to trigger the removals and additions, and to place some data on the owner's 4 TB home (issue #244, pull request #245; docs/research/storage-panel.md has the feed's contract and what was verified).

- The feed. spine-datasets rebuilds PLAN.json on its branch storage-feed on every push to its main that touches a record, after each request its workflow opens, and daily at 05:53 UTC: format, built_at, read_at, target_bytes, requests[] (number, url, selection), volume (quota_bytes, used_bytes, read_at, datasets_bytes, other_bytes), home (quota_bytes, used_bytes, null until the owner names the home's path and a grid word reads it, read_at) and sets[] (id, name, group, reach, fetchable, status, location lab, home or none, bytes, the measured size once frozen, else what the source states, else null, bytes_known, licence open, restricted or unknown, rebuild, frozen, overlap[] with, patients, series, same_bytes). The selection grammar is `-id` removes, `+id` adds, `id@home` and `id@lab` place, tokens separated by spaces; `python3 tools/storage.py check SELECTION` there refuses an over-cap or sizeless fetch and any move to the home while its use is null.
- The tool. `python3 tools/storage_panel.py fetch` reads the feed through GitHub's contents API with STORAGE_FEED_TOKEN (else GITHUB_TOKEN), follows no redirect so the token reaches no other address, and writes the snapshot docs/textbook/figures/22/storage-plan.json in one canonical shape, exiting 2 with no token and 1 with one sentence when the feed is unreachable; `build` writes storage.html with the snapshot inlined (no fetch at view time), storage.svg (the drive bands, the chapter's image line) and storage.json (the record, with the snapshot's sha256 and the feed's built_at and read_at); `check`, in scripts/check.sh, fails when a committed file is not what the snapshot gives. .github/workflows/docs.yml runs fetch with the App's read token on spine-datasets before each site build and builds from the committed snapshot when the fetch fails, never failing the deploy; the figure's Re-run redraws from the committed snapshot.
- The page. Drive bands with the target marked and an age badge per reading; the pending requests as links; a table of every set (filter by name, id or group; a changed-only view) with keep, remove, add (fetchable sets only) and place lab or home, the home greyed with its reason while its use is unread; totals after the choices against the target and each quota, red where a cap is passed or a chosen set has no size, with the planner's refusals in words; overlap notes from the sets' own overlap lists, never all pairs; the selection with Copy (clipboard, else the text selected). The arithmetic is tools/storage_panel.py's model mirrored in the page's MODEL_JS, and tests/test_storage_panel.py runs both on one plan with node.
- The host protocol, the figure's side only (the hosts are the site's page around each framed figure, tools/textbook_site.py, which answers every dispatch and read "no connector", and the artifact edition's, tools/textbook_artifact.py, which carries the connector): Apply posts {type: "schwingnet.dispatch", repo: "OpenSpineConsortium/spine-datasets", workflow: "storage.yml", ref: "main", inputs: {selection}, label: "storage", fallbackUrl} to the parent window and listens for {type: "schwingnet.dispatch.result", label, ok, error}; Refresh posts {type: "schwingnet.read", id, repo, path: "PLAN.json", ref: "storage-feed"} and re-renders from {type: "schwingnet.read.result", id, ok, text, error}; with no answer in 8 seconds, or ok false, the page shows the workflow's link, the selection to paste into its selection input and one line saying a request pull request then waits for the owner's merge. On the Pages site the figure's iframe is sandboxed without popups, so a link inside it cannot open a tab; the figure's Explore button carries the workflow's link, and the fallback posts {type: "schwingnet.open", href, label} to the page around it, which shows the link in its bar.
- Two readings the panel makes of the contract, not verified against storage.py: an addition placed on the home is written as two tokens, `+id id@home`; a stated but unmeasured size (bytes given, bytes_known false) is summed and marked stated, and only a null size is refused as sizeless.
