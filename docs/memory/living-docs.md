Lessons under docs/learn/ are living documents: the check runs their commands, their notebooks are generated, and the docs site is built from them, the docstrings and the test results.

tools/living_docs.py runs every block marked `bash run` in each lesson (docs/learn/0N-*.md) in a fresh practice folder, each block in a bash of its own that opens, on the page, with `cd "$LAB"` after the lesson's one `bash setup` block (which the check and the notebooks replace with their own), and fails when the `output` block after it is no longer printed, lines matched in order as substrings; scripts/check.sh runs `test` and `check`. `check` also fails when a lesson's notebook under docs/learn/notebooks/ differs from what `notebooks` would write, so after changing a lesson run `python3 tools/living_docs.py notebooks` in the same pull request, the notebooks clone the library's newest release at run time, so a vendoring pull request leaves them current; `check` fails, too, when a module under tools/ or scripts/ has no docstring or a shell script no opening comment, since the site's Reference page is made from them. A board snapshot in a lesson carries claimed issues' labels in `claim_issues` as well as `issues`: the board reads a claim's blocker label only from there. A lease written in any page names its ref and tip (`--force-with-lease=claude/N:<tip>`), which tests/test_claim_skill.py enforces. .github/workflows/docs.yml builds the site on each push to the default branch and deploys it with Pages only when the variable SYMPHONY_DOCS is pages; on 2026-10-20 the owner chose members-only Pages on symphony-template for now.
