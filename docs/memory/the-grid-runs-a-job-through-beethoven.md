A workflow job can run on the WSU grid through the runner chain that hpcworker's tools/grid_runner.sh serves as Slurm jobs; the connection points from the grid out, a job on the grid holds only its own one-job credential, and the one thing of the grid's at GitHub is the ssh gate's key, which can only start, read or stop that chain.

.github/workflows/grid.yml runs one command on a compute node, in a checkout of the ref, and keeps the output as the job's log and as an artifact; it runs only for an event that names a private repository that is not a fork, never for a fork's pull request (the setting "Run workflows from fork pull requests" stays off), and skips a caller started by a schedule. A step never reaches Slurm, the home or the lab volume; the chain stops itself with the reason after three jobs in a row that could not serve, and on each actions/runner release that asks for an update, until the owner runs --install and --start. The runner is GitHub's own, inside its own image (the runner needs RHEL 8 or later, the grid's nodes are EL7) as a Slurm job on reqp/requeue, registered one job at a time with a just-in-time credential the account's gh mints on the grid into a mode-0600 file that leaves with the job. Nothing is pushed in and no Claude token goes there: claude.yml, workers.yml and coordinator.yml stay on GitHub's machines. The chain is the owner's to start from the portal's shell; docs/setup/grid.md has each step with its link, hpcworker's docs/OPEN_QUESTIONS.md what the grid has not yet shown, and docs/research/wsu-grid-and-github-actions.md what was measured and weighed, with the second step decided on 2026-10-16 and built once the owner's test of 2026-10-17 showed that a key alone signs in to grid.wayne.edu from outside the VPN: the ssh gate. hpcworker's tools/grid_runner.sh --gate-key, typed by the owner, writes one restricted line whose forced command, tools/grid_gate.sh, takes one word, start, status or stop, for one repository's chain, once a minute; .github/workflows/grid-gate.yml says it from GitHub's machine with the key from the environment grid's secret GRID_GATE_KEY, and grid.yml's start box runs it first. hpcworker's tools/grid_runner.sh --gate-setup, typed once in the grid's shell, does the whole setup there (the environment, the key, its line, the variables, the secret through gh's standard input, the key deleted, a first status run), so nothing runs on the owner's computer. The gate never queues a job of its own and never opens a shell; the password is nowhere (docs/setup/grid.md, "The ssh gate").
