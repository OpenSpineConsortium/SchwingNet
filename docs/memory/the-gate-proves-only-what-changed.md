The gate's symbolic lane, CrossHair and Z3 over the package, proves only the modules a change reaches, both in gate.yml and in the pre-push hook (beethoven-qa 9.0.0, taken 2026-10-25; from 10.0.0, taken 2026-10-26, pyproject.toml is read by its keys), so a green proof on a pull request that changed no module says CrossHair had nothing new to prove, not that it proved every module again.

- The rule is the pinned copy's src/beethoven_qa/scope.py. A changed module reaches itself and every module that imports it. pixi.toml, pixi.lock, the pinned copy under vendor/, a module that imports by a computed name, and a link or submodule git tracks anywhere reach every module. A document, data, a test or a workflow reaches none.
- pyproject.toml is judged by the keys whose values differ (scope.table_reach, 10.0.0): a comment, an entry of [tool.beethoven-qa.unproven] added or reworded, the boundary table and the table of a quiet tool (ruff, mypy, pytest, bandit, black, isort, flake8, pylint, pyright, codespell; never coverage) reach no module; an unproven entry removed reaches the one function it set aside; any other key reaches every module and the proof line names it. #401 added one unproven line and re-proved every module under 9.0.0, which is why the owner asked on 2026-10-26 to keep the proof to what changed. The gate's other check still covers the whole package, and the line `gate: proof: ...` says which modules were proved.
- In CI the base is the newest commit of main the gate passed on a push, given to the lane as BEETHOVEN_QA_BASE by the step "the commit the proof starts from". On a pull request the commit checked out is GitHub's test merge, so main's own changes since that commit count too. Where GitHub names no such commit, git cannot read it, or gate.yml itself changed since it, the lane proves every module, as it does once a day on main and when the gate is run by hand from the Actions tab.
- The kit's .githooks/pre-push sets BEETHOVEN_QA_BASE=auto, where the branch left origin's main. `BEETHOVEN_QA_BASE=none git push origin <branch>` proves every module before that push.
- Why: on 2026-10-25 the lane was 31 of the gate's 32 minutes. 76 of the day's 85 pull-request runs, about 1,480 billed minutes, re-proved a package their pull request never touched, and the hook spent the same quarter of an hour before every push. That day the organization's included Actions minutes ran out.
