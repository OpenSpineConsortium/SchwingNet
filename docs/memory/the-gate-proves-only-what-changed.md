The gate workflow runs its symbolic lane, CrossHair and Z3 over the package, only where a change touches what that lane reads, so a green gate on a pull request that changes none of those paths says CrossHair found nothing new to prove, not that it ran.

- The lane reads src/, tests/schwingnet/, vendor/, conftest.py, pyproject.toml, pixi.toml, pixi.lock and .github/workflows/gate.yml itself. Each run asks GitHub for the newest commit of main the gate passed on a push and compares it with the commit checked out, which on a pull request is GitHub's test merge. The lane runs where any of those paths differs. It also runs in full once a day on main, when the gate is run by hand, and whenever the comparison cannot be made.
- Why: on 2026-10-25 the lane was 31 of the gate's 32 minutes, and 76 of the day's 85 pull-request runs, about 1,480 billed minutes, re-proved a package their pull request never touched. That day the organization's included Actions minutes ran out.
- The pre-push hook still runs the whole gate before every push, so a session's push takes as long as before. Only CI's minutes changed.
- A run that skipped the lane says so in its step "whether the symbolic lane reads anything this change touched". The step names the commit it compared with and the first paths that differ. To prove the package on demand, run the gate from the Actions tab with "Run workflow".
