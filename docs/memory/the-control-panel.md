The control panel is two pages of the site, /symphony/control/ to drive a Symphony repository through GitHub's API as the signed-in person and /symphony/cost.html to price the work against the other ways of running coding agents on GitHub; neither held a Claude token until the owner dropped that rule on 2026-10-18 for the Tokens page's Add a slot box.

# The control panel

- Where: OpenSpineConsortium/openspineconsortium.github.io, the body files tools/pages/symphony/control/index/body.html and tools/pages/symphony/cost/body.html, one script assets/js/symphony-panel.js and assets/css/control.css, built by tools/build_site.py like every page; the panel is out of the navigation (hidden=True) and linked from /symphony/, the cost page is in it. Plain HTML and JavaScript, no dependency, no server of ours: the page calls api.github.com as the person.
- What it drives: adds a repository (one whose About carries the topic symphony joins the list; another gets the two presses, the App's install link preselected for it and the form); shows the board (STATE.md on the branch board), the queue, the issues given to workers, claimed, in review, blocked and the epics; queues a task as an issue labelled todo in the Task form's shape; asks Claude with an issue or a comment that mentions @claude, which claude.yml answers; registers a worker as an "Add a worker" issue in the form's shape, which add-worker.yml turns into the pull request; lists the pull requests with their checks and merges a ready one whose checks are green; starts the workers, the board, the checks and the metrics by workflow_dispatch. Every state is in words under the summary line and every button is named, so a Claude driving a browser reads and presses it like a person; ?repo=OWNER/NAME opens a repository.
- Sign-in: "Sign in with GitHub" first, as the owner asked on 2026-10-16 (one-click sign-in as the primary option, as opposed to a fine-grained token): the SymphonyBoard App's user token through the stateless sign-in service symphony-app/signin (a Cloudflare Worker that holds the App's client secret, exchanges the code with PKCE, refreshes, revokes, keeps nothing). The button is the first thing on both pages and can be pressed since 2026-10-17 (site #24): SIGNIN_SERVICE is https://symphony-signin.openspineconsortium.workers.dev and CLIENT_ID is SymphonyBoard's Iv23liTkIRov2FYN83wD, neither a secret; emptying either turns the button off again, with one line saying why and the token box open. The browser checks set the two constants themselves (symphony-app#17), so they run whatever the site ships. The fallback, folded under "Use a fine-grained token instead", is a fine-grained personal access token the person pastes. Either is kept in the browser only (localStorage with "Keep me signed in", else sessionStorage, where a sign-in for one tab keeps its refresh token in the page's memory alone, so it ends with its eight-hour token once its page is gone, closed, reloaded or left for another page); a pasted token is asked about at GitHub before it replaces anything; the tabs renew a sign-in in turn, only GitHub's bad_refresh_token ends one, a tab whose own sign-in ended takes up no other, and Forget the token signs out at once every tab that used the kept one and ends a renewal waiting its turn; a call goes out with a token GitHub has named for the page, or, while GitHub has named nobody, with one of the tab's own (the one it opened with, the one the person gave it, its renewals), and a write only for the account the page named when it was asked for, or, asked for while the page named nobody, only with the tab's own token (the fifth review, openspineconsortium.github.io#23). The workers themselves run on the repository's own secret. The rule that the panel never takes a Claude token was the owner's, and the owner dropped it on 2026-10-18, saying it was set arbitrarily: the Tokens page's Add a slot box saves a pasted token as an organization secret through the App, which then needs permission to write organization secrets, granted by the owner in the App's settings. The box, the Tokens page and that permission are the work of the thread that owns the Claude tokens, and the Apps' privacy statement, which says the pages never take a Claude token, is versioned before the box goes live, since it is the exhaustive list of what the Apps hold.
- The cost page reads METRICS.json on the branch metrics (economics and coordination, docs/setup/metrics.md) and prices the same tokens under an API key, GitHub Copilot's coding agent, unsorry and OpenAI; its price table (PRICES_AS_OF in symphony-panel.js) is kept beside tools/economics.py's and every source is linked at the foot of the page. unsorry (agenticsnz/unsorry) is the closest rival: volunteers' own agents, coordination in Actions.
- The Apps' privacy statement (symphony-start PRIVACY.md, version 9, rendered at /symphony/apps-privacy.html) covers both pages: what they read and write, where the token is kept, that the service keeps nothing and the developer receives nothing.
- The research note docs/research/control-panel.md holds the ask, the design decisions, the cost comparison with its prices and sources, the reviews' findings, what waits on the owner and the follow-ups; it is kept current by the thread that built the pages. The pages' browser checks, mutants and reviews' scripts are kept in symphony-app's signin/panel-checks/ (symphony-app#16), with a README on running them.
- The assistant (design A of docs/research/control-board-graph.md, the owner's choice of 2026-10-17): the panel asks its questions through an issue "Assistant: <login>" labelled assistant, which claude.yml answers read-only in ten turns with .github/symphony/assistant.md appended to the system prompt (docs/setup/claude-action.md, The assistant issue); the page's side is the Ask Claude bar frozen at the console's foot on every tab (first the Assistant section, openspineconsortium.github.io#28, 2026-10-18; the bar since the thread "Ask Claude bar", docs/research/ask-claude-bar.md), which opens the issue once per repository and person, reads the answer with If-None-Match until the action's final header opens the comment, and acts on its symphony block, doing the reads by itself and offering the changes (run a workflow, give, merge, draft a task or an @claude prompt) as buttons that run the panel's own handlers only on the person's press; its twenty browser checks are symphony-app's signin/panel-checks/e2e2/assistant.test.mjs, and the Apps' privacy statement version 11 lists what it does and keeps.
- Layout (2026-10-18, docs/research/control-panel-console.md): /symphony/control/ is one console that fills the window under the site's 64 px header (the strip is a hover drop-down), a side column with the repository's whole name, the GitHub links and the rail of tabs (Command, Board, Tasks, Pull requests, Runs, Workers, Ask Claude, Tokens, Share, Repositories, About), one tab at a time, each scrolling inside itself, and a status line at the foot that holds the page's message (#msg) and who is signed in, always visible; nothing is added above the tabs; Command holds the readouts and the launch buttons; the Tokens page is the Tokens tab and tokens.html only forwards to /symphony/control/#tokens; a new section is one rail button and one panel; the browser checks open a tab before touching what is in it (signin/panel-checks/e2e2/console-tabs.mjs). Since site #51 and #56 a new message flashes the status line, a Full screen button hides the site's header, #cp-askbar above the status line is the Ask Claude bar's, Tasks is a board of columns and Pull requests, Runs, Workers and Agents are cards drawn by CSS over the same tables (cells classed cell--<part>), and a worker is added by tiles that set the hidden selects.
- Dependencies and Folders (2026-10-18, docs/research/control-panel-dependencies-and-folders.md): the Dependencies tab draws each open epic's sub-issues and blocked-by links with a vendored Mermaid 12.2.0, byte for byte the board's chart text, at most sixty reads a draw and none once GitHub's newest count (rateLatest, set by every answer in call()) is under 100; the Board tab draws a STATE.md chart only where every line matches the board's grammar (BOARD_NODE_LINE). Folders links OneDrive items to a repository through the Worker's /drive routes; Track refuses a folder name the default branch already holds at its top. Each tab's checks and mutants are in symphony-app's signin/panel-checks/e2e2/ (graph.test.mjs, folders.test.mjs); signin.test.mjs's G7 can fail on timing in a full run and passes run alone (ONLY=G7).
- The + style (2026-10-18, docs/research/control-panel-plus-style.md): no form sits on a tab; tasks, workers, agents, repositories and people are added by a + button that opens a dialog, and every card opens its status on a press, its settings on its gear and removes on its X (a worker's or agent's change or removal is a pull request on a branch symphony/..., built on and never moved); the Ask Claude and Repositories tabs are gone, the repository picker lists the App's installations; the boundaries drag and A-/A+ zoom the console, both kept in localStorage under symphony_panel_layout; the checks press the dialog's opener (console-tabs.mjs).
