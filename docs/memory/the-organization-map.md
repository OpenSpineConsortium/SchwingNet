The organization map is .github/symphony/organization.json, the curated record of how the organization's repositories depend on each other and touch (a vendored library, a reusable workflow, a GitHub App, a runner, data handed on) and which systems outside GitHub they reach; the control panel's Organization tab draws it beside what it reads live from GitHub, and it changes by pull request.

# The organization map

- Where: .github/symphony/organization.json in this repository, private like most of the repositories it names. `nodes` are the repositories (name, group, visibility, role) and the systems outside GitHub (`"kind": "system"`: the WSU grid, claude.ai, Cloudflare, the Chrome Web Store, Microsoft 365, Weights and Biases, the dataset hosts, PyPI); `edges` are `{from, to, kind, what, by}`, read as "from depends on to", with every kind and every group spelled out in the file itself. `python3 tools/organization_map.py check` holds it together from scripts/check.sh.
- Who reads it: the control panel's Organization tab (OpenSpineConsortium/openspineconsortium.github.io, assets/js/symphony-panel.js) reads it from the open repository's default branch as the viewer and draws it as a chart, an edge table and repository cards, beside the repositories GitHub lists for the owner and the cross-repository blocked-by and sub-issue links the Dependencies draw keeps. The site is public and its script names no private repository, so the private names live here, in the file.
- How to keep it: when a repository gains or loses an interface (a new vendored copy, a workflow that calls another repository, an App installed, data handed on), change its edge in the same pull request as the change, with the evidence in `by` (the workflow file, the VENDORED record, the README line), and move `written`; a repository the map does not know is still listed by the tab from GitHub, with no edges.
- Why a file and not a read: GitHub records none of these interfaces where the panel could read them as the viewer (a vendored copy, a reusable workflow's callers, an App's installations), and the organization's own listings are refused to a cloud session; so the record is written where the project's other records are and checked like them.
- The epics, the two goals and the blocked-by links written across the organization's issues on 2026-10-29, with what was left undone on purpose, are docs/research/organization-map.md.
