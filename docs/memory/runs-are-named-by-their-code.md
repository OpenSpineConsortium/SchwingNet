Runs are named by the code they run: tools/run_code.py lists, for each kind of run, the tracked files it executes, and their digest names the run in place of the commit, so a run cut short is carried on after any merge to main that changes none of them.

- The kinds: `row`, one run of tools/flow.py, named by schwingnet.flow.configured_run_id over this digest, the catalog's sha256 and the configuration; `state`, a sweep's state folder, `<code 8>-<catalog sha256 8>` over this digest and the plan file's bytes (`tools/block_sweep.py state` prints it); `sweep`, `bank` and `catalog`, the Metaflow flows, whose launch key flows/launch.py takes over this digest, the words and each flow's key_reads (bank's recipes and raw copies, the sweep's plan), tagging every run key:, commit: and code:.
- Why (issue #252, finding 27): the grid's gate brings main in before every word, and main merges many times a day; of the 88 merges from 22 to 25 October, 10 changed a file a sweep runs and 6 one a bank or catalog build runs, so a run named by its commit started over after the rest.
- A file a run's code newly reaches, an import, a tool it loads or a script it names, goes into its kind's list in tools/run_code.py or into LEFT_OUT by name with the reason: tests/test_run_code.py follows each kind's code from its entry and fails on a file in neither, on a LEFT_OUT entry no longer reached, and on listed code no longer reached.
- A record keeps the commit the run first started on (RUN.json's code_commit, PLAN.json's commit, the flow parameter --commit, which Metaflow's resume clones); every commit with the same digest holds the same code, so that commit names it.
- A test that copies the repository to run a kind copies every file of its list, pixi.lock among them, or the digest refuses the copy as not tracked (tests/test_block_sweep.py's clean_copy, tests/test_flows.py's sweep stub).
