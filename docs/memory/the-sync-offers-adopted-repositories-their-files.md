The template's sync offers every adopted repository the files the board and the control panel run on, as a pull request from symphony/sync.

.github/workflows/sync.yml runs tools/sync_adopted.py in the template alone, on a change to those files on main, weekly and by hand. With SymphonyBoard's key it walks every installation (the owner chose every adopted repository on 2026-10-19, over the organization's alone) and, in each repository whose default branch holds docs/agents/PROTOCOL.md, offers the units an adoption brings: the vendored library with its record, the board's and the tidy workflows, the metrics workflow, the Token workflow and the drive sync (drive-sync.yml with tools/drive_sync.py, tools/docx_review.py and tools/drive_organize.py), each with every module its scripts import. A file is replaced only where the repository holds a version the template's history once held there; any other file holds its unit back whole, as does a module of theirs Python would import first. Only the Token unit and the drive sync are added where they are missing (the drive sync since 2026-10-20, because the Folders tab refuses Track in a repository without drive-sync.yml), since a missing metrics workflow means the repository never agreed to share; a whole template's copy (it holds protocol.yml) is left out, since it runs the template's tests on these scripts. A pull request closed unmerged is not offered again for the same files (a digest of each path, mode and blob), `off` in .github/symphony-sync stops the offers, and the log prints counts only. It answers the owner's "existing repos ... should at least get the files needed to function on the symphony board" (2026-10-19), which lifts the parked update route for these files alone; symphony-start's mode existing brings the Token workflow too (symphony-start#76).
