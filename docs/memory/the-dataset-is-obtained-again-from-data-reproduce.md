The manifest of every source and the code that fetches and verifies a copy are under data/reproduce/, byte-for-byte copies of spinesurg-ct-nnunet's data_platform (branch L6_Class, commit bf1432f, 2026-10-20) with their SHA-256 in SHA256SUMS; docs/research/datasets-reproduce.md, rendered by tools/reproduce_table.py from the registry, data/reproduce/map.json and that manifest, gives for every registry record the manifest records behind it, how and when each was acquired, the links it came from, the fetch command, the checks, the grid path and the licence; scripts/check.sh fails when the page, the map and the copies disagree.

The registry (data/sources/) says what a source is and where it sits; the manifest says how it was obtained and how to obtain it again. The two are joined by data/reproduce/map.json, which names for each of the 60 registry records the manifest records that hold it, or says that none exists and why (four do not: coronary_angiography, pediatric_iri, veterinary_pig_levelcheck, and cervical_thoracic_intraop, which does not exist publicly). The anomaly harvest maps to the manifest's family B, 144 records.

Run `python3 data/reproduce/reacquire/reacquire.py --grid <id>` for the exact commands and checks of a source; on the grid, run the same bytes from `~/spinesurg-ct-nnunet/data_platform/reacquire` through its sbatch wrapper, because the rebuild routes call that repository's tools. On 2026-10-20 the planning path listed 211 sources, printed the dry run of every one without an error, and passed its 28 offline tests in the source repository. data/reproduce/README.md records this and says how to bring the copies forward when the source changes.
