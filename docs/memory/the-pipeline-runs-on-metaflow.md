The grid pipeline runs as Metaflow flows started by flows/launch.py, which resumes the newest unfinished run of the same flow, commit and parameters before it starts a new one; the owner's rule is that a native behaviour of the workflow software is used and enforced, never written around.

- The owner's words of 2026-10-24 22:27 UTC, on a design note that said the preprocessing had no native resume because no flow used Metaflow: "dude wtf why not?". Metaflow 2.19.39 is in the pixi feature train, so in the train-cpu and train-gpu environments, not in the default one; grid/bin/train-cpu-python carries it (#252).
- Three flows: BankFlow (flows/bank.py, bank then ingest, a foreach branch per source), CatalogFlow (flows/catalog.py, one step, since the build lock is held from listing the manifests to the marker) and SweepFlow (flows/sweep.py, prepare, the rows with no parent, then the warm starts, then the results). grid/02-bank-ingest.sbatch and grid/03-catalog.sbatch exec the launcher when SLURM_JOB_ID is set and SCHWINGNET_FLOW_STEP is not, so every Slurm job goes through Metaflow, while a direct bash call, as tests/schwingnet/test_chain_stages.py makes, runs the stage's body; grid/sweep-driver.sbatch calls the launcher, never block_sweep itself.
- Measured: `resume --origin-run-id` after an exception or a SIGKILL clones every finished step and every finished foreach branch and reruns only the rest; it clones the parameters, so it never changes them, and --max-workers is passed again. Runs are found by the tag key:<16 hex> under namespace(None), newest first; schwingnet.pipeline.decide resumes the newest when it did not succeed.
- The datastore on the grid is /rs/rs_grp_oschome/go2432/metaflow (SCHWINGNET_METAFLOW or --root override it); cards are read with `python flows/<flow>.py card server` or `card view`, and SweepFlow exports them best-effort into the sweep's state folder, since a caught or cloned task has none.
- What resume does not cover is reuse across two finished runs; that stays with the tools' content addressing (the configuration-addressed run folders of tools/flow.py, and issue #260 for ingest's date and the catalog's version per commit). The fetch, stage 1, resumes by its own .part files and stays outside Metaflow.
