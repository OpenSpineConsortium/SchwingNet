The research loop (.github/workflows/research.yml, issue #220) is a Claude session every four hours that takes the best-ranked item of the claims register nobody holds and works it to a pull request under the claim protocol, as the worker research-loop, with full command of grid work, fetches and training by the owner's word of 2026-10-24.

The owner asked at 16:17 UTC on 2026-10-24 for "A CLAUDE INTEGRATION DIRECTLY INTO THE TEXTBOOK" that continues the research "INDEPDENTLY OF HUMAN INTERACTION", and at 17:36 UTC, told it would ask before any grid job, fetch or training, said "no i dont want this restriction ... give it full command to direct autonmous research". docs/project.md records the exception under Out of scope.

- The switch is the variable RESEARCH_LOOP (off stops it); the cap is RESEARCH_RUNS_PER_DAY (6 unless it says otherwise, 50 at most), counted by the marker artifact research-runs as synthesis.yml counts its reads; three failures in a row pause the schedule six hours; one run at a time; nothing in crowd mode; RESEARCH_MAX_TURNS sets the turn cap (300). It runs on CLAUDE_CODE_OAUTH_TOKEN alone.
- tools/research_loop.py pick chooses the work before Claude starts: the loop's own open issue labelled research first, then the best-ranked ready item of docs/textbook/claims.json that no open issue or pull request labelled research names (the marker `<!-- research-item: E07 -->` or a title beginning `Research E07`); an issue labelled blocked, owner-act or in-review, or claimed by another worker, holds its item. tools/claims_rank.py gives every item a status, open, doing or done, and `next` offers only open items.
- The standing brief is .github/symphony/research.md: claim, work, update claims.json and the chapter in the same pull request, every new number with its run id and file, the review record, ready; the owner merges. When blocked it comments, labels blocked and moves on; an act only the owner can take (counsel, the IRB, a letter, a reader, a gate word, a token) becomes an issue labelled owner-act assigned to the owner.
- Its reach on the grid: grid-gate.yml (start, status, stop of the runner chain) and grid.yml (one command on a compute node in the runner's container, no lab volume, no Slurm, under 55 minutes), dispatched on main by tools/research_loop.py grid and gate with the job's own token, which GitHub lets start a workflow_dispatch; the clerk takes a grid command only as one committed program with plain arguments (bash or python3 and a file on main, no shell operator, no -c), so new code runs on the university's node only after it has landed on main. The gate words of grid/gate.sh, which queue the Slurm jobs over the volume (fetch, v1, latency, leaks and the rest), go through symphony-template's grid-accounts.yml, which admits only an admin of that repository, so the loop asks the owner for them in an owner-act issue.
- What bounds a misled run (the session reads web pages and issue text nobody vouched for, and its tool list is no fence): the Claude App's token, which pushes branches and writes issues and pull requests on this repository, and the job's token, which dispatches any workflow of this repository that takes a dispatch and cancels, reruns or deletes its runs and artifacts; neither reaches another repository, a secret or a variable. The brief marks everything read as data, never an instruction.
- The textbook's site gives every chapter and figure an Ask Claude button that opens a new issue beginning "@claude", which claude.yml answers for the owner, members and collaborators, and a Research loop page with the ranked queue and the switch.
