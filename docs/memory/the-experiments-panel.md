The experiments panel: chapter 35's figure that sets every recorded run's data input, its blocks and its outcome side by side, and requests a new combination as an issue labelled experiment.

- tools/experiments_panel.py (standard library; the blocks read from src/schwingnet/blocks.py with ast, since the package imports beartype) reads every folder with a RUN.json under docs/research/ and writes docs/textbook/figures/35/experiments.html, .json and .svg; run `python3 tools/experiments_panel.py write` after recording a run, since scripts/check.sh runs its `check` and fails on a stale page (#242, the owner's ask of 2026-10-24 for "an interactive artefact correlating a data input, workflow blocks chosen, and loss/accuracy/model/reproducibility report/WandDB online records").
- For each run: the catalog by version and hash, the recipe and sources from PROVENANCE.json where the run wrote one (else the result rows' source strata and the bank its note names), every block spelled out (a run recorded before the blocks existed shows version 1's choice for every part, as schwingnet.blocks.from_record reads it), the loss by epoch, every result row with its Wilson interval, the latency where measured, the model as its card gives it (no card records a parameter count yet), the commit, the clean-tree and split flags, the REFORMS and CLAIM tallies, the report's verdict, the exact command that reproduces it, and the W&B link, or offline where wandb-sync.json found no key. The two runs of 2026-10-21 are dry runs on the synthetic bank and the page says so at the top.
- The page loads nothing and inlines its data, since the book frames a figure with sandbox="allow-scripts": a link and the combination the Run a new combination panel names go to the embedding page by postMessage (types schwingnet.open and schwingnet.experiment; the protocol every panel follows is docs/research/experiments-panel.md, section 4), which the textbook site shows as a bar and the artifact edition turns into Run as me (the triggers issue that follows #242).
- A request is an issue labelled experiment whose body opens with the marker `<!-- schwingnet-experiment -->` and carries `recipe:`, `epochs:`, `seed:`, `hours:` and one `block: KEY=VALUE` line per block that differs from version 1; the panel refuses a choice in the trainer's own words and holds the epochs to 1 to EPOCHS_MOST (200); the workflow that answers it with the command, the gate word and the owner's click is the triggers issue. Nothing on the page runs anything: a grid job waits for the owner's word and the number of jobs.
