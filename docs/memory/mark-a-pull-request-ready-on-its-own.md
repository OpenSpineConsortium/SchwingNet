Mark a claim's pull request ready in a call of its own, once the last edit of its body and the push that deletes its claim file have started their runs: Checks runs on edited, synchronize and ready_for_review alike, in one concurrency group that cancels the run in progress, and the protocol check judges the draft flag its event carried, so a run of the draft's that starts last fails a pull request that is ready.

- On 2026-10-24 one call of the GitHub tool edited #185's body and marked it ready. The edit's event, taken while the pull request was still a draft, started its run three seconds after the ready mark's, cancelled it, and failed tools/check_protocol.py with "docs/agents/claims/182.md is missing: a draft carries its claim file", though every test had passed.
- So write the body, its review record included (the-review-record.md), while the pull request is a draft, push the commit that deletes the claim file, and mark the pull request ready in a second call after that push's run has started, so the ready mark's run is the last.
- Where it has happened, any new event on the ready pull request, a push or an edit, runs the check on its true state; a re-run does not, since it replays the old event.
