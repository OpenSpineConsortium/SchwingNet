The template's tests run again in each copy, over the files tools/template_init.py filled, as the copy's required check; tests/test_filled_copy.py makes such a copy and runs its check, so a test that holds only for the template fails the template's check first.

A copy's check is its own `bash scripts/check.sh`, from its first pull request, over a tree the template never had: the placeholders are filled, LICENSE may be missing (the front door never copies it), .github/symphony-metrics may say off (the front door's opt-out writes it), the person's shell may export SDLC_METRICS=off, as tools/usage.py tells them to, and in crowd mode scripts/crowd.py has put the crowd's own pages in place of the template's, the worker page among them, whose prompt names the worker by the contributor's login. A test that reads the repository's own files therefore reads what the repository holds, as tests/test_one_prompt.py reads the names a routine page carries where its workflow has GitHub's values, or controls what it reads, a folder and an environment of its own; one that can only hold for the template's own files skips elsewhere, by the template_only mark of tests/test_crowd.py, test_template_init.py and test_metrics.py.

tests/test_filled_copy.py runs only where .template/PENDING exists: it copies the template's files as they stand, a change not yet committed included, fills them as the first push's run does, and runs three copies' checks side by side: an organization's copy on main with sharing on, as "Use this template" makes it; a person's copy on master as the front door's whole template makes it with sharing off, with no LICENSE and off in the switch file, and with SDLC_METRICS=off besides; and an organization's copy in crowd mode, with crowd.py's own build_change applied as its setup pull request would be. That adds about the time of one copy's check to the template's.

Learned on 2026-10-13: the template's pull requests symphony-template#56 and symphony-template#57 merged on a green check. The first turned every new copy's check red by comparing the routine pages' placeholders with the workflows; the second turned red a copy with sharing off, and any check run where SDLC_METRICS=off was exported, the template's own included, by reading the switch of the repository the tests ran in and letting the caller's SDLC_METRICS reach the code under test. Crowd mode's setup pull request was red in every copy the same way, since the worker-prompt tests held the template's own worker page, which crowd.py replaces with the crowd's.
