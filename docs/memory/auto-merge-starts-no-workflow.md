An auto-merge starts main's workflows only where the SymphonyBoard App armed it: from beethoven-qa 7.0.0 (#239) the kit's automerge.yml arms with the App's installation token, so the merge is the App's and starts main's push workflows; one armed with the workflow token, as every merge before 7.0.0 was, starts none and leaves its issue open.

- GitHub starts no workflow for an event the workflow token caused, workflow_dispatch and repository_dispatch aside, and an auto-merge is made as whoever armed it. On 2026-10-23, before 7.0.0, neither #174's merge nor #167's started a push run on main of Checks, gate, standards, Docs or Synthesis, and #167's started no pull_request run of the Board (#176); #136, #140 and #166 stayed open after their pull requests merged that way.
- automerge.yml (vendor/beethoven-qa/kit/.github/workflows/automerge.yml, byte for byte) mints the App's token for this repository alone with contents and pull requests write, from the variable SDLC_APP_ID and the secret SDLC_APP_PRIVATE_KEY, and its log says which token armed the pull request. It still arms with the workflow token a pull request that changes a file under .github/workflows/ (the token holds no workflows permission, so a token that starts workflows never lands a workflow change), one opened while the App's token cannot be made, and one the App may not arm.
- First runs, 2026-10-24: the App's token is made here (the mint step succeeds in automerge.yml). #241, #245 and #247 each changed a workflow file, so the workflow token armed them and their merges started nothing on main; a pull request here changes a workflow file often, so expect the workflow token for many. Its arm call also prints "auto-merge not armed: ... Resource not accessible by integration" where auto-merge was already armed by an earlier run, a read of the result the workflow token may not make, not a failure to arm. #254, which changes only docs/memory/, was the first the App armed.
- So after a merge armed with the workflow token, close its issue as completed by hand, and start by Run workflow what must follow the merge at once; otherwise the daily runs take it: the synthesis look at 06:41 UTC, rulesets.yml at 06:17 UTC, the board on its six-hourly run or the next issue or pull request event.
- An org ruleset on beethoven-qa itself requires one approval, so an auto-merge there waits for a review whoever armed it (beethoven-qa#12 was armed by the App and merged by hand on 2026-10-24); SchwingNet's own ruleset asks for none.
