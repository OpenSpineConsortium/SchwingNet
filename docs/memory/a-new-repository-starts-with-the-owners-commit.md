A session's push guard refuses a push to main in any repository, so a new repository's first commit is the owner's, and sessions bring everything else by pull request.

tools/guard_push.py runs as a hook on every git command a session of this repository runs, whatever repository the command touches, and refuses a push to main as a push to the default branch. An empty repository has no branch until its first push, so a session cannot start one, and pushing another branch first would make that branch the default. On 2026-10-16 the owner created OpenSpineConsortium/flowbench with nothing ticked, the session's push of a first commit to its main was refused, and the owner added the README from the empty repository's page (https://github.com/OWNER/NAME/new/main?readme=1, then "Commit changes..." and "Commit changes") before flowbench#1 brought the harness in. A thread that asks the owner for a new repository asks for "Add a README" ticked at creation, so the repository's main exists and the first pull request has a base.
