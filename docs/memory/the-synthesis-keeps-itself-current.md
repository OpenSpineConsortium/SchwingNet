The synthesis keeps itself current: .github/workflows/synthesis.yml looks at every change with no Claude, and runs the Claude reads a change needs, 10 runs a day unless SYNTHESIS_READS_PER_DAY says otherwise (50 at most), each adding to the one open synthesis pull request, or opening it, which waits for the owner's tap.

- The stamp, artifacts/_synthesis/work/out/state.json, holds each artifact folder's git tree as its record read it and each dataset record's hash, with what was already known when it was stamped. `SYNTH_SYMPHONY=<a checkout of symphony-template> python3 -I -B artifacts/_synthesis/work/tools/synth.py status` names what is new, changed or gone, the quotes today's texts no longer hold and the concept checks the stamp has not seen, with no Claude.
- The workflow looks on a push to main that changes artifacts/ outside artifacts/_synthesis/, docs/research/ or data/sources/, daily at 06:41 UTC, and on Run workflow, and keeps one open issue labelled synthesis saying what waits, closed once the report finds nothing at all. A push starts it only where a person or an App made it: a merge GitHub's auto-merge makes starts no workflow (auto-merge-starts-no-workflow.md), so the daily run, which also takes symphony-template's artifacts, looks at what it landed. Research notes and dataset records are checked by script alone; only an artifact, a verdict or a concept check becomes a Claude read.
- Its reads run on the repository secret CLAUDE_CODE_OAUTH_TOKEN, a `claude setup-token` token on that account's plan limits with no API billing, by the owner's choice of 2026-10-23 that they start on their own, an exception to the rule that no Claude credential is kept anywhere; it is the repository's one Claude token, so @claude, the coordinator (weekly and on an epic) and any worker registered in Actions run on it too once it is set. A run reads only while the variable SYNTHESIS_READS is not off, crowd mode is off, the SymphonyBoard App's SDLC_APP_ID and SDLC_APP_PRIVATE_KEY are set, symphony-template could be checked out, and the open synthesis pull request merges cleanly, changes only what a join writes and has not failed owner-ok; fewer than SYNTHESIS_READS_PER_DAY runs (10 unless it says otherwise, 50 at most) have read that day; and, for a run a push or the schedule starts, six hours have passed since the last of three reading runs in a row that all failed. Run workflow skips that pause but not the day's count, and the job summary names the first condition that stopped a run.
- A run whose sessions bring nothing back writes nothing and fails, and still counts toward the day. Otherwise it adds what it read to the one open synthesis pull request, or opens it, from a branch synthesis/<run>, one commit on main; the App opens it, so each push waits for the owner's tap on owner-ok, and it merges by itself once green (automerge.yml), or stays a draft for a person to mark ready where main's rules do not require owner-ok.
- What a run writes goes through artifacts/_synthesis/work/tools/redact.py (a login, the owner's first name, a grid volume's path, a form's link and the rest its docstring lists; what its rules do not name passes, so the owner reads the pull request before the tap), is saved in the records' own layout (synth.save) and is the same on every hash seed: `python3 -I` draws a new seed in every process, so a set whose order reaches a result is sorted, and tests/test_synthesis.py runs the dataset checks under four seeds. A concept check's key is made from its passage as that scrub leaves it, so a change to what the scrub takes out runs `synth.py rekey <a checkout of main>` in its own pull request, up to date with main and changing no text and no record the concepts are made from, which carries the stamp's word to the renamed keys, so the issue lists no check as gone and new, and no read is spent, for a key that alone changed.
- A dataset record whose name gives the concept checks the wrong names for its set, or none, is set right in artifacts/_synthesis/work/aliases.json; concepts.md lists the records no text is checked against.
- artifacts/_synthesis/work/RESUME.md, section Keeping it current, is the whole account.
