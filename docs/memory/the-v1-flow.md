The v1 flow: a run is refused from a dirty tree or a leaky split, stamped by a run id, and recorded with what it cost beside its numbers.

- tools/flow.py runs the level stage (task #11) locally in the train-cpu environment or as sbatch jobs in train-gpu, writes RUN.json (schwingnet.flow.RunRecord) before the first step, records each job's cost from the runner or sacct, and `record` copies a run's small files into docs/research/v1-demo/runs/ with one ledger row; never the checkpoint.
- Every reported number is a ResultRow: correct/n, the 95 percent Wilson interval, the persons, the run id, the commit, the clean-tree flag and the catalog's sha256; tools/evaluate.py reads the test part once, after training, and the transitional stratum is reported apart.
- tools/train.py writes a witness strip of the same validation crops at every epoch, so learning is seen, not trusted; crops come from the truth boxes (the detector stage is not in v1), and ImageNet weights come from a file, never a download, since compute nodes have no internet.
- The dry run of 2026-10-21 on tools/synthetic_bank.py (learnable, nothing of any person) is docs/research/v1-demo/README.md: the workflow end to end on a CPU in 2.5 minutes; a grid run waits on the owner's word and the gate.
- A script under tools/ must take tools/ off sys.path before importing torch: tools/profile.py shadows the standard library's profile module.
- Functions that take a pydantic model are listed under [tool.beethoven-qa.unproven] in pyproject.toml, since CrossHair 0.0.111 cannot construct one; their contracts are checked by tests/schwingnet/test_flow.py.
- Since #252 the run id is the hash of the code the run executes (tools/run_code.py's digest of the kind row; runs-are-named-by-their-code.md), the catalog and the run's configuration (CONFIGURATION.json, schwingnet.flow.configured_run_id, with augment's changes and the sources in one order whatever order they were typed), so a configuration finds its folder again: a finished run, one that wrote FINISHED.json, its last file, is reported and left; one cut after its evaluation gets only the last push, its ledger row where the ledger has none for the run, and its report; one whose train/checkpoint.json reads and names the sha256 of the best.pt beside it runs only its evaluation, and one with train/last.pt resumes training from its last epoch with `tools/train.py --resume`, bit-identical on a CPU, else it trains from the start, the trainer moving a checkpoint.json that is no such record aside to checkpoint.json.unsound first; `--slug` names the folder; a RUN.json with the older id, of the commit, the catalog and the start, still validates.
- A start holds its run's folder by a non-blocking flock on <run>/.lock, and the trainer holds train/ by train/.lock, each to its end, so a second start of a run in progress, or a second trainer in its folder, is refused in words naming the holder and touches nothing; CephFS honours flock across nodes. The flow writes RUN.json, CONFIGURATION.json, witness.json and split-check.json whole, flushed to the disk before the rename and the folder after it, as the trainer writes its own, since a node that dies can leave a renamed file short or with stretches of zeros; LEDGER.md, which every row of a sweep finishes into, is written whole under an exclusive flock on LEDGER.md.lock beside it, the header kept, and a volume that refuses the write is said in words with the ledger left as it was, so no earlier row is lost.
- `--resume` holds a run to the sha256 of its catalog, ImageNet file and parent, not to their paths, as the flow names it, and --init reads the parent where its path leads, so a link to its best.pt finds its run and blocks; train/last.pt is bound to its bytes by its sha256 in train/last.pt.sha256, which names the new file and the old one while the rename is to be made, so a last.pt torch cannot read, one whose bytes the record does not name, as a stretch of zeros torch reads without a word, one with no record, or one whose best line names weights best.pt does not hold is moved aside to last.pt.unreadable and the run trains from epoch 0 in the same call, saying why on its card; the hash and the flushes cost about half a second an epoch for v1's 134 MB last.pt on a CPU with no SHA instructions; metrics.jsonl is flushed every line, for the sweep's card; `--batch 1` where the model cannot train on one crop is refused in the one-crop refusal's words.
- The trainer and the evaluator refuse in words a --catalog whose sha256 is not the one RUN.json names, since every number is stamped with it; the evaluator scores only a best.pt train/checkpoint.json names by its sha256, and the trainer refuses a fresh start into a train/ whose checkpoint.json is a finished run's record, touching nothing.
- In slurm mode each job is in RUN.json from the moment it is submitted, with no exit code until sacct calls it finished, so a start that dies while its job waits, a login shell closed under it, leaves the job for the next start to wait on and record, never to submit a second one beside it; a start that finds such a job where sacct cannot be run is refused in words; local mode records its jobs once they ended, as before.
