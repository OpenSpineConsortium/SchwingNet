# Notebooks of drive files

Source: the thread "Organize a whole OneDrive", 2026-10-19, for the owner's ask of 01:36 UTC: group files into a notebook, as Gemini's NotebookLM does, where they are not moved but held as one context tied to a repository Claude works on in the background, accumulating research and writing derivatives to support edits made directly to the files on OneDrive, with citation managers (Mendeley, EndNote or another) taking advantage of the owner's Elsevier institutional token, offered as a resource to the owner's GitHub enterprise.

## What a notebook is

A notebook is a private repository that points at a few of the drive's files by the drive's ids and keeps beside them what Claude makes of them: research/, one file a question opening with its sources; drafts/, what it writes from the files; and references.json, the reference list. The files stay where they are, so a file may sit in several notebooks, and nothing a notebook does can lose one. tools/notebook.py holds the shape: check holds a proposal (notebooks.json, beside catalog.json on a private repository's branch drive-catalog) to the catalog, show gives each notebook's counts without its file names, make writes a notebook repository's starting files, refs reads a citation manager's export. The notebook skill (.claude/skills/notebook) is the procedure. Being in symphony-template, which is internal to the enterprise, every repository of the enterprise takes it from there.

Edits to the files themselves go through the lens-review skill: tracked changes and comments in a copy beside the file, so the owner accepts or rejects each in Word, never over the owner's file unless the owner says so.

## Where the owner's rules bound the ask

- Elsevier, as first written. The owner lifted the key rule and the university's library lifted the rest for private academic use, both on 2026-10-19 (below). Elsevier's APIs take the institution token only beside an API key.
- Citation managers. No connector for Mendeley, EndNote or Zotero is in Claude's directory (searched 2026-10-19), and the rule on outside code bases says no integration code until the owner chooses. The way with no code, key or account is the export every manager writes: BibTeX or RIS, read by refs. EndNote has no public web API, so it has only that way. Zotero's web API syncs both ways but takes a key; Mendeley's needs an OAuth app like the Folders one, and Mendeley is Elsevier's, so its catalog data falls under the Elsevier rule. The owner chose the Mendeley app on 2026-10-19, for its Chrome importer, which with Claude in Chrome on the owner's own computer gives verifiable citations; it is not built yet. It needs a sign-in secret held where the Folders app's is, in the control panel's Worker, which another thread owns, and Mendeley is Elsevier's, so whether its data falls under the licence's AI clause is to be checked. Until it is built the export is the way, and refs reads it. Community MCP servers for Zotero exist outside Claude's directory and could be added as custom connectors.
- Elsevier's terms. The university's library confirmed to the owner on 2026-10-19 that, for this academic use, there is no restriction on how the owner reaches Elsevier's content so long as the token and the text are never made public. No model is ever trained on it either way. The request to Elsevier of 2026-10-15 promised that no outside AI service receives its content (spine-program's RECORD.md, section 6), so letting Claude read Elsevier text goes beyond what Elsevier was told, and Elsevier itself then told the owner (2026-10-19) that Claude reading the text is allowed so long as it is never made public. So Claude may read it, and the API key, the institution token and any citation manager's key may be kept as secrets, and every place they are used is private: an Actions secret scoped to private repositories, a cloud environment's variable, never a public repository, a log, a URL or browser code.
- Bibliographies in Word need no connector: each reference is checked by its DOI against Crossref or PubMed, free, keyless and not Elsevier, and the citation written into the document as a tracked change in a form the owner's citation manager reads, EndNote's temporary citation {Author, Year #record} among them, so Update Citations in Word builds the bibliography. Mendeley Cite keeps its citations in its own add-in, which is not yet read.

## References into Word, with a source anyone can follow

Asked the same day: how naturally a Zotero MCP server fits the OneDrive Word setup, for documents whose every reference can be confirmed by a path that does not break, each captured from the browser by a citation manager's extension and put into Word by Zotero or Mendeley Cite. The owner wants the bibliography's own flexibility and to see where each reference came from, not a check by DOI alone.

- Capture. The Zotero Connector for Chrome, or Mendeley's Web Importer, saves the item from the page it is on, with that page's address, its identifiers and, for Zotero, a snapshot or the PDF. That record is where a reference comes from.
- Zotero writes a citation into Word as a field whose code is "ADDIN ZOTERO_ITEM CSL_CITATION" followed by the citation as CSL JSON, and that JSON carries the item's URI in the owner's library (http://zotero.org/users/<id>/items/<key>). So a citation in the document names the exact library item, and the item names its source; the Zotero plugin's Refresh in Word renders the citations and the bibliography in any style, and the owner keeps editing them as usual (forum and guide threads: https://forums.zotero.org/discussion/89432/why-field-code-in-ms-word-contain-so-much-informations, https://opentext.ku.edu/zoteroguide/chapter/citing-in-the-zotero-world/).
- Claude can write exactly that field. Read the item through Zotero's web API, write the field into the copy beside the document as a tracked insertion (tools/docx_review.py's way), and on opening the copy in Word with the Zotero plugin, Refresh makes it a citation like any the owner inserted by hand. Inference, to be proved on one document: the field's code is plain text Zotero documents, but no test has run it yet.
- Mendeley Cite keeps its citations in its own add-in's storage, which Mendeley does not document (its guides only show the add-in's buttons: https://library-guides.ucl.ac.uk/mendeley/inserting-and-editing-citations). Claude can capture into Mendeley and read its library through Mendeley's API, but cannot yet write a citation Mendeley Cite will take. A Mendeley library imports into Zotero whole, so Mendeley's Web Importer can stay the capture and Zotero the citer.
- A Zotero MCP server. Several exist (https://glama.ai/mcp/servers/integrations/zotero), such as 54yyyu/zotero-mcp, which reads either the Zotero desktop app's local API, so it runs only on the owner's computer, or the web API with a key. A claude.ai connector needs a server on the internet, which this project does not host, so in a cloud session the same calls go straight to Zotero's web API with ZOTERO_API_KEY, with no server; on the owner's computer, Claude Code or the desktop app can run the MCP server locally against Zotero itself.
- The path, then: capture with the Connector or the Web Importer; Zotero holds the item and its source; Claude cites by the item's key as a Zotero field in a tracked copy; the owner opens it in Word desktop, presses Refresh and accepts or rejects. Whether Word for the web runs the Zotero plugin is not checked here.
- Which is native. Neither Mendeley Cite nor EndNote comes with Office: Mendeley Cite is a free add-in from Word's store, EndNote's Cite While You Write installs with EndNote, which is paid, and Zotero's plugin with Zotero. Word's own citations (References, Insert Citation, Bibliography) are built in, kept in the document's sources part (customXml, b:Sources, an open format) with citations as CITATION fields, so a citation written that way needs no add-in on any copy of Word. The owner, who does not use Word, wants Word supported natively (2026-10-19), so Claude writes Word's own citations as the native layer, each source with its URL and DOI so its origin shows, and Zotero's fields for those who cite with Zotero.
- Built (tools/docx_cite.py, 2026-10-19). A file of citations names, for each, a paragraph, the words the citation follows and the references' keys; the tool writes each as a tracked insertion in a copy, either as Word's CITATION field with every reference added to the document's own source list (customXml, b:Sources, with its DOI and its address, or https://doi.org/ and the DOI where it has none), or as Zotero's field with each item's library URI and its data. A paragraph holding a field, a link or a tracked change is refused, so a second citation in a cited paragraph waits for the first to be accepted. notebook.py refs keeps each reference's address (BibTeX url, RIS UR) and reads a Zotero web API answer with each item's URI. LibreOffice opens both forms and shows the citations in place; whether Word's Update Field and Insert Bibliography, and Zotero's Refresh, take them as their own is the test still to run in Word, on a made-up document first.
- Tested (2026-10-19, on a made-up four-paragraph document cited twice, three citations of two made-up works). Both forms pass the Office Open XML schemas and the tracked-change checks of Anthropic's docx validator, author Claude. LibreOffice 7 reads the Word form's CITATION fields as bibliography entries of its own (text:bibliography-mark, type article, the shown text kept), so a second program takes them as citations and not just as text. Word itself and Zotero's Refresh cannot run in a cloud session, which has no Word, no Zotero and no computer-use tool, so the two copies were put in a folder of their own in the owner's OneDrive through the Microsoft 365 connector for the owner to open in Word: Insert Bibliography and Update Field in the Word copy, Refresh with Zotero's plugin in the Zotero copy, whose items are not in the owner's library, so Zotero uses the data carried in each field. The owner opened a third copy, the Word form with a BIBLIOGRAPHY field after the text and updateFields set in the document's settings, in Word desktop on 2026-10-19, answered Yes to updating the fields, and Word listed both works: Word takes the CITATION fields and the source list as its own. So a document Claude cites can carry its reference list already, which Word fills on opening. Zotero's Refresh is still untested.
