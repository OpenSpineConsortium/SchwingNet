# The control panel's Dependencies and Folders tabs

Source: the thread "Control panel sign-in", 2026-10-18, written at the owner's checkpoint of 13:02 UTC. It follows control-board-graph.md (the research behind Dependencies) and drive-sync.md (the design behind Folders), and records where the two tabs stand, so the next session carries them on without asking again.

## What they are

- Dependencies (the owner's choice 6 in control-board-graph.md): a console tab after Tasks, data-tab "dependencies", that draws a repository's epics, sub-issues and blocked-by links with Mermaid in the browser, from GitHub's own sub-issue and dependency data, with no graph code of ours.
- Folders: a console tab after Share, data-tab "folders", that links a repository to OneDrive folders the owner ticks, as drive-sync.md describes. OneDrive only: Google Drive waits for a route with no API key, since the owner refused the Google Picker's browser key.
- The sign-in Worker gains /drive routes for Microsoft's sign-in, whose redirect URI is exactly https://openspineconsortium.com/symphony/control/ with its trailing slash.
- Each tab adds lines to the Apps' privacy statement (symphony-start PRIVACY.md), and each takes the next version after main's when it merges; 18 is symphony-start #57's.

Dependencies. No injection and no divergence from the board's bytes: the page's label function matched the library's node_label on 20,000 random titles, control characters, fullwidth signs, combining marks and a lone surrogate among them. An earlier draw's failure stayed in the summary after a later draw on the same state succeeded. The Board tab's gate let a raw "#" through, which the board never writes. ## The Explore tab

Added the same evening, at the owner's ask for a view to click or scroll into, from an epic down to a worker's Claude logs. It sits after Dependencies and reuses the issues and pull requests that tab already read. The levels go goal, epic, issue, pull request or claim branch, workflow run, job, step, and the log lines. Runs, jobs and logs are read only when a level opens, and none are read once fewer than 100 calls are left in the hour. Only the last three logs are kept in the page's memory, and the statement's version 24 says so (symphony-start #63).

A scroll moves a level only when the gesture starts at the edge of what is shown, and only on its first event, so a trackpad's glide never runs through several levels. GitHub keeps a job's log in storage on another origin and answers the read with a redirect. The page sends only Authorization, so the browser asks that storage no preflight, and Chromium drops the header on the cross-origin redirect. A browser that refuses to follow the redirect gets a plain sentence and the Open on GitHub link. Lines go to a step by their time. A skipped step takes none. On a tie within the same second a line stays with the earlier step unless it opens the next step's group, and lines before the first step go to the first.

Site #64 carries the tab, merged at 50aefb8. symphony-app #32 carries ten checks (XP1 to XP10) and 24 mutants, all killed. The checks for the log use a local storage server, since Playwright sends a mocked route's redirect to the network.
