# The storage panel: drive use and dataset combinations under the target, from spine-datasets' feed

Source: the project thread "Textbook: figures, ranking, Unberath, overlap, workflow chapter, Claude integration, artifact edition, experiments panel", 2026-10-24, on the owner's ask of 20:34 UTC: know the drive usage from the artifact, trial combinations of datasets that fit under 20 TB, trigger the removals and additions, and place some data on the owner's 4 TB home. Issue #244, pull request #245. Confidential with the rest of this repository. No grid job, fetch, training or Claude run was started for this work, and the panel starts none: its one action is a workflow dispatch on spine-datasets that opens a request pull request the owner merges.

## 1. The feed's contract

The feed is PLAN.json on the branch storage-feed of OpenSpineConsortium/spine-datasets, never on its main, built by that repository (its pull request #240, merged 2026-10-24) on every push to main that touches a record, after each request its workflow opens, and daily at 05:53 UTC. It is read with the contents API at ref=storage-feed. Its top level is format (`spine-datasets/storage 1`), built_at, read_at (when the volume was read, for an age badge), target_bytes, requests[] of {number, url, selection}, volume {quota_bytes, used_bytes, read_at, datasets_bytes, other_bytes}, home {quota_bytes, used_bytes, read_at} and sets[]. The home's used_bytes stays null until the owner names the home's path and a grid word reads it, so the greyed home option is the shipped state. Each set is {id, name, group, reach (held once on the grid), fetchable, status, location (lab, home or none), bytes (the measured size whenever frozen), bytes_known, licence (open, restricted or unknown), rebuild, frozen, overlap[] of {with, patients, series, same_bytes}}. spine-datasets #247 adds same_scans to each overlap entry (its lineage table's same_values): the volumes of the two sets that match by geometry (sizes and spacings, in any axis order), voxel count and the sum of scaled values, so the same scan, perhaps stored in another axis order or number type, and not byte-identical voxels, which the table's same_voxels counts and the feed leaves out (ctspine1k with ctspinopelvic1k, 526, with no patients or series, since NIfTI carries neither). same_bytes is the bytes of the files the two hold byte for byte. #247 also drops the pairs that share only a volume's geometry with every count zero (the storage-planner thread, 2026-10-24 23:50 and 23:54 UTC; spine-datasets tools/storage.py overlap_of; issue #272).

The selection grammar is the planner's: `-id` removes a set, `+id` adds one, `id@home` and `id@lab` place one, several tokens separated by spaces. The dispatch is storage.yml on spine-datasets' main, workflow_dispatch with the one input selection; there, `python3 tools/storage.py check SELECTION` refuses an over-cap or sizeless fetch and any move to the home while home.used_bytes is null, and the run opens a request pull request the owner merges, so no fetch ever runs from the panel alone.

The first snapshot, read live on 2026-10-24 at about 21:05 UTC through the contents API with this session's read access to spine-datasets (sha256 fcdd7bfe2cacd74283b0b4318044f5c777c2816782d352d0129e50dad81b6792, committed as docs/textbook/figures/22/storage-plan.json): built 20:52:07 UTC from a reading of the volume at 17:15:28 UTC; 166 sets, of which 104 are on the lab volume (97 held, 7 fetched), 48 can be fetched and 14 cannot yet (gated, embargoed or waiting on the owner); the volume 17,553,250,000,000 bytes used of 21,990,230,000,000, 7,626,035,136,479 of them datasets and 9,927,214,863,521 other files; the target 20,000,000,000,000; the home's quota 4,000,000,000,000 and its use null; no request pending; 59 sets with no size, 8 with a stated size not yet measured (the largest the full NLST at 2.3 TB), and no set yet overlapping another in the feed.

## 2. What the panel does, and what it refuses

tools/storage_panel.py builds docs/textbook/figures/22/storage.html from the committed snapshot, inlined in a script element of type application/json, so the page fetches nothing at view time; storage.svg, the drive bands, is the image the chapter's figure line names, and storage.json is the record in the site's convention (tools/textbook_site.py), traced to the script, with the feed's built_at and read_at and the snapshot's sha256. The page shows the lab volume's use of its quota, the datasets' bytes against the other bytes, the target as a mark and a thin band of the use after the choices; the home's use of its quota, or "not read yet"; an age badge per reading; the pending requests as links; and a table of every set in three groups (on the drives, can be fetched, not fetchable yet) with a filter box by name, id or group and a changed-only view, since 166 rows are more than a reader scans. Each held set has keep, remove and a place (lab or home); each fetchable set has leave, add and a place; a set the feed cannot fetch has no control and a title saying its status. Every byte figure is terabytes with one decimal, rounded half up on whole tenths so the Python and the page print the same, with the exact bytes in a title attribute.

The planner's check is mirrored in words so a selection is never sent only to be refused. In a fixed order: a changed set with no size ("has no measured size, so the planner refuses the fetch or the move: the size rule reads a set's exact size before a byte lands"); any move to the home while its use is unread; a total over the target; a total over the volume's quota, which the size rule on the grid would refuse whole; a total over the home's quota. Apply is disabled, with the reason in its title, while any refusal stands or no choice differs from the feed. Overlap notes name each pair of kept or added sets that the feed says share patients, series, scans or files, each count only where it is above zero, since a zero for a NIfTI set means nothing was read: the patients and series in common, the scans that hold the same images (matched by size, spacing and voxel values), which say how many scans a selection holds twice, and the bytes of identical files, read from the sets' own overlap lists rather than all pairs, so a keystroke costs the sum of the lists and not 166 squared. The arithmetic (final_location, tokens, selection, totals, overlaps, refusals, tb) is written once in Python and mirrored in the page's MODEL_JS; tests/test_storage_panel.py works the cases by hand and runs the JavaScript with node on the same fixture and on the committed snapshot.

## 3. The host protocol, the figure's side

The page implements only the figure's side of the protocol the textbook's hosts provide: the site's page around each framed figure (tools/textbook_site.py, MESSAGE_JS, on main since #243) and the artifact edition's host, which carries the connector (tools/textbook_artifact.py, #240). Apply posts to the parent window {type: "schwingnet.dispatch", repo: "OpenSpineConsortium/spine-datasets", workflow: "storage.yml", ref: "main", inputs: {selection: "<string>"}, label: "storage", fallbackUrl: "https://github.com/OpenSpineConsortium/spine-datasets/actions/workflows/storage.yml"} and listens for {type: "schwingnet.dispatch.result", label, ok, error}; Refresh posts {type: "schwingnet.read", id, repo, path: "PLAN.json", ref: "storage-feed"} and re-renders from {type: "schwingnet.read.result", id, ok, text, error}, keeping the choices whose sets the new feed still lists. A message counts only from the parent window, and a read result only with the id the page sent. When no answer comes within 8 seconds, or ok is false, the page shows the fallback: the workflow's link, the selection to paste into its selection input, and one line saying a request pull request then waits for the owner's merge; a page with no parent window shows it at once. On the Pages site, where the figure sits in an iframe sandboxed with allow-scripts alone, the page around it answers every dispatch and read at once with ok false and the error "no connector", so the fallback is the whole story there; a link inside such an iframe cannot open a new tab (no allow-popups), so the fallback prints the address in full, the figure's Explore button on the site carries the same link, and the page also posts {type: "schwingnet.open", href, label} to the page around it, once when a fallback appears and again on each click of a link in it, which the site shows as a link in its own bar, the convention of docs/research/experiments-panel.md. Copy uses navigator.clipboard.writeText in the click handler and, where that is refused, as in the sandbox, selects the text and says so.

## 4. How it is kept current

.github/workflows/docs.yml mints the App's read token on spine-datasets (actions/create-github-app-token at the same pinned commit as synthesis.yml, repositories spine-datasets, permission-contents read, continue-on-error) and runs `python3 tools/storage_panel.py fetch`, then `build`, before the site build; a fetch that fails logs one sentence and the build proceeds from the committed snapshot, so the deploy never fails for the feed. `fetch` follows no redirect, since urllib would send the token to whatever address a redirect names, and refuses an answer that is not the feed's format. scripts/check.sh runs `python3 tools/storage_panel.py check`, which rebuilds from the committed snapshot and fails when the committed page, picture or record differs, so a snapshot refreshed by hand without the page built again fails the required check. The figure's Re-run (figure.yml) redraws from the committed snapshot alone, since that runner holds no token for spine-datasets. .github/workflows/textbook-artifact.yml, the artifact edition's workflow on pull request #240, was open while this was built and was not edited; it needs the same two steps before its build so the artifact edition carries a fresh panel too.

## 5. What was verified, and what was not

Verified here: the feed read live and committed as the snapshot; the build deterministic (the same snapshot gives the same bytes); the check failing on an edited or missing file; the fetch refusing a missing token (exit 2), a redirect (never followed, the token sent to no second address) and a wrong or unreachable feed, against a local stand-in server; the JavaScript mirror equal to the Python on the fixture and on the committed snapshot; the page at 1200 and 400 px wide in light and dark, with no horizontal overflow of the page, every control doing what it says, and the protocol against a stand-in host that answered dispatch ok, refused a read, and answered a read with a fresh feed in which the home had been read, after which the home's controls were enabled and a placement there counted.

## 6. What the kept sets are worth (#284)

Source: the owner's question of 2026-10-25 at 02:44 UTC in the project thread "Fit datasets under the 20 TB cap", passed to the thread "Make the textbook drive the research": to choose which datasets to keep from power calculations, anatomical coverage, the quality of the data, the presence of annotations and their use for the synthetic X-rays or 3D priors, and whether the textbook has a page for it. Issue #284, pull request #285. The fields come from spine-datasets' pull request #249 (merged as 7dcaf05), whose storage/README.md says what each means.

The feed's contract, as #249 adds it. Each set may carry `value`, read from its record alone: people and scans; level_truth, one of read (people named the levels), automatic (only a tool's masks do), no or unknown; level_truth_people and level_truth_scans, the people and scans it covers, a count where the truth is read, 0 where it is no and null otherwise; transitional_people; regions, a list of words, and spine, whether the spine is in view; masks_by_level, read, automatic or null, and masks_held, whether they are on the grid; segmented; prior_source, a CT with masks by level, which can feed the synthetic X-rays and 3D priors; paired and tier, the census tier A to E of a pair (A spine pairs on the grid, E pairs of something other than the spine); and modality, the set's group. The top level may carry `power`: half_width, confidence, z, assumed_accuracy, people_needed, and over the sets on the drives level_truth_people_kept (an upper bound, since sets that share people count them twice; kept_is_upper_bound says so), level_truth_people_unread (the kept sets with no count), level_truth_scans_kept and transitional_people_kept. Every field is optional to the panel: a feed from before #249 draws the page as before, with no worth section in the image and the cards saying the feed carries no values.

The model, in tools/storage_panel.py and mirrored in MODEL_JS. A count is a whole number of 0 or more, an integral float allowed, else none, so a boolean or a string never counts. people_needed is the ceiling of z^2 p (1 - p) / h^2, the normal approximation to the binomial the feed uses, and is none outside 0 < p < 1, 0 < h < 1 and z > 0; the page offers 90, 95 and 99 percent (z 1.644854, 1.959964, 2.575829) and the feed's own. The sets a selection keeps are those whose place after the choices is the lab or the home. For people with level truth the page gives two figures: the most, the sum over the kept sets; and the least, the most less what each overlapping pair of kept sets may share, the smaller of the pair's own counts (patients, else same_scans) and of the two sets' counts, or the smaller set whole where the pair gives no count, but never below the largest single set. The same two figures are given per modality, against the people a test needs, as none counted, enough, short by n, or enough at most and short at the least. Anatomy counts the kept sets per region, the regions a change loses or gains, the sets with the spine in view and those naming no region. Labels count the kept sets by level truth, by masks read or automatic, held and segmented. The synthetic X-rays and 3D priors count the prior sources kept and before, their bytes and the unsized ones, and the paired sets by tier. Each changed set gets one line: its people with level truth, its truth and modality, the regions only it covers, whether it is a prior source, and its bytes.

The page. Four columns join the set table: level truth with its people, people with level truth per terabyte, the regions covered and the uses (prior, paired with its tier); the last two hide on a phone. An order select sorts each section by the feed's order, people with level truth per terabyte, people with level truth, people per terabyte or size, largest first and unknowns last, ties in the feed's order. The filter reads tags beside the name, id and group: truth-read and the other truth words, the modality, prior, paired, tier-a and the other tiers, spine, masks-read, masks-held, segmented and each region, hyphenated (whole-body, head-and-neck). A section "What the kept sets are worth" holds four cards, Power (with the accuracy, half-width and confidence as inputs), Anatomy covered, Labels and their quality, and Synthetic X-rays and 3D priors, and under them a line per change. The image's two lines say the same for the drives as they stand.
