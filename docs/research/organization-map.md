## 5. The map

The file is .github/symphony/organization.json. `nodes` are the 39 repositories (name, group, visibility as GitHub reports it, public, internal or private, and a one-line role) and 8 systems outside GitHub (`"kind": "system"`: the WSU grid, claude.ai, Cloudflare, the Chrome Web Store, Microsoft 365, Weights and Biases, the dataset hosts, PyPI); `edges` are 113 entries `{from, to, kind, what, by}`, read as "from depends on to": the repository named first takes, calls, reads, runs on or is served by the one named second; `kinds` names the 19 kinds of edge with their meaning (vendors, made-from, sync, app, runs-on, gate, reads, data, tasks, imports, calls, releases-through, serves, pairs-with, hub, measures, tests, drives, publishes) and `groups` the six groups of node (spine, symphony, beethoven, people, tools, systems). `by` names the evidence: the workflow file, the VENDORED record, the README line or the memory file of this repository. A secret appears only by its name, as an interface, never by its value; the grid's folders appear only as a system, since nothing of them is ever copied here.

How it was made: each repository's workflows gave the calls between repositories (a reusable workflow at another repository's main, a checkout of another repository, a dispatch to it, a runner label another repository serves), the VENDORED records gave the vendored copies and their versions, symphony-protocol's ecosystem.json gave which repository takes which modules, the READMEs gave each repository's role and the Apps, runners and services it names, and this repository's memory gave the data handoffs (the grid, the dataset hosts, Weights and Biases, Microsoft 365, the claude.ai artifacts and connectors). Where two sources disagreed the workflow file won, since it is what runs.

How it is checked and kept: `python3 tools/organization_map.py check`, from scripts/check.sh, holds it together (every edge joins two nodes that are there and is listed once, every kind and every group is one the file lists, every repository says its visibility and its role). When a repository gains or loses an interface, the edge changes in the same pull request as the change, with the evidence in `by`, and `written` moves; a repository the map does not know is still listed by the tab from GitHub, with no edges, which is the sign that the map wants a line.

## 6. The control panel's Organization tab

The site's control panel gets a rail button Organization after Dependencies (tools/pages/symphony/control/index/body.html, assets/js/symphony-panel.js and assets/css/control.css in OpenSpineConsortium/openspineconsortium.github.io, its pull request #150; its 14 browser checks are symphony-app's signin/panel-checks/e2e2/org.test.mjs, pull request #92 there, beside the Dependencies tab's 170, which pass against the changed script). As the viewer, it reads the owner's repositories (`/orgs/{owner}/repos`, or `/users/{owner}/repos` when the owner is a person, two pages of 100), the map from the open repository's default branch, the cross-repository blocked-by and sub-issue items the Dependencies draw already read and until now dropped, kept in a list, and the blockers of the open repository's blocked open issues the draw did not read, at most 40 a draw (ORG_READS_MAX), said in words when the cap stops it; it keeps the same reserve as the Dependencies tab (GRAPH_RESERVE, 100 calls) and uses no search API, whose own rate limit would be mistaken for the panel's. It draws the map as a chart in the panel's stage, grouped by the file's groups with public, private and system repositories told apart and chips to show one group or one kind, an edge table (from, kind, to, what, by) and one card per repository (role, visibility, open issues, the edges in and out, the cross-repository task links). A repository GitHub lists that the map does not know is listed with no edges; a repository the map names that GitHub does not list for the viewer is drawn and said to be out of the viewer's reach. The site is public and its script names no private repository: the names live in the map, which the panel reads from the viewer's own repository with the viewer's own access.
