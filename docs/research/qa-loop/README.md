# The QA loop: where it stands

Source: the thread "Build self-propelling QA Metaflow pipeline", 31 October 2026, from the owner's asks of 01:55 to 02:03 UTC that day. Confidential with the rest of this repository: the landmark and phantom direction stays private.

The owner asked for a Metaflow pipeline with quality-assurance checkpoints, convergence, the anomaly classes encoded and decoded, the 3-D landmarks whose 2-D projections fingerprint each level uniquely, that fingerprint present in real fluoroscopy and the latency, which propels itself until they are met, with no artificial limit on it other than knowing how much space each block's output takes so the memory never chokes; and, at 02:03 UTC, that C-ArmLSpine's paired CT and fluoroscopy serve the search for the lumbosacral landmarks. The loop is that pipeline, under PREREG.md beside this file, frozen before any run.

- The flow: QaloopFlow (flows/qaloop.py, flows/README.md), started only through flows/launch.py. start holds the run to the PREREG and the plan's bytes; round runs one round of tools/qaloop_round.py, which trains the auto-anatomist further on phantoms of six column classes (typical, lumbar_rib, no_rib_t12, six_lumbar, four_lumbar, t13) and asks six gates; the controller (tools/qaloop_gates.py) makes one change for each failing gate, or ends the loop; the next round is the same step again, Metaflow's recursive switch, so the whole loop is one run that a later job of the same words resumes at the round a time limit cut. end writes RECORD.json, SUMMARY.md, ENDED.json and the CLAIM 2024 and REFORMS report (tools/report.py --study qa-loop, tools/qaloop_report.py).
- The gates and their bars (PREREG.md section 3): convergence of the training loss and the held-out surface distance; each anomalous class's key vertebra outlined from the CT alone (Dice 0.80), named by the name head (0.70) and told from its latent alone (probe recall 0.60); the landmark fingerprint, a greedy search over a pool of eighteen landmarks per level for the fewest that name each level in one frame of a C-arm run, per view and anchor (Wilson lower bound 0.9 and a margin); that fingerprint's presence on real frames, each landmark's edge strength against the body's own pixels; real naming on C-ArmLSpine's frames; and the naming path's 95th percentile within 97 ms.
- The real arm: C-ArmLSpine's CBCT and spot frames with their registered poses, the cases where both labellers agree on two or more levels; the landmarks are placed on each case's masks in 3-D and projected through each frame's own pose, which is how the paired data serves the lumbosacral search. The test persons of data/splits/test-persons.json are never read.
- No artificial limit: each round measures every block's bytes on disk and peak memory per unit (a pair's case, a phantom row, a fingerprint person, a round) and sizes the next round from them, the most rows and the most persons a class the host's memory holds. The loop plan sets no other limit on the data it grows; the name head's weight, the number of landmarks and the presence floor move in ranges the plan gives, which are the space the controller searches.
- The grid: the word `qaloop <plan>` (grid/gate.sh) queues a chain of GPU links of 12 hours on galhp, one for the smoke and six for the loop, each afterany the one before and each resuming the run; a send after a chain whose links ran out carries it on at the chain's own commit, and a chain that ended in failure is sent again only once a commit changes what failed. The plans are grid/qaloop/qa_smoke.json and grid/qaloop/qa_loop.json, both held by the PREREG's Covers line by their bytes.
- Where it stands: the smoke ran end to end through the launcher on CPU in this thread's container on 2026-10-31, on stand-ins since the container holds no C-ArmLSpine: two rounds of 25 steps, every gate asked in both, latency passing and the other five failing as so short a training must, the report written and the verdict 0, in about four minutes. Its numbers answer no question. The first smoke showed one flaw, fixed before any grid run: with four gate persons a type, a cell the chosen landmarks named perfectly failed on its interval alone, and the gate called it beyond the ceiling because the whole pool's accuracy, fitted on so few persons, was below the bar; the controller would have stopped growing the data for such cells. A cell is now beyond one frame only where the upper bounds of its own interval and the pool's are both below the bar, and the persons grow as far as the memory holds before any cell is named beyond (PREREG.md sections 3 and 4, refrozen). In both rounds the anteroposterior cells of the four- and six-lumbar classes counted from the bottom named no run right, which is the first known limit of PREREG.md section 6: the phantoms draw an L6 as an L5 and a four-lumbar column simply lacks one, so a frame that shows neither the thoracic levels above nor a count from the sacrum cannot tell those columns from a typical one. Nothing has been sent to the grid yet.
- The tests: tests/test_qaloop.py (the gates, the controller, the plans), tests/test_qaloop_report.py (the report), tests/test_run_code.py (the code the loop's runs are named by) and the qaloop tests of tests/test_gate.py (the word's refusals, one link for the smoke, six for the loop, the carry-on and the failure).
