# How large imaging corpora are organised, versioned and accounted for, and how the catalog compares

Source: the thread "SchwingNet video demo plan", 2026-10-21, the owner's ask of 01:46 UTC ("the database should be readonly and versioned ... compare how I'm doing it with like Google or Facebook ... make sure the dataset itself is organized nicely in a way which lends itself naturally to good data accounting and efficient expansion of new datasets in an alphabetical or at least systematic structure"). A deep-research run of four researchers (Google: TFDS, ArrayRecord, Grain, Data Cards; Meta and peers: WebDataset, SA-1B, Hugging Face, Megatron, Croissant; medical consortia: BIDS, nnU-Net, MIMIC-CXR, TCIA, MIDRC; versioned catalogs: SQLite, Delta, Iceberg, Lance, DVC, Metaflow) and one report writer, run in the cloud session; the full report with every link is kept in the session's scratchpad and summarised here, since the project keeps research in the repository. The cloud session could not reach tensorflow.org, sqlite.org, docs.metaflow.org, arxiv.org, physionet.org or ai.meta.com, so most primary text was read from the projects' GitHub sources and the rest from search summaries; the last section lists what that leaves open. This note is what the catalog of task #10 took from it in #33 (the versioned read-only store, the layout and the ingest tool).

## What every organisation surveyed does

- A version is an immutable object under a new name plus a small pointer that is swapped, never an edit in place. TFDS writes each version into `<dataset>/<config>/<MAJOR.MINOR.PATCH>/`, checks the version on every read and lets only the newest version be generated; Delta names each commit by a 20-digit zero-padded number so a directory listing is the history; Iceberg writes `v<N>.metadata.json` with a snapshot log (snapshot id, parent id, sequence number, timestamp, an `operation` word) and swaps one metadata file for another; Lance writes an immutable manifest per version with the writer's version stamped in it; Hugging Face makes a version a git commit over content-addressed 64 MB blocks; PhysioNet and BIDS put the version in the URL or the DOI. TFDS's semantics are the sharpest: adding records is a MAJOR bump, because every published slice is arithmetic over the per-shard counts.
- Content addressing lives in the storage layer, and the fan-out is two hex characters: DVC's cache is `md5/<2 chars>/<30 chars>`, Metaflow's datastore is `sha[:2]/sha` ("duplicate content is only stored once"), Croissant recommends a sha256 on every file object, Xet stores each block once under its hash; MIMIC-CXR's `p10..p19` folders are the same idea over a readable id.
- Shards are named by a zero-padded counter and sized for sequential reads: TFDS `-00450-of-01024` with 64 MiB to 1 GiB per shard, WebDataset `-{000000..000999}.tar` with 100,000 records or 3 GB per shard, Hugging Face `train-00000-of-00003`, SA-1B about a thousand tars of 10 to 12 GB. No surveyed system names a shard by its content. ArrayRecord is the random-access counterpart (a footer index, `group_size:1` for per-record reads, PNG and JPEG kept uncompressed inside it), and Grain checkpoints only an index, so a resumable run is pinned by an unchanged dataset version plus a seed.
- Accounting is counts per file rolled into totals per snapshot: TFDS `shardLengths`, Delta `numRecords` per `add` with removed files kept as tombstones, Iceberg's `added-/deleted-/total-` triple for files, records and bytes. The human ledger (licence, origin, ethics, citation, who generated it) is a card beside the tree: Data Cards and Healthsheets, Datasheets' seven sections, Croissant with its RAI vocabulary, BIDS `dataset_description.json` with `SourceDatasets` and `GeneratedBy`. None of them has a field for the consuming site's IRB status or the date acquired.
- Medical consortia key the tree and the split on a patient pseudonym: MIMIC-CXR `p10/p10000032/s50414267/`, CheXpert `train/patient42142/study5/`, BIDS `sub-<label>/ses-<label>/`, MIDRC's 80/20 sequestration by unique patient at ingestion, Google Health's chest-radiograph study keeping a patient in one split. A new source is a new container with its own descriptor (nnU-Net `DatasetXXX_Name`, BIDS `derivatives/<pipeline>/`, TFDS `dataset/config`), nothing old touched; DINOv2 adds relative deduplication on ingest against the pool and every held-out set.
- A read-only SQLite file on a network filesystem is safe exactly when it never changes. SQLite's own guidance: network filesystems have locking bugs, WAL does not work over one, and `immutable=1` "skips all file locking and change detection" and forces read-only; `nolock=1` is for writers and the wrong flag. CephFS is better than NFS (coherent caches, fcntl through the MDS) and still ranks itself below a local filesystem. DVC's shared-cache recipe is the same discipline: files 0444 on the share, any mutable state on local disk. Metaflow has no path-plus-hash pin of its own: a step reads the file by path and stores its hash as an artifact.

## How the catalog compares, point by point

| The catalog (#10, #33) | Nearest practice | Verdict |
|---|---|---|
| One folder per source, named by a lowercase id; the registry's grid_root is that folder and the data root lists sources alphabetically | TFDS snake_case names and `dataset/config` keys; nnU-Net `DatasetXXX_Name`; BIDS `sub-<label>` | Matches. The id grammar `[a-z0-9_]+` is TFDS's, lowercased. |
| Shards at `<source>/shards/<date>-<12 hex>/`, named by the digest of their sorted frame hashes | No surveyed system content-names a shard; the hash lives in a manifest or the store | Departure, kept on purpose: a shard is self-verifying and the same bytes ingested twice are the same shard, which is what makes the ingest idempotent. What the name drops, the count, the manifest and the catalog carry (`item_count` per shard, frames per source and part per version). |
| Frames at `<aa>/<sha256>.<ext>`, 0444 | DVC `md5/ec/...`, Metaflow `sha[:2]/sha`, MIMIC `p10..p19` | Matches exactly. |
| Frames as individual files on CephFS | Every loader surveyed packs records into containers for sequential I/O | Departure, and the one thing to measure before the first training run: whether a training step reads the tree directly or packed shards derived from it under the same hashes. Not yet measured. |
| `versions/catalog-NNNNNN-<12 hex>.sqlite`, 0444, `PRAGMA application_id` and `user_version` stamped, opened `mode=ro&immutable=1` | SQLite's own `immutable=1` guidance; Delta's zero-padded commits; Iceberg `v<N>.metadata.json`; DVC's 0444 cache | Matches; the hash in the file name is a check neither Delta nor Iceberg puts in theirs, and a reader checks the whole hash against the log line, since the mode guards against a slip and not against a replaced file. |
| `VERSIONS.jsonl`, append-only: parent, written_at never earlier than the parent's, reason, bytes, shards added and removed beside the running totals, frames per source and part, embeddings per model | Iceberg's snapshot log and summary; Delta's log; Lance's writer stamp | Matches in shape; written_at, bytes and the totals beside the deltas were added from Iceberg in #33. |
| `CURRENT`, written to a sibling and renamed into place | Delta `_last_checkpoint`; Iceberg `current-snapshot-id` | Matches, with the rule that a job resolves `CURRENT` once at its start and holds the resolved path for its whole life. |
| A build whose bytes equal the latest version is dropped, so the store never holds two of one thing | TFDS: only the newest version can be generated | A stronger rule than any surveyed; the catalog's bytes are a function of its inputs (the code commit it is told counts as one), so this is cheap. |
| Person pseudonym as the split key, frozen test persons, a salted hash for the rest, the split check per source at its identity level | MIDRC's sequestration by unique patient; MIMIC-CXR patient lists; beethoven-research's SplitLevel and disjoint | Matches; `split-check` is REFORMS's disjointness rule over the catalog's own person table, refusing a version before any training step reads it. |
| The descriptor per source | Data Cards, Healthsheet, BIDS, Croissant | Present as two files already: data/sources/<id>.json (what it is, licence, reach, counts) and data/registry/<id>.json (identity level, person-key rule, access and determination, modality, device class, regions, grid root, shards). The IRB and date-acquired fields none of the public conventions carry are in the registry's access line. |
| Deduplication on ingest | DINOv2's relative dedup | Exact duplicates by sha256 within a bank are reported and kept once; near-duplicates (a perceptual hash column) and dedup against the existing archive are not built. |

## What #33 took, and what it left

Taken: the layout above as contracts under the gate (schwingnet.catalog.frame_path, shard_folder, version_file_name, changed_keys) and as refusals in the tool (a registry file named other than its source, a grid root that is not the source's folder, a shard manifest anywhere but `<grid_root>/shards/<shard>/MANIFEST.json`, a frame whose path is not its content address); the versioned read-only store with its log and pointer; Iceberg's timestamp, size and totals on every log line; SQLite's `application_id`, `user_version` and `VACUUM` before the file is sealed; the ingest tool (tools/ingest.py) that writes a bank into one shard at its content addresses with its manifest and a report, idempotent by construction; the split check as a command.

Left, each with its reason: Hugging Face's git-and-Xet model (a repository with commit history is the wrong tool for a private grid archive, and its own limits of 10,000 files per folder would bind at once); WebDataset's resampled epochs (the determinism rules forbid them); Delta's tombstone expiry and Iceberg's optimistic concurrency (one builder, many readers, a rename is enough); nnU-Net's numeric ids (a word is an id); `nolock=1` and WAL (both exist for writers, and the volume has none); a stored per-source count in a card (counts come from the catalog, as BIDS and MIMIC-CXR derive them; a stored count the table contradicts is the wrong-but-plausible number the project's rules warn of); an ordinal in a shard's name (meaningless for content-named shards; the catalog orders shards by ingest date and name).

## Measured here, 2026-10-21, the cloud container (4 cores), synthetic banks

The numbers are in data-catalog.md under "Smoke and stress test"; the one measurement that is not made, and that the report calls the decision to make with a number in hand, is a training step reading frames one file at a time over CephFS against reading a packed shard, on a grid node.

## What is not verified

sqlite.org's prose was read through search summaries and checked against pager.c, not quoted from the pages; no source measures `immutable=1` on CephFS read from many nodes; no published measurement of per-file reads against packed shards on CephFS was found; Google's internal layout and Google Health's storage are unpublished, and the one organisation fact (a patient stays in one split) is read from a search fragment; the Data Cards paper's framework is recollection; Meta's internal practice is known from engineering-blog snippets and SA-1B's shard sizes from community reports; Hugging Face's revision pinning and `dataset_info` YAML are from memory; BIDS's required field levels, MIMIC-CXR-JPG's split files, MSD's licence key, TCIA's per-collection licence rules, MIDRC's dataset and imaging-study schemas and nnU-Net's `splits_final.json` were not read from primary pages; Lance's protobuf fields are not verbatim; metaflow-slurm's data handling was not determinable.
