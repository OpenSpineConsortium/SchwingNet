## 1. The question

Is the static check's prediction right, row by row, on a GPU: does every combination of the training blocks that `tools/block_sweep.py check` says runs train and evaluate on each catalog of the smoke, and is every combination it says is refused refused for the reason it gives, so that any combination within the blocks' stated incompatibilities works on any dataset held, the annotated and the unannotated sets passed on as they should be.

## 2. Population and inputs

- The plans: grid/sweeps/synthetic.json (sha256 4d9481676c3ac6f64f68ea9ed139dc3a71cc8ccb6dee43bead4d08e271a99cc2), grid/sweeps/real.json (a0a580a28c17966a1fae3e35855f5dd0bacca1f7cc133bd763bcc134d13d81e0) and grid/sweeps/two_source.json (c026b6e79281870d710c0e45cb2d85791b0f337ff060f04f816f518433106556) at the commit above, each regenerated byte for byte by a test from tools/block_sweep.py, so a plan is a function of the code. Each holds 27 rows of 3 epochs at seed 1: 20 rows of the covering array, in two halves, the prior off and the level-map prior on, holding every value of every factor and every pair of the parts whose code meets, each half closing with the two cuts to one labelled source of several; one row from the ImageNet file; two warm starts from a cover row, one adding the prior; and the four refusals the check predicts.
- The catalogs: the synthetic catalog `tools/block_sweep.py synthetic` builds (a labelled bank with level maps, its labelled cases split between two labelled sources, the frozen test persons and an unannotated bank); catalog version 1 of C-ArmLSpine, real frames, chosen by grid/v1-version.sh --alone; and that catalog with VinDr-SpineXR banked beside it. Each is a versioned catalog whose split check passes before the launcher starts (grid/sweep-driver.sbatch).
- The test persons: data/splits/test-persons.json (sha256 4c57462fb8d4fa4591fb73d10e506957b5f00f66c25c2e7f07731f2f073cb59d), kept out of train and validation by the catalog's split rule.
- The weights: the ImageNet ResNet-18 file resnet18-f37072fd.pth for the row that names it; where it is missing, the rows that start from it are not applicable.
- Exclusions: none beyond the rows the check calls not applicable, each with its stated reason, as the four cuts to one labelled source of several on a catalog that holds one labelled source, where such a cut keeps every crop or none.

## 3. The measurements

- Per row, the outcome tools/block_sweep.py records: ran (the flow trained and evaluated it), refused with a code of its REFUSALS, failed, not applicable or to come; and whether it matched the check's prediction (block_sweep.matched).
- Per row that ran: its best validation accuracy, its test accuracy over all levels and its W&B runs, as results.json holds them; and its CLAIM 2024 and REFORMS report (tools/report.py), written by the row after its last step and checked by the flow's end step against the row's files as the row left them, before anything is written; where the row left no report, the end step writes it and then checks it. A row is the run's own where its work was done in that Metaflow run: its FINISHED.json, which tools/flow.py writes last, was written after the run began, as Metaflow registered the run, or, where the row holds none, the newest of its files other than the report's was. A row the run cloned from the run it resumes, or one tools/flow.py found finished and left as it was, is not the run's own.
- Per sweep: the counts of results.json and the faults the flow caught.

## 4. The hypotheses and their bars

- H1: every row's outcome matches the check's prediction: no row failed, mismatched or still to come, and no fault caught.
- H2: every row that ran has a current CLAIM 2024 and REFORMS report at the end, and no row of the run's own left a stale one.
- The bar is exact equality. The prediction is deterministic, made from the catalog's facts before any row trains, so no number is estimated, and neither a published value nor a power calculation applies. An item a report counts as missing is shown and is not a failure: a smoke row says that a route works, not how well, and no smoke number is to be published.

## 5. What counts as failure

- A mismatch, a failed row, a row still to come or a caught fault: the verdict is 1, with the sentence "the check's prediction for <row> was wrong: it said <predicted> and the row <outcome>", or for a fault "<row> could not be run or recorded: <its last line>". A mismatch is a bug in the check or in the blocks, fixed before the plan is sent again.
- A row of the run's own whose report, as the row left it, is not what the row's files give, or any row whose report cannot be written or does not check once written: the verdict is 1, with one of these lines among the report's lines on the run's progress page: "<row>: NOT CURRENT as the run wrote it, so written anew; why: <the check's words>", "<row>: NOT CURRENT as the run wrote it, and not written anew; why: <the check's words>" (or "as an earlier run wrote it", for a row not the run's own), "<row>: NOT WRITTEN at the end; why: <the tool's words>" or "<row>: NOT CURRENT once written at the end; why: <the check's words>". A stale report is written anew where the tool can write it, so the page and the row's folder show the current one; the run's verdict stays 1.
- A stale report of a row that is not the run's own is no failure: it says only that tools/report.py, data/reporting/study.json or the checklists changed after the row's work was done, which no run's key names, so a run cut and resumed, or the plan sent again after a success, would otherwise fail for what it never did. It is written anew under the report tool as it is now, with the line "<row>: written anew under the report tool as it is now, its work done before this run began; <its counts>; it was not current, why: <the check's words>".

## 6. The analysis plan

The verdict is computed by flows/sweep.py (verdict_of) from results.json and the reports, so no reader chooses it, and the run's progress page shows it with each report's counts. The accuracies are description only: a smoke row trains three epochs, so its accuracy says that the route works, not how well, and it is never read as a result about SchwingNet nor compared between rows. Nothing is read blind, since no person reads an image.
