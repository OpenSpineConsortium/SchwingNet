# SchwingNet: goal and settings

This file is the project's goal and the settings every account's thin Project shares. It is the one place where the goal is written: CLAUDE.md imports this file into every session, and the claude.ai Projects carry no copy of it. It changes by pull request like everything else.

## Goal

Confidential: this file describes unpublished work with a provisional patent in preparation, and stays in this private repository; nothing of it is copied to a public place. SchwingNet names vertebral levels on intraoperative fluoroscopy; the reported stack and its numbers are spine-program's 01_carm_level_detection (README.md, STATUS.md, docs/MODEL_CARD.md). This project makes the next SchwingNet as a workflow that grows: low-latency, high-accuracy vertebral classification on fluoroscopic video or images, built through Symphony's claim protocol and beethoven-qa's definition of done between 2026-10-20 and the CNS talk of 2 November 2026 (mini-oral 66629), so that every number the talk shows is reproduced by a command from a record in this repository. Done is: a dataset added by one pull request and one incremental run, no epoch run twice; version 1 of SchwingNet, one model per stage trained to work on the registry as it stands, with its card; an evaluation page that draws fixed real witness frames at every checkpoint and tables every version with intervals and its latency, in Weights and Biases and on this repository's docs site; and the recorded C-arm sweep with the overlay and the measured latency, ready to show once the provisional is filed (by 30 October). The plan is docs/research/retraining-plan.md (version 2, the owner's words of 2026-10-20); no training job is submitted before the owner gives the word and the number for it.

## Scope

In scope: the areas this project owns, each in one line; docs/agents/OWNERSHIP.md maps them to workers.

- The retraining, once the owner has stated the measure: the pre-registered plan, the grid jobs through Beethoven (docs/setup/grid.md), the clean encoder rebuild, the split check, the eval gate; every number carries its run id, commit and result file.
- The measurement: held-out C-ArmLSpine, the transitional stratum with two readers, the synthetic anomaly arm with exact truth, never pooled with the real one.
- The demo: the recorded sweep (C-ArmLSpine case134 and case39), the overlay, the measured latency, the slides' figures.
- The quality gate: new code to beethoven-qa's definition of done; the legacy tools of the reported pipeline listed under unproven, never refactored before the talk, since a refactor voids the parity gate.
- The synthesis of the artifacts (artifacts/_synthesis/), the record the Artifact Textbook is written from, kept current by .github/workflows/synthesis.yml: it looks with no Claude at every change of an artifact, a research note or a dataset record, within minutes of a merge a person or an App makes and at the next daily run for one GitHub's auto-merge makes, and runs the Claude reads a change needs, 10 runs a day unless the variable SYNTHESIS_READS_PER_DAY says otherwise, 50 at most, each adding what it read to the one open synthesis pull request, or opening it (#166).

Out of scope, by decision: what this project does not do, each with the reason, so nobody proposes it again.

- Anything public before the provisional is filed: no push to a public repository, no preprint, no slide of the method; the talk shows what SchwingNet does, not how (the owner, 2026-10-20).
- A live run at the podium: no laptop latency exists and the CPU path took seconds per frame; the demo is a recording of a causal run with its latency on screen.
- A grid job, a Claude run or a training without the owner's word and the number of jobs; usage credits are never used. The synthesis reads of .github/workflows/synthesis.yml have that word and number: the owner chose on 2026-10-23 that they start on their own, 10 runs a day unless the variable SYNTHESIS_READS_PER_DAY says otherwise, 50 at most, and the variable SYNTHESIS_READS set to off stops them (#166). The textbook's research loop, .github/workflows/research.yml, has a standing exception for grid jobs, fetches and training: the owner asked on 2026-10-24 at 16:17 UTC for a Claude integration that continues the research "AUTONOMOUSLY ... INDEPDENTLY OF HUMAN INTERACTION", and at 17:36 UTC, told it would ask first, answered "no i dont want this restriction ... give it full command to direct autonmous research" (#220). It runs every four hours, at most RESEARCH_RUNS_PER_DAY runs a day (6 unless it says otherwise, 50 at most), the variable RESEARCH_LOOP set to off stops it, and it still keeps the size rule, the refusals of gdown, Kaggle and Redivis until #163, no CT-RATE without the owner's terabytes, no Radiopaedia by script, no usage credits, the claim protocol and nothing public; letters, e-mails and the gate words it cannot reach stay the owner's (.github/symphony/research.md).
- A settings-as-code app (github/safe-settings, or the Repository Settings App reading .github/settings.yml), decided no on 2026-10-11 (symphony-template#18): it is a dependency with admin rights on every repository it covers, and a server of our own in one case, for settings that Symphony Setup applies for one run from the front door, scripts/setup-repo.sh from a clone, and organization rulesets, secrets and variables for what an organization makes.

Its ecosystem.json is the one list of which repository takes which modules, and its ECOSYSTEM.md, generated from that list, maps all five repositories.
