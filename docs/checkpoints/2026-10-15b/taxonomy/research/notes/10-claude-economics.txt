# Economics and terms of running Claude Code on a subscription in automation (as of 2026-10-15)

Research notes for the Symphony/Beethoven positioning study. Every primary page below was fetched by this worker on 2026-10-15 (curl or WebFetch); line numbers refer to the Markdown copies served at `https://code.claude.com/docs/en/<page>.md`, to `https://platform.claude.com/docs/en/about-claude/pricing.md`, to the github/docs repository at commit 12691d2 (2026-10-15), or to local clones. Grades: Verified (primary source opened), Reported (secondary source or search summary only), Inferred (reasoning from cited facts).

## Takeaways

- Running Claude Code in GitHub Actions on a flat Claude subscription is a documented, first-party path, not a loophole: Anthropic's GitHub Actions page tells users to put a `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token` in a repository secret, "available on Pro, Max, Team, and Enterprise plans", and says "If you authenticate with an OAuth token, runs use your Claude subscription instead of API billing." Symphony's workers.yml and coordinator.yml use exactly this (anthropics/claude-code-action@v1 with `claude_code_oauth_token`).
- That path is the distinctive economic fact of Symphony: the main neighbors that are also Actions-native do not offer it. openai/codex-action requires an API key; GitHub Agentic Workflows (gh-aw) says "Claude subscription OAuth tokens such as CLAUDE_CODE_OAUTH_TOKEN are not supported"; GitHub Copilot's own and third-party coding agents bill per token in AI credits (1 credit = $0.01) plus Actions minutes. Free standard-runner minutes on public repositories plus a flat Claude plan gives a near-zero marginal cost per agent run until the plan's five-hour or weekly window is hit.
- The boundary is narrow and moved six times in 2026. Consumer Terms (effective 2025-10-08) forbid automated or non-human access "Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it"; the Claude Code legal page is the explicit permission for Claude Code itself, and says OAuth is "designed to support ordinary use of Claude Code and other native Anthropic applications" and that "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK." Third-party harnesses (OpenCode, OpenClaw) were blocked on 2026-01-09 and cut off from subscription limits on 2026-04-04 (Reported); a planned June 15 Agent SDK credit was paused (Verified), and on 2026-10-07 Anthropic wrote "You can still use the Claude Agent SDK, claude -p, and third-party apps with your subscription limits" (Verified), which sits uneasily beside the legal page's ban on routing Free/Pro/Max credentials on behalf of users.
- Plans and prices (claude.com/pricing, 2026-10-15): Free $0; Pro $20 monthly or $17/month annual ($200 up front); Max 5x $100 and Max 20x $200, monthly only; Team standard seat $20 annual / $25 monthly, premium seat $100 / $125 (5x standard), 2 to 150 seats; Enterprise $20/seat/month annual, 20-seat minimum, plus all usage at API rates. Claude Code is in every paid plan, and all surfaces (apps, Claude Code, cloud sessions, routines, the Action) draw on one pool with a rolling five-hour window plus a weekly limit. Anthropic publishes no absolute token numbers, only multiples (Pro at least 5x Free per session; Max 5x/20x Pro per session).
- The new Max and Team monthly API credits ($100 Max 5x, $200 Max 20x; Team $20 per standard and $100 per premium seat, pooled to at most $500) do not stretch Symphony's Action runs: the support FAQ says "Runs started by the Claude Code GitHub Action ... count as Claude Code usage, so API credits don't cover them, even with -p." They do cover `claude -p` and the Agent SDK run with an API key from the linked Console organization, and they expire monthly.
- API list prices for comparison (per million tokens, input/output): Fable 5.1 $10/$50, Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0.10/$0.50 (prompts up to 100K tokens); cache reads are 0.05x input on Opus 5.5 and Sonnet 5.5 ($0.20 and $0.10). A 40-turn agent run of about 1.6M cache-read tokens works out at roughly $0.70 on Sonnet 5.5, $1.40 on Opus 5.5 and $3 on Fable 5.1 (Inferred); Anthropic's own enterprise average is "around $13 per developer per active day and $150-250 per developer per month".
- Binding constraints for Symphony: the OAuth token is "tied to the subscription of the person who ran claude setup-token", and Anthropic recommends an API key, not an OAuth token, for a secret shared across repositories (organization secret); every worker in Actions shares that one person's five-hour and weekly window; the token "can only make model requests" and cannot start Remote Control; an account pool rotating several accounts of one person is the riskiest part of the plan under the "ordinary, individual usage" sentence and the Usage Policy's multiple-accounts clause (Inferred).
- Beethoven's design matches the rules: Remote Control is on Pro, Max, Team and Enterprise only ("API keys are not supported"), needs an interactive `/login`, makes outbound HTTPS only, and can serve up to 32 sessions per server process; the legal page explicitly allows "an end user signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code". hpcworker handles no token, no setup-token and no multi-account rotation.
- Anthropic's own first-party coordination products now overlap Symphony's coordinator role and run on the same subscription: cloud sessions (no separate VM charge; 4 vCPU, 16 GB RAM, 30 GB disk), Projects (one conversation starting parallel cloud threads; enforced cap 200 new threads per day; Pro and Max only; private to one account), and routines (100 scheduled runs per hour per account). What they lack is a shared, multi-account, repository-resident plane; that is Symphony's gap to fill.

## Findings

### 1. Plans, prices and Claude Code limits

- Pro: $17/month with annual billing ($200 up front) or $20 monthly; includes Claude Code. [Verified] https://claude.com/pricing (fetched 2026-10-15); https://support.claude.com/en/articles/8325606-what-is-the-pro-plan ("$20 per month (US)").
- Max: "From $100"; Max 5x $100/month, Max 20x $200/month, "currently available as a monthly subscription only"; adds priority access at high traffic and "$100 to $200/month in API credits to build on the Claude Platform". [Verified] https://claude.com/pricing; https://support.claude.com/en/articles/11049741-what-is-the-max-plan
- Team: 2 to 150 seats; standard seat $20/seat/month annual, $25 monthly, "more usage than Pro"; premium seat $100 annual, $125 monthly, "5x more usage than standard seats"; up to $500/month pooled API credits. Enterprise: "US$20/seat/month, billed annually, 20 seat minimum. Usage cost scales with model and task" (usage at API rates). [Verified] https://claude.com/pricing
- Limits structure: "Every plan has usage limits that reset on a rolling five-hour session window, and paid plans add weekly limits on top. Your activity across Claude on web, desktop, mobile, and Claude Code all draws from the same pool ... there's no fixed message count. ... Pro gives you at least 5x more usage per 5-hour session than Free. Max gives you 5x or 20x more usage per 5-hour session than Pro." Anthropic "may limit your usage in other ways, such as weekly and monthly caps or model and feature usage, at our discretion." [Verified] https://claude.com/pricing FAQ; https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work (updated 2026-10-14)
- Weekly limit resets at a fixed weekly time assigned to the account; occasional "limit resets" can restore a five-hour or weekly limit to full (not usable from Claude Code in the terminal). [Verified] https://support.claude.com/en/articles/11049741-what-is-the-max-plan; https://support.claude.com/en/articles/17007452-what-is-a-limit-reset
- Fable models (Fable 5, Fable 5.1, $10/$50 API): on Max and Team/Enterprise premium seats up to 50% of weekly limits may go to Fable at no extra cost; on Pro and standard seats Fable runs only on pay-as-you-go usage credits (since 2026-07-19 for Fable 5). [Verified] https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan (dated 2026-09-02); pricing table on https://claude.com/pricing
- Limits history 2026: on 2026-05-06 Anthropic doubled "Claude Code's five-hour rate limits for Pro, Max, Team, and seat-based Enterprise plans" and removed "the peak hours limit reduction on Claude Code for Pro and Max accounts", citing a SpaceX Colossus 1 deal (over 300 MW, over 220,000 NVIDIA GPUs). [Verified] https://www.anthropic.com/news/higher-limits-spacex
- A temporary +50% weekly Claude Code limit (from 2026-05-13) was replaced on 2026-09-14 by a permanent +25% over the original baseline, a 17% cut versus the promotion; the 2026-08-29 @ClaudeDevs post also said the separate Fable weekly limit would be removed. [Reported] https://x.com/ClaudeDevs/status/2093742321473065266 ; https://www.bleepingcomputer.com/news/artificial-intelligence/anthropic-is-cutting-claude-codes-current-weekly-limits-by-17-percent/ . Conflict: support pages updated in October 2026 still say "Max plans also have a separate weekly limit for Fable" (https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan; https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans).
- Past the limits, "usage credits" (formerly extra usage) bill at standard API rates against a prepaid balance with an optional monthly cap; they do not expire except in jurisdictions such as Japan (six months from 2026-09-10). [Verified] https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans
- On the Pro plan the five-hour "wrap-up allowance" (finish the step in progress after the limit) applies "up to once per weekly usage period"; on Max each time a five-hour limit is hit. [Verified] https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan
- Team and seat-based Enterprise: "each member's Claude Code usage draws from a per-seat allowance that resets on a rolling five-hour window and a weekly window", shared with chat and Cowork; usage-based Enterprise has no per-seat limits and bills at API rates. [Verified] https://code.claude.com/docs/en/costs.md line 154; https://support.claude.com/en/articles/11845131-use-claude-code-with-your-team-or-enterprise-plan
- A proposed class action (Kahn v. Anthropic, N.D. Cal., filed about 2026-06-14) alleges Max 20x delivers six to eight times Pro and Max 5x about 3.5 times; motion-to-dismiss hearing reported for 2026-11-06. [Reported] https://aiweekly.co/alerts/anthropic-sued-over-claude-max-5x-and-20x-usage-claims ; https://decrypt.co/371201

### 2. claude-code-action on a subscription token (CLAUDE_CODE_OAUTH_TOKEN)

- Anthropic documents it: "CLAUDE_CODE_OAUTH_TOKEN: an OAuth token that authenticates with your Claude subscription, available on Pro, Max, Team, and Enterprise plans. Generate one by running claude setup-token locally." `/install-github-app` offers "creating a long-lived token with your Claude subscription" and saves it as that secret. [Verified] https://code.claude.com/docs/en/github-actions.md lines 34-38, 77
- Cost statement: the Action consumes GitHub Actions minutes, and "If you authenticate with an OAuth token, runs use your Claude subscription instead of API billing." [Verified] same page lines 303-308
- Organization caveat: "For a secret shared across repositories, authenticate with an API key ... rather than an OAuth token, since an OAuth token is tied to the subscription of the person who ran claude setup-token." Workload identity federation (OIDC to a Console service account) is the keyless API alternative. [Verified] same page lines 91-107
- Token properties: `claude setup-token` makes "a one-year OAuth token", "requires a Pro, Max, Team, or Enterprise plan", "can only make model requests, so it can't establish Remote Control sessions or fetch claude.ai connectors"; bare mode (`--bare`) does not read `CLAUDE_CODE_OAUTH_TOKEN`. [Verified] https://code.claude.com/docs/en/authentication.md lines 276-310
- Risk: the headless page says "--bare is the recommended mode for scripted and SDK calls, and will become the default for -p in a future release", and bare mode "never reads OAuth credentials". [Verified] https://code.claude.com/docs/en/headless.md lines 43-49, 70. Whether claude-code-action will then pass a flag that keeps OAuth working is not stated. [Inferred]
- The action's own setup doc names a narrower set: "Pro and Max users can generate this by running claude setup-token locally". [Verified] anthropics/claude-code-action docs/setup.md line 10 (commit a26b07d, 2026-10-14). Conflict with code.claude.com, which adds Team and Enterprise.
- Max/Team monthly API credits do not cover the Action: "Runs started by the Claude Code GitHub Action, an IDE extension or the Claude desktop app count as Claude Code usage, so API credits don't cover them, even with -p." They do cover "claude -p and the Claude Agent SDK when you run them yourself with an API key from your linked Claude Console organization". [Verified] https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-and-team-plans (FAQ)
- Symphony uses this path: workers.yml and coordinator.yml call anthropics/claude-code-action@v1 with `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`, capped by `--max-turns` (40 to 60 for the coordinator) and job timeouts (30 to 90 minutes). [Verified] /home/user/symphony-template/.github/workflows/workers.yml lines 140, 271-278; coordinator.yml lines 104, 139-146, 298, 329-336. Its docs say runs "draw on the main account's Claude plan ... and bill nothing", sharing "the five-hour window and the weekly limit" with that account's sessions. [Verified] /home/user/symphony-template/docs/setup/claude-action.md lines 14-21, 39-48

### 3. Terms, usage policy, third-party harnesses and the 2026 enforcement

- Consumer Terms (effective 2025-10-08, still current on 2026-10-15) cover Free, Pro and Max; Commercial Terms cover Team, Enterprise and API. Section 3 forbids accessing the Services "through automated or non-human means, whether through a bot, script, or otherwise" "Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it"; Section 2: "You may not share your Account login information, Anthropic API key, or Account credentials with anyone else. You also may not make your Account available to anyone else." [Verified] https://www.anthropic.com/legal/consumer-terms ; https://code.claude.com/docs/en/legal-and-compliance.md
- Claude Code legal page, "Authentication and credential use": OAuth "is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications"; developers building products, including on the Agent SDK, "should use API key authentication"; "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users", nor "collect, store, or intermediate Claude.ai credentials or session tokens"; enforcement "may" come "without prior notice". [Verified] https://code.claude.com/docs/en/legal-and-compliance.md
- Same page: "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK." Hosting is allowed if "Each end user must authenticate with their own Anthropic API key, Claude subscription plan credentials, or 3P inference provider credential" and the binary is unmodified; the page "does not ... prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code". [Verified] https://code.claude.com/docs/en/legal-and-compliance.md
- Usage Policy: a new version published 2026-10-08 takes effect 2026-11-12. Under "Do Not Abuse Our Platform" it prohibits "Coordinate malicious activity across multiple accounts, or create multiple accounts, to avoid detection, circumvent product guardrails, or generate identical or similar inputs that otherwise violate our Usage Policy", "Utilize automation in account creation", and bypassing "capabilities, restrictions, or guardrails established within our products". Agentic use: "Users are responsible for ensuring that agents they build or deploy ... comply". [Verified] https://www.anthropic.com/legal/aup ; https://www.anthropic.com/news/2026-usage-policy-update
- 2026-01-09: server-side checks stopped third-party tools (OpenCode among them) from using Pro/Max OAuth by spoofing the Claude Code client; Thariq Shihipar (Anthropic) said safeguards against "spoofing the Claude Code harness" were tightened. [Reported] https://thenewstack.io/anthropic-claudecode-opencode-split/ ; https://paddo.dev/blog/anthropic-walled-garden-crackdown/ ; https://gigazine.net/gsc_news/en/20260220-anthropic-third-party-block
- 2026-02-19/20: the documentation update that added the "Authentication and credential use" wording was read as an explicit ban on subscription OAuth in third-party tools. [Reported] https://winbuzzer.com/2026/02/19/anthropic-bans-claude-subscription-oauth-in-third-party-apps-xcxwbn/ ; https://alternativeto.net/news/2026/2/anthropic-officially-bans-using-subscription-authentication-for-third-party-claude-use
- 2026-03 (about 2026-03-19): OpenCode merged PR #18186 "Remove anthropic references per legal requests", removing its Claude Pro/Max OAuth plugin. [Reported] https://lilting.ch/en/articles/opencode-anthropic-legal-astral-openai-codex ; the GitHub API answer was refused in this session, so the PR itself was not opened.
- 2026-04-04 12:00 PT: per Anthropic's email, "subscription limits can no longer be used with third-party harnesses including OpenClaw"; such use moved to extra usage or an API key, with a one-time credit equal to one month's subscription redeemable by 2026-04-17 and discounted usage bundles; Boris Cherny said subscriptions were not built for those usage patterns. [Reported] https://news.ycombinator.com/item?id=47633396 ; https://x.com/BSCNews/status/2040778984179548273 ; https://thenextweb.com/news/anthropic-openclaw-claude-subscription-ban-cost
- 2026-05-13: Anthropic announced that from June 15 Agent SDK, `claude -p`, Claude Code GitHub Actions and third-party Agent SDK apps would draw from a separate monthly credit ($20 Pro, $100 Max 5x, $200 Max 20x) instead of subscription limits. [Reported] https://thenewstack.io/anthropic-agent-sdk-credits/ ; https://www.infoworld.com/article/4171274/anthropic-puts-claude-agents-on-a-meter-across-its-subscriptions.html
- 2026-06-15: "We've paused the previously-announced changes to Claude Agent SDK usage. For now, nothing has changed: Claude Agent SDK, claude -p, and third-party app usage still draw from your subscription limits." 2026-10-07: "Claude Max and Team plans now include monthly API credits, which cover the Claude Agent SDK, claude -p, the Claude API, and Claude Managed Agents. You can still use the Claude Agent SDK, claude -p, and third-party apps with your subscription limits." [Verified] https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan (sitemap lastmod 2026-10-07)
- Conflict: the October support text allows "third-party apps" on subscription limits, while the legal page still forbids third-party developers routing Free/Pro/Max credentials on behalf of users. Read together, a person running a third-party app on their own login is tolerated (and metered), while a product holding or brokering others' logins is not. [Inferred] from the two Verified pages above
- Several accounts of one person: no clause forbids owning more than one account; the risk lies in the "ordinary, individual usage" assumption and the Usage Policy's ban on multiple accounts used to "circumvent product guardrails". A pool that rotates one person's accounts to escape the five-hour window plausibly reads as circumventing usage limits. [Inferred] from consumer terms Section 2-3, legal page, AUP. Symphony's records show the owner chose this knowingly (/home/user/symphony-template/CLAUDE.md lines 50, 84) and the template forbids holding contributors' credentials (line 41).

### 4. API prices and what an agent run costs

- Current models, per MTok, base input / 5-minute cache write / 1-hour cache write / cache hit / output: Fable 5.1 $10 / $12.50 / $20 / $0.25 / $50; Opus 5.5 $4 / $5 / $8 / $0.20 / $20; Sonnet 5.5 $2 / $2.50 / $4 / $0.10 / $10; Haiku 5.5 (prompts up to 100K) $0.10 / $0.125 / $0.20 / $0.01 / $0.50, and above 100K $0.50 / $0.625 / $1 / $0.05 / $2.50. Legacy Opus 4.5-5 $5/$25; Sonnet 4.5/4.6 $3/$15; Sonnet 5 $2/$10 (introductory price made permanent, the 2026-09-01 rise to $3/$15 cancelled). [Verified] https://platform.claude.com/docs/en/about-claude/pricing.md lines 15-44; https://claude.com/pricing
- Modifiers: Batch API halves prices; US-only inference 1.1x; fast mode for Opus 5.5 at 2x ($8/$40); Claude 4.7-and-later tokenizer produces about 30% more tokens for the same text. Managed Agents: tokens plus $0.08 per session-hour of running time; Anthropic's worked example, a one-hour Opus 5.5 session with 50K input and 15K output, costs $0.58 ($0.428 with caching). [Verified] same pricing page lines 54, 158-218, 415-462
- Cache lifetime: "an hour on a subscription and drops to five minutes once you're drawing on usage credits; on an API key or cloud provider, it's five minutes by default". [Verified] https://code.claude.com/docs/en/costs.md line 370
- Anthropic's own spend benchmark on the API: "the average cost is around $13 per developer per active day and $150-250 per developer per month, with costs remaining below $30 per active day for 90% of users"; agent teams use "approximately 7x more tokens than standard sessions when teammates run in plan mode". [Verified] https://code.claude.com/docs/en/costs.md lines 11, 339
- Typical Action run, worked from list prices: a 40-turn run with 1.6M cache-read tokens, 100K cache-write, 20K fresh input, 25K output costs about $0.70 on Sonnet 5.5 ($0.16 + $0.25 + $0.04 + $0.25), $1.40 on Opus 5.5, $3.10 on Fable 5.1 and $0.04 on Haiku 5.5. [Inferred] from the pricing table above; the token profile is an assumption.
- Measured: coordbench's curse-1 pilot (Sonnet 5.5, CooperBench tasks) reports about 1.26M tokens and $0.42 per pair for one agent, and about 3.3-3.7M tokens and $1.05-1.11 per pair for two-agent arms. [Verified] /home/user/coordbench/bench/cooperbench/results/curse-1-pilot/summary.md lines 1-8. Its price table charges Sonnet 5.5 cache reads at $0.20/MTok (/home/user/coordbench/bench/cooperbench/session/summary.py line 37), while Anthropic lists $0.10, so those dollar figures likely overstate cost. [Inferred]
- Subscription versus API break-even: at Anthropic's $13 per active day average, Max 5x ($100) pays for itself after about 8 active developer-days a month and Max 20x ($200) after about 15, before counting that one Max account's window is shared by every worker. [Inferred] from the costs page and pricing page; Anthropic publishes no absolute allowance to make this exact.

### 5. Remote Control and Claude Code on the web

- Remote Control: connects claude.ai/code or the Claude app to a Claude Code process on the user's machine; "Subscription: available on Pro, Max, Team, and Enterprise plans. API keys are not supported." On Team and Enterprise an Owner must enable it; unavailable on Bedrock, Vertex, Foundry, a non-Anthropic ANTHROPIC_BASE_URL, an apps gateway, or under the HIPAA configuration. [Verified] https://code.claude.com/docs/en/remote-control.md lines 9-38, 446-447
- Mechanics: "makes outbound HTTPS requests only and never opens inbound ports"; registers with the Anthropic API and polls; transcripts are stored on Anthropic servers under the data-usage policy; execution and files stay local. [Verified] same page lines 220-226
- Limits: server mode `--capacity` default 32 concurrent sessions; `--spawn worktree` isolates sessions; one remote session per interactive process; server mode exits after about 10 minutes of network outage; resume works for about four hours after a server stops; interactive sessions disconnect after about 30 minutes without the presence heartbeat; Trusted Devices (beta) needs a sign-in no older than 18 hours. [Verified] same page lines 64-65, 212, 238-243, 338-348
- Fit with Beethoven: hpcworker runs `claude remote-control` inside tmux in an Apptainer image as a Slurm job, with the student's own interactive login, and handles no setup-token, no CLAUDE_CODE_OAUTH_TOKEN and no API key; a pilot job on Wayne State's grid reported plan "max" and registered on 2026-09-29. [Verified] /home/user/hpcworker/README.md lines 22-28, 122-131, 168-186. This is consistent with the authentication page's note that a setup-token cannot establish Remote Control. [Inferred]
- Cloud sessions (Claude Code on the web): "available on Pro, Max, and Team plans, and for Enterprise users with premium seats or Chat + Claude Code seats"; usage "counts toward your plan's usage limits ... and there's no separate charge for the cloud VM"; "cloud sessions share rate limits with all other Claude and Claude Code usage ... Running multiple tasks in parallel consumes more rate limits proportionately"; cloud sessions always use subscription credentials, an ANTHROPIC_API_KEY set in the environment does not override them. [Verified] https://code.claude.com/docs/en/claude-code-on-the-web.md lines 10-13, 431-436; https://code.claude.com/docs/en/authentication.md line 249
- Cloud VM: Ubuntu 24.04 x86_64, 4 vCPUs, 16 GB RAM, 30 GB disk; foreground commands default 2 minutes, up to 10, background up to 30 more minutes; idle VMs pause and may be reclaimed. [Verified] https://code.claude.com/docs/en/cloud-environments.md lines 275, 407-409, Time limits section. Symphony observed 15 GB memory and a two-hour background limit in its own sessions. [Verified] /home/user/symphony-template/CLAUDE.md line 101 (a conflict of detail with the docs)
- Projects (claude.ai/code): one conversation that starts parallel cloud threads; public beta on Pro and Max, "aren't available on Team or Enterprise plans yet"; "The enforced limit is 200 new threads per day across your projects"; a thread at the limit waits and resumes when the window resets. Routines: Pro, Max, Team, Enterprise; belong to one account and are not shared; 100 scheduled runs per hour per account, 30 run-now/API fires per hour per routine, no overage on those caps; runs draw subscription usage. [Verified] https://code.claude.com/docs/en/claude-projects.md lines 10, 45, 412; https://code.claude.com/docs/en/routines.md lines 23, 55, "Usage and limits"

### 6. Comparison: GitHub Copilot and OpenAI Codex

- GitHub Copilot moved from premium requests to usage-based billing on 2026-06-01: "the cost of an interaction depends on two things: the model and the number of tokens consumed", metered in GitHub AI Credits at $0.01 each; legacy annual Pro/Pro+ plans keep premium requests until they end. [Verified] github/docs content/copilot/reference/copilot-billing/request-based-billing-legacy/what-changed-with-billing.md; data/variables/product.yml line 344
- Copilot plans and monthly credits (base + flex = total): Pro $10, 1,000 + 500 = 1,500 ($15); Pro+ $39, 3,900 + 3,100 = 7,000 ($70); Max $100, 10,000 + 10,000 = 20,000 ($200); Business $19/seat 1,900 (promo 3,000); Enterprise $39/seat 3,900 (promo 7,000). Credits reset on the 1st at 00:00 UTC and do not roll over; code completions stay unlimited on paid plans. [Verified] github/docs data/variables/copilot.yml lines 26-49; content/copilot/concepts/billing-and-usage/individuals/billing.md
- Copilot prices Claude at Anthropic's list price: Claude Opus 5.5 $4 input / $0.20 cached / $20 output, Sonnet 5.5 $2 / $0.10 / $10 per MTok. So Copilot Max buys a published $200 of API-rate tokens for $100, where Claude Max publishes only multiples.
