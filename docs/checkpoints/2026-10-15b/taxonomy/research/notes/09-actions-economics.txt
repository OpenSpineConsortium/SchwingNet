# GitHub Actions economics, limits and terms (as of 2026-10-15)

Scope: what GitHub Actions gives a public repository for free, what it costs a private one, the limits that bind an Actions-native agent system such as Symphony, the Actions terms, the security features free on public repositories, and how free CI for open source elsewhere compares. Primary sources: the github/docs repository at commit 12691d2 (committed 2026-10-15T10:31:56-07:00), cloned with history back to 2025-12-01 into /tmp/claude-research/github-docs; github/site-policy at b9578b5 (2026-05-29) in /tmp/claude-research/site-policy; MicrosoftDocs/azure-devops-docs, gitlabhq/gitlabhq (GitLab's docs mirror) and circleci/circleci-docs fetched raw into /tmp/claude-research/ci-docs. Paths below without a host are files in those clones. github.blog, docs.github.com, resources.github.com and vendor sites are blocked from this session; anything from them is from WebSearch summaries and graded Reported.

## Takeaways

- Standard GitHub-hosted runners are "free and unlimited on public repositories", on six machine families: Linux x64 and arm64 and Windows x64 and arm64 at 4 vCPU / 16 GB / 14 GB SSD, macOS Intel 4 vCPU / 14 GB and macOS M1 3 vCPU / 7 GB, plus the 1-vCPU ubuntu-slim container. Public jobs get twice the private machine (private Linux/Windows standard runners are 2 vCPU / 8 GB). Larger runners (including GPU) are never free, even on public repositories.
- The free public compute is bounded by concurrency, not by minutes: 20 concurrent jobs on Free (5 macOS), 40 on Pro, 60 on Team, 500 on Enterprise, per account across all its repositories; a job stops at 6 hours, a run at 35 days. For Symphony the first walls are elsewhere: GITHUB_TOKEN's 1,000 REST requests an hour per repository and the 100-run cap on a `queue: max` concurrency group, both of which Symphony's own workflows hit before minutes matter.
- Private repositories: 2,000 included minutes a month (Free, personal or organization), 3,000 (Pro, Team), 50,000 (Enterprise Cloud); after that, per-minute prices that GitHub cut on 2026-01-01 (Linux 2-core $0.008 to $0.006, Windows $0.016 to $0.010, macOS $0.080 to $0.062; Linux 1-core stays $0.002, Linux arm64 2-core $0.005). Without a payment method, use stops at the quota.
- Self-hosted runners are still free. GitHub announced a $0.002/min "cloud platform" charge on self-hosted runner minutes from 2026-03-01 (docs commit ce33310e, 2025-12-16) and pulled it from the docs the next day (dd812b36, 2025-12-17); no current page mentions it, and secondary sources say it is postponed, not cancelled.
- The Actions terms (effective 2026-04-27) forbid cryptomining, offering Actions or "any elements" of it as a commercial service, disproportionate burden ("don't use Actions as a content delivery network or as part of a serverless application"), and, on GitHub-hosted runners, "any other activity unrelated to the production, testing, deployment, or publication of the software project associated with the repository". Agents that write and test the repository's own code sit inside that; a benchmark that runs other projects' tasks, or a paid product that rides on customers' free minutes, needs a careful reading.
- The free public tier is also where GitHub's governance features are free: rulesets, required checks, code owners, environments with required reviewers and wait timers (which on Free, Pro and Team exist only for public repositories), CodeQL code scanning, secret scanning and push protection, dependency review, and Dependabot (free everywhere). Symphony's enforced gate and its owner-approved release environment depend on this.
- GitHub has narrowed free public use only around abuse and security, never by metering minutes: first-time-contributor approval for fork PRs (2021-04-22, cryptomining), auto-disabled schedules after 60 days of inactivity, held "potentially malicious" runs on public repositories (2026-07-28), approval-gated runs for PRs opened with GITHUB_TOKEN (2026-06-11, rolling out), and a default policy blocking `pull_request_target` in public repositories, enforced 2026-11-02.
- Free open-source CI elsewhere has shrunk: Travis CI ended unlimited OSS builds (2020), GitLab.com moved public projects onto quotas (from 2021; 400 compute minutes a month on Free, 50,000 via its Open Source program), Azure DevOps retired public projects in April 2026 and converts them to private in 2027, citing GitHub, and Cirrus CI stopped running jobs on 2026-06-01. CircleCI still offers OSS up to 400,000 credits a month on Linux/Arm/Docker (Reported). GitHub Actions is now the default free compute for public repositories.

## Findings

### 1. What is free for public repositories and for self-hosted runners

- Actions usage "is **free** for **self-hosted runners** and for **public repositories** that use standard GitHub-hosted runners" [Verified] content/billing/concepts/product-billing/github-actions.md:24; same in data/reusables/actions/actions-billing.md:1.
- "Use of the standard GitHub-hosted runners is free and unlimited on public repositories." [Verified] data/reusables/actions/supported-github-runners.md:3.
- Public-repository standard runners: Linux x64 4 CPU / 16 GB / 14 GB SSD (ubuntu-latest = 24.04, also 22.04, 26.04); Windows x64 4 / 16 / 14 (windows-latest = 2025, also windows-2025-vs2026, 2022); Linux arm64 4 / 16 / 14 (ubuntu-24.04-arm, 22.04-arm, 26.04-arm); Windows arm64 4 / 16 / 14 (windows-11-arm, windows-11-vs2026-arm); macOS Intel 4 / 14 GB / 14 GB (macos-15-intel, macos-26-intel); macOS M1 3 / 7 GB / 14 GB (macos-latest = macos-26, also 14, 15, xcode-27 in preview) [Verified] data/reusables/actions/supported-github-runners.md:18-90.
- Private-repository standard runners are half that on Linux and Windows: 2 CPU / 8 GB / 14 GB, x64 and arm64; macOS identical to public [Verified] supported-github-runners.md:112-186. The public machines were doubled from 2 to 4 vCPU between 2023-12-01 and 2024-01-17 ("Double the power for open source") [Reported] https://github.blog/2024-01-17-github-hosted-runners-double-the-power-for-open-source (search summary).
- ubuntu-slim: 1 vCPU / 5 GB / 14 GB, a container on a shared VM, available on public and private repositories, unprivileged (no Docker-in-Docker), job timeout 15 minutes, $0.002/min on private [Verified] data/reusables/actions/single-cpu-table-row.md; content/actions/reference/runners/github-hosted-runners.md:52-65; data/reusables/billing/actions-standard-runner-prices.md:3.
- Larger runners (more cores, GPU, static IPs) "are always charged for, even when used by public repositories or when you have quota available from your plan"; "Included minutes cannot be used"; available only to organizations on Team or Enterprise Cloud [Verified] github-actions.md:133; content/billing/reference/actions-runner-pricing.md:68-69; data/reusables/actions/larger-runner-permissions.md.
- GPU runners exist only as larger runners: Linux 4-core GPU $0.052/min, Windows 4-core GPU $0.102/min; never free [Verified] actions-runner-pricing.md:59-60.
- Standard runners are also free for GitHub Pages and for Dependabot jobs, in any repository [Verified] github-actions.md:125-129.
- Copilot code review consumes Actions minutes from 2026-06-01 on private repositories; "Public repositories: Minutes remain free" [Verified] github-actions.md:34-41, data/reusables/copilot/code-review/code-review-actions-usage.md:1; date from https://github.blog/changelog/2026-04-27-github-copilot-code-review-will-start-consuming-github-actions-minutes-on-june-1-2026/ [Reported].
- Artifact and cache storage on public repositories: the docs state the free quota table "for private repositories" (github-actions.md:26) and say public usage is free (github-actions.md:24), but no page gives a public-repository storage number. The 10 GB per-repository cache allowance and 7-day eviction apply to every repository; going above 10 GB needs a payment method and an opt-in setting [Verified] content/actions/reference/workflows-and-actions/dependency-caching.md:356-367. Whether a public repository that raises its cache limit is billed above 10 GB is not stated [Inferred gap].
- Artifact and log retention: 90 days by default; public repositories may set 1-90 days, private 1-400 days [Verified] data/reusables/actions/about-artifact-log-retention.md:1,15-16.
- Minute multipliers are gone from the docs: /billing/reference/actions-minute-multipliers now redirects to per-SKU prices, and the dashboard "may show your Actions usage as a dollar amount ("spend")" [Verified] actions-runner-pricing.md:11, github-actions.md:150-151. Several 2026 third-party pages still describe 2x/10x multipliers [Reported] search results, e.g. https://cicdcalculator.com/github-actions; treat those as outdated.
- Self-hosted runners: free on every plan and visibility (github-actions.md:24). The $0.002/min self-hosted "cloud platform" charge was written into the docs on 2025-12-16 for "March 1, 2026" (commit ce33310e; data/variables/actions.yml held `self_hosted_runner_charge_date: 'March 1, 2026'`) and removed on 2025-12-17 (commit dd812b36, "GitHub Actions pricing update", which deleted data/features/actions-cloud-platform-march.yml, data/reusables/actions/self-hosted-price-note.md and data/reusables/billing/actions-price-changes.md) [Verified] git history of the github/docs clone. A grep of the 2026-10-15 tree for "cloud platform charge", "self_hosted_runner_charge" and "platform fee" finds nothing [Verified].
- The withdrawn wording said self-hosted runners would be "Free until your plan quota is empty, then billed for cloud platform use", with no explicit public-repository exemption [Verified] `git show ce33310e:content/billing/concepts/product-billing/github-actions.md`:36. GitHub's announcement and press coverage said standard and self-hosted use on public repositories "will remain free" and "96 percent of customers will see no change" [Reported] https://github.blog/changelog/2025-12-16-coming-soon-simpler-pricing-and-a-better-experience-for-github-actions/, https://www.devclass.com/development/2025/12/17/github-to-charge-for-self-hosted-runners-from-march-2026/1734518. Sources conflict on the scope; the docs never shipped either way.
- Postponement wording, 2025-12-17: "We're postponing the announced billing change for self-hosted GitHub Actions to take time to re-evaluate our approach"; the hosted-runner cut of up to 39% went ahead [Reported] https://www.theregister.com/2025/12/17/github_charge_dev_own_hardware/, https://gihyo.jp/article/2025/12/github-actions-pricing-structure-updates. As of October 2026 no new date is announced [Reported] https://www.tenki.cloud/blog/github-actions-runner-pricing-2026, https://socket.dev/blog/github-actions-pricing-whiplash.

### 2. Private repositories: included usage and prices after 2026-01-01

- Included per month: Free (personal) 500 MB artifact storage / 2,000 minutes / 10 GB cache per repository; Pro 1 GB / 3,000 / 10 GB; Free for organizations 500 MB / 2,000 / 10 GB; Team 2 GB / 3,000 / 10 GB / 75 GB custom-image storage; Enterprise Cloud 50 GB / 50,000 / 10 GB / 150 GB [Verified] data/reusables/billing/actions-included-quotas.md:3-7. Docs conflict: Pro's shared Actions/Packages storage is 1 GB there but Packages storage for Pro is 2 GB in content/billing/reference/product-usage-included.md:60-67, while github-actions.md:50,134 says the two share one pool [Verified conflict].
- Minutes reset monthly and are "charged to the repository owner, not the person who triggered the workflow runs"; anyone with write access can run them [Verified] github-actions.md:28-32. For reusable workflows "billing is always associated with the caller workflow" [Verified] content/actions/concepts/billing-and-usage.md:53. A central runtime that each adopted repository calls (Symphony's planned design) therefore spends each adopter's own minutes, free when the adopter is public [Inferred].
- Standard-runner prices from 2026-01-01: Linux 1-core x64 $0.002, Linux 2-core x64 $0.006, Linux 2-core arm64 $0.005, Windows 2-core x64 $0.010, Windows 2-core arm64 $0.010, macOS 3/4-core $0.062 per minute; jobs round up to whole minutes [Verified] data/reusables/billing/actions-standard-runner-prices.md:3-8; actions-runner-pricing.md:14. Before 2026-01-01: $0.002 / $0.008 / $0.016 / $0.080 (-0%, -25%, -38%, -23%) [Verified] `git show 260144b4` (docs commit "Phase 2: Update relevant content for 1 Jan price change", 2026-01-05). arm64 standard prices were added 2026-02-12 (commit 6d1eb11b) [Verified].
- Larger-runner prices: x64 Linux 4-core $0.012 up to 96-core $0.252; Windows 4-core $0.022 up to 96-core $0.552; macOS 12-core $0.077; arm64 Linux 2-core $0.005 up to 64-core $0.098; Windows arm64 2-core $0.008 up to 64-core $0.194; macOS 5-core M2 Pro $0.102 [Verified] actions-runner-pricing.md:22-53.
- Storage over quota: shared artifacts/Packages $0.25 per GB-month; Actions cache $0.07 per GB-month; custom images $0.07; accrued hourly in GB-hours; deleting artifacts does not reduce what already accrued [Verified] github-actions.md:45-74,167-171.
- No payment method: "usage is blocked once you use up your quota"; larger runners are blocked until a payment method exists. Budgets can stop usage; a cache over budget becomes read-only [Verified] github-actions.md:139; data/reusables/billing/default-over-quota-behavior.md; dependency-caching.md:374.
- Worked example in the docs: 3,000 Linux + 2,000 Windows minutes over quota on Team = $18 + $20 = $38 [Verified] github-actions.md:175-179.

### 3. Limits that bind an Actions-native agent system

- Job concurrency, standard hosted runners, per account: Free 20 total / 5 macOS; Pro 40 / 5; Team 60 / 5; Enterprise 500 / 50; larger runners Team or Enterprise 1,000 / 5 or 50 macOS / 100 GPU; Support can raise them [Verified] content/actions/reference/limits.md:64-71. These apply to public repositories too (the table is by plan, not visibility) [Inferred].
- Job execution time: 6 hours on GitHub-hosted runners, 5 days on self-hosted; self-hosted queue time 24 hours; workflow run time 35 days including waits and approvals; environment approval wait up to 30 days; wait timers 1 to 43,200 minutes and not billed [Verified] limits.md:29-30,42-45; content/actions/reference/workflows-and-actions/deployments-and-environments.md:44.
- Matrix: 256 jobs per run; re-runs: 50 per run; workflow file: 500 KB; check runs: 50,000 per suite [Verified] limits.md:31-34.
- Queuing: 1,500 triggering events per 10 seconds per repository; 500 workflow runs queued per 10 seconds; with `queue: max`, up to 100 runs or jobs may wait per concurrency group, the rest are cancelled; default is one pending run per group; `queue: max` cannot be combined with `cancel-in-progress: true` [Verified] limits.md:35-38; data/reusables/actions/actions-group-concurrency.md:107,126; data/features/actions-nga.yml. Symphony's board workflow uses `queue: max` (symphony-template/.github/workflows/board.yml:97) and coordbench's bench uses it per account slot (coordbench/.github/workflows/bench.yml:246) [Verified local].
- Cache: 10 GB per repository by default (raisable, user-owned repositories up to 10 TB), entries unused for 7 days evicted, 200 uploads / 1,500 downloads / 400 deletes per minute per repository [Verified] dependency-caching.md:356-367; limits.md:52-54.
- REST rate limits: GITHUB_TOKEN 1,000 requests per hour per repository (15,000 for Enterprise Cloud resources); GitHub App installation tokens 5,000/h minimum, plus 50/h per repository above 20 and per user above 20, capped at 12,500/h (15,000 on Enterprise Cloud); personal tokens and user-to-server tokens 5,000/h per user; unauthenticated 60/h per IP [Verified] data/reusables/rest-api/primary-rate-limit-*.md; limits.md:94-100.
- Secondary limits: 100 concurrent requests; 900 points/min per REST endpoint (GET 1, POST/PATCH/PUT/DELETE 5); 2,000 points/min GraphQL; 90 s CPU per 60 s; about 80 content-creating requests per minute and 500 per hour, web UI included; 2,000 OAuth token requests per hour per App; "subject to change without notice" [Verified] data/reusables/rest-api/secondary-rate-limit-rest-graphql.md:5-25.
- GITHUB_TOKEN events start no workflow, except `workflow_dispatch` and `repository_dispatch`, which always do; and, behind the flag actions-github-token-pull-request-approval ("currently rolling out on dotcom"), PRs opened or updated with GITHUB_TOKEN now create `pull_request` runs (opened, synchronize, reopened) in an approval-required state that a writer starts with "Approve workflows to run"; labeled, edited and closed still start nothing [Verified] data/reusables/actions/actions-do-not-trigger-workflows.md:1-6; data/features/actions-github-token-pull-request-approval.yml. Announced 2026-06-11, "Bot-created pull requests can run workflows if approved" [Reported] https://github.blog/changelog/2026-06-11-bot-created-pull-requests-can-run-workflows-if-approved/. Symphony already routes around the rule by dispatching ci.yml itself (symphony-template/.github/workflows/protocol.yml:18-22, 211-213) [Verified local].
- GITHUB_TOKEN expires when the job finishes or after at most 24 hours [Verified] data/reusables/actions/github-token-expiration.md:1. Commits pushed with it trigger no Pages build [Verified] data/reusables/actions/actions-do-not-trigger-pages-rebuilds.md.
- Schedules: shortest interval 5 minutes; run from the latest default-branch commit; may be delayed at high load, "High load times include the start of every hour", and "some queued jobs may be dropped"; disabled by default in forks; disabled automatically in a public repository after 60 days without activity; optional IANA time zones [Verified] data/reusables/repositories/actions-scheduled-workflow-example.md:1; data/reusables/actions/schedule-delay.md:1; data/reusables/actions/scheduled-workflows-disabled.md:1. Symphony's crons sit on off minutes (17, 29, 43) and are fallbacks only (symphony-template/.github/workflows/board.yml:82, coordinator.yml:49, metrics.yml:72, protocol.yml:45, workers.yml:57) [Verified local].
- Secrets: 1,000 organization, 100 repository, 100 environment secrets; 48 KB each [Verified] content/actions/reference/security/secrets.md:29-37.
- Docker Hub's rate limit is not applied to GitHub-hosted runners pulling public images, but is for private images and on self-hosted runners [Verified] limits.md:103-107.

### 4. The Actions terms

- GitHub Terms for Additional Products and Features, "Version Effective Date: April 27, 2026" [Verified] site-policy Policies/github-terms/github-terms-for-additional-products-and-features.md:16. The GitHub Terms of Service carry the same effective date [Verified] Policies/github-terms/github-terms-of-service.md:45.
- Actions section, verbatim: Actions "may not be used in violation of the Agreement, the GitHub Acceptable Use Policies, or the GitHub Actions service limitations set forth in the Actions documentation. Additionally, regardless of whether an Action is using self-hosted runners, Actions should not be used for: Cryptomining; Disrupting, gaining, or attempting to gain unauthorized access to, any service, device, data, account, or network (other than those authorized by the GitHub Bug Bounty program); The provision of a stand-alone or integrated application or service offering the Actions product or service, or any elements of the Actions product or service, for commercial purposes; Any activity that places a burden on our servers, where that burden is disproportionate to the benefits provided to users (for example, don't use Actions as a content delivery network or as part of a serverless application, but a low benefit Action could be ok if it's also low burden); or If using GitHub-hosted runners, any other activity unrelated to the production, testing, deployment, or publication of the software project associated with the repository where GitHub Actions are used." [Verified] github-terms-for-additional-products-and-features.md:31-36.
- Enforcement: "GitHub may monitor your use of GitHub Actions. Misuse of GitHub Actions may result in termination of jobs, restrictions in your ability to use GitHub Actions, disabling of repositories created to run Actions in a way that violates these Terms, or in some cases, suspension or termination of your GitHub account." [Verified] same file:38.
- "_Use for Development and Testing_: You may only access and use GitHub Actions to develop and test your application(s). Only one licensed user may access a virtual machine provided by Actions at any time." [Verified] same file:40-42. Note the tension with the bullet above, which also allows deployment and publication [Inferred].
- Competitive benchmarking: anyone offering a competing product who uses a GitHub product waives restrictions on GitHub benchmarking them [Verified] same file:93-95.
- Acceptable Use Policies section 4 forbids "automated excessive bulk activity and coordinated inauthentic activity, such as spamming, cryptocurrency mining" and "using our servers for any form of excessive automated bulk activity, to place undue burden on our servers through automated means"; section 6: "You will not reproduce, duplicate, copy, sell, resell or exploit any portion of the Service ... without our express written permission"; section 9 lets GitHub throttle or suspend for "significantly excessive" bandwidth [Verified] Policies/acceptable-use-policies/github-acceptable-use-policies.md:56-69,80-82,103-105.
- API terms: "Abuse or excessively frequent requests to GitHub via the API may result in the temporary or permanent suspension of your Account's access to the API" and "You may not share API tokens to exceed GitHub's rate limitations." [Verified] github-terms-of-service.md:217-223.
- Accounts: one free personal account per person plus at most one free machine account, which a human owns and is responsible for [Verified] github-terms-of-service.md:84-86.

### 5. Security and governance features free on public repositories

- "All public repositories have access to code scanning, secret scanning, and dependency review", free; making the repository private without a license turns them off [Verified] content/billing/concepts/product-billing/github-advanced-security.md:36,55.
- Feature table, public repository without a license: code scanning yes, CodeQL CLI yes, Copilot Autofix yes, secret scanning yes, push protection yes; custom patterns, delegated bypass, AI-detected secrets, security campaigns, security overview no [Verified] content/get-started/learning-about-github/about-github-advanced-security.md:55-92. The same table marks dependency review "No" for public repositories (line 66), contradicting the billing page (line 55) and data/reusables/gated-features/dependency-review.md, which list public repositories; content/code-security/concepts/supply-chain-security/dependency-review.md:50 says the action "is available for all public repositories" [Verified conflict; the weight of pages says free].
- Push protection for users is on by default for public repositories; secret scanning "runs automatically for free" on public repositories [Verified] data/reusables/gated-features/push-protection-for-users.md, secret-scanning.md.
- Dependabot alerts, security updates and version updates are available on all repositories [Verified] data/reusables/gated-features/dependabot-alerts.md, dependabot-security-updates.md, dependabot-version-updates.md.
- New AI features cost even on public repositories: AI Scan and agentic autofix "consume Code Security AI Credits even when the repository is public" [Verified] github-advanced-security.md:69.
- Governance gated by visibility: rulesets, protected branches and code owners are free on public repositories on GitHub Free and Free for organizations, and need Pro, Team or Enterprise Cloud for private ones; environments and environment secrets are free on public repositories; on Free, Pro and Team, required reviewers, wait timers and custom deployment protection rules "are only available for public repositories" [Verified] data/reusables/gated-features/repo-rules.md, protected-branches.md, code-owners.md, environments.md; deployments-and-environments.md:35,46,97. Symphony's release gate (the release environment whose required reviewer is the owner) and coordbench's bench environment rely on this [Verified local] symphony-template/CLAUDE.md durable decisions; coordbench/.github/workflows/bench.yml:15-19.
- Workflow execution protections (who and which events may trigger workflows) are available on "All public repositories, and private repositories on Team or Enterprise" [Verified] content/actions/how-tos/administer/control-workflow-execution.md:13.
- A local summary of the same plan ladder, read from github/docs on 2026-10-13, agrees row for row with the above [Verified local] symphony-template/docs/setup/free-or-paid.md:24-58.

### 6. Whether GitHub has narrowed free public use, and free CI elsewhere

- Actions went GA on 2019-11-11 "free for all public repositories" [Reported] https://github.blog/changelog/2019-11-11-github-actions-is-generally-available/ (search summary; the planned date was 2019-11-13).
- 2021-04-22, after cryptomining abuse: fork PRs from first-time contributors need a writer's approval before workflows run, and enforcement for abuse falls on the fork's account [Reported] https://github.blog/2021-04-22-github-actions-update-helping-maintainers-combat-bad-actors/; current docs: "By default, all first-time contributors require approval to run workflows", and `pull_request_target` runs regardless [Verified] data/reusables/actions/workflow-run-approve-public-fork.md:3-10.
- 2026-07-28: Actions "holds certain workflow runs for approval" in public repositories when it judges them potentially malicious (compromised credentials pushing workflows that steal secrets); approval must come from a writer in an authenticated web session; signals undisclosed [Reported] https://github.blog/changelog/2026-07-28-github-actions-holds-potentially-malicious-workflows-for-approval, https://techrepublic.com/article/news-github-actions-workflow-hold/.
- Default policy blocking `pull_request_target` in public repositories without their own event policy, now in evaluate mode, enforced 2026-11-02 for repositories on the default policy before GA [Verified] content/actions/reference/security/securely-using-pull_request_target.md:56-73; data/reusables/actions/workflows/pull-request-target-policy.md. None of the 43 workflow files in the 12 OpenSpineConsortium clones that have workflows uses `pull_request_target` [Verified local] grep of each repository's .github/workflows.
- No source found of GitHub metering or throttling standard-runner minutes on public repositories; every narrowing above is a security or abuse control [Inferred from the above and a search: https://github.com/orgs/community/discussions/70492].
- GitLab.com: Free namespaces get 400 compute minutes a month; small Linux runner cost factor 1, up to 12 for 2xlarge and macOS M2 Pro; public projects in the GitLab for Open Source program cost factor 0.5, their public forks 0.008; the program gives Ultimate plus 50,000 compute minutes a month, OSI licenses on every project, renewed yearly [Verified] gitlabhq/gitlabhq doc/ci/pipelines/compute_minutes.md:43,94-119; doc/subscriptions/community_programs.md. Public projects began consuming minutes for new namespaces on 2021-07-17 after cryptomining abuse, with a card requirement from May 2021 [Reported] https://about.gitlab.com/blog/prevent-crypto-mining-abuse, https://about.gitlab.com/blog/public-project-minute-limits/.
- Azure Pipelines: public projects "are retired, and new public projects can no longer be created"; in 2027 they convert to private and drop from "unlimited Microsoft-hosted pipeline minutes" to 1,800 free minutes a month (one job, 60 minutes each); Microsoft gives the reason as "consolidating on GitHub for public, open-source collaboration", announced April 2026 [Verified] MicrosoftDocs/azure-devops-docs docs/organizations/projects/public-projects-retirement.md (ms.date 2026-04-30); docs/pipelines/licensing/concurrent-jobs.md:25,49-53,159 (ms.date 2026-06-19). The free grant for new organizations had required a request form since 2021 [Reported] search summary of learn.microsoft.com.
- CircleCI: open-source projects "up to 400,000 credits per month" (about 80,000 build minutes) on Linux, Arm and Docker; Windows, macOS and private use the Free plan's 30,000 credits [Reported] https://circleci.com/pricing/ via search; CircleCI's own docs defer the numbers to that page [Verified] circleci/circleci-docs docs/guides/modules/plans-pricing/pages/plan-overview.adoc:33-44.
- Bitbucket Pipelines: Free plan 50 build minutes a month, up to 5 users; no confirmed open-source exemption [Reported] aggregator pages, e.g. https://agentdeals.dev/vendor/bitbucket-pipelines.
- Buildkite: free Personal plan (about 3 concurrent jobs, 1 user, 90-day retention); hosted-agent minutes and an OSS exemption unconfirmed, sources disagree [Reported] https://toolradar.com/tools/buildkite/pricing, https://agentdeals.dev/vendor/buildkite.

## Claims worth verifying

- "Standard runners are free and unlimited on public repositories" is the docs' wording, but the Actions terms let GitHub act on "disproportionate" burden and on use "unrelated to the production, testing, deployment, or publication of the software project associated with the repository". Check whether agent workers that run for 90 minutes a time, many times a day, in one repository are inside that line; check whether coordbench's benchmark runs of other projects' tasks count as testing coordbench itself.
- Whether the paid SymphonyBoard App, whose open runtime runs in each customer's own (possibly free, public) Actions, could be read as "the provision of a stand-alone or integrated application or service offering ... any elements of the Actions product or service, for commercial purposes". Marketplace Apps and Actions sell on the same substrate, which argues no; get a reading.
- The self-hosted charge: confirmed absent from the docs at 2026-10-15, but "postponed" not "cancelled"; any 2026 changelog after December 2025 that sets a new date, and whether public repositories would be exempt (the withdrawn docs text did not say so).
- Whether public repositories are ever billed for artifact storage or for cache above 10 GB once the limit is raised; the docs give only private-repository quotas.
- The concurrency table (20 jobs on Free) applies across an account's public repositories too; this caps how many Claude workers in Actions one free account can run at once. Confirm with a run, since the table does not say "including public".
- The GITHUB_TOKEN pull-request approval behavior is "currently rolling out": whether Symphony's sync and protocol PRs now show an "Approve workflows to run" banner, and whether its explicit ci.yml dispatch still yields the required check on the head.
- Whether the 2026-07-28 "potentially malicious workflow" hold has fired on any Symphony repository, given that Claude workers push branches and the template's workflows change by pull request.
- CircleCI's 400,000-credit OSS figure, Bitbucket's 50 minutes and Buildkite's free tier come only from search summaries; verify on the vendors' pricing pages.
