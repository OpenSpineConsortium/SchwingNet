## Takeaways

- The engine is three private, proprietary repositories with one direction of dependence, qa <- agents <- research; it is described by its owner as "an autonomous prompt-to-paper research engine" that turns "a research prompt into a verified, reproducible, archived result" (beethoven hub state/claude_context.md:12; BUILD_PLAN.md:45; beethoven-agents/CLAUDE.md:11). Of that, only the code-quality layer is substantially built.
- beethoven-qa is the most built: release 5.0.0 in its manifests (only v3.0.0 tagged), about 8,071 lines of Python, 233 test functions (274 tests with parameters), a CrossHair+Z3 gate, six code-standard groups emitting SARIF, an interface/boundary checker, a pinned-copy vendoring command, an evidence report, and a Claude Code plugin (5 skills, 1 agent, 3 workflow scripts, 1 PostToolUse hook). Its unique stance: every blocking verdict comes from a tool, never a model; "humans review the contracts, not the lines".
- The "symbolic proof" is mostly a bounded search: on 5.0.0's own tree, 13 of 165 conditions were confirmed over all paths and 152 were "not confirmed within 20 s" (56 targets, 14 min 3 s on 4 cores; 26 min for the lane on GitHub's private 2-core runner). Honest positioning must say "bounded symbolic search with some proofs", not "formally verified".
- beethoven-agents has built the hermetic Apptainer recipe (CI-built once, never on the grid), Claude Code managed settings, a 522-line PreToolUse guard whose non-blocking property is checked by CrossHair, and `bee`, a multi-account switcher that never touches a credential. Metaflow with metaflow-slurm, the super-master lease, the registry, the bus and the reaper are not built (pixi.toml has no Metaflow; "land here").
- beethoven-research holds one 135-line module, splits.py (the split-level disjointness check REFORMS asks of the first study), with 15 test functions. The REFORMS result-row rule, the reproduce-every-number command, the CLAIM record, the study code and publication are "not built yet". One REFORMS concern (leakage across partitions; REFORMS item 6b, CLAIM 2020 item 21) is enforced in code today.
- None of the three repositories references Symphony, symphony-protocol or sdlc (grep: zero hits). The only written integration is on Symphony's side: a "Phase 11" rule that "No Beethoven repository runs Symphony's code or holds a Claude token", an optional Markdown-only pilot of the claim protocol in beethoven-qa (owner question 14, recommended yes after Phase 3), and Symphony's planned generic qa gate keeping beethoven-qa as the Python design-by-contract lane ("not built yet").
- A hard incompatibility blocks Symphony's Claude-in-Actions parts from Beethoven: Symphony's workers, @claude and coordinator run on CLAUDE_CODE_OAUTH_TOKEN from `claude setup-token`; Beethoven's non-negotiables forbid setup-token, CLAUDE_CODE_OAUTH_TOKEN and any "CI that runs Claude Code on a stored key or token". What can be shared is the Claude-free core: the branch-name claim lock, the board, the protocol check, the push guard, required checks and auto-merge.
- The grant packet (AIDaS Seed 2027, $18,057, due 2026-10-16) describes the stack as "a Claude Code worker under the laboratory's claim protocol (one issue, one branch, one pull request ...)" launched by "the Beethoven extension, which starts Claude Code as a Slurm job in the trainee's own account", under "gates registered before any job runs"; it names neither beethoven-qa, REFORMS, CLAIM, CrossHair nor Symphony.
- Free Actions minutes do not help the engine today, because its repositories are private: GitHub-hosted standard runners are "free and unlimited on public repositories" (4 vCPU, 16 GB), while private ones draw on 2,000 to 50,000 included minutes on 2 vCPU, 8 GB runners at $0.006 a minute. beethoven-qa's gate job alone took 28 min 45 s on a private runner; making the engine public would make it free and, since the gate runs one CrossHair process per core, roughly halve its symbolic lane (Inferred).
- The need is real and measurable: in a 2025 umbrella review, median CLAIM compliance was 68% at study level (421 studies) and about a third of items went unreported; only 5 of 98 imaging journals encouraged AI-specific reporting guidelines and 3 required a checklist (2024). REFORMS (32 items, 8 modules) is a consensus checklist with no journal mandate found. Turning such checklists into executable pre-submission gates is the engine's most distinctive research claim, and is almost entirely unbuilt.

### 5. REFORMS and CLAIM: what they require and how widely they are enforced

- REFORMS: Kapoor et al., "REFORMS: Consensus-based Recommendations for Machine-learning-based Science", Science Advances 10(18):eadk3452, May 2024 (PMID 38691601); 32 questions with guidelines, from a consensus of 19 researchers; preprint arXiv 2308.07832 (August 2023) [Reported] search results: EQUATOR listing https://www.equator-network.org/reporting-guidelines/reforms-consensus-based-recommendations-for-machine-learning-based-science/, PMC https://pmc.ncbi.nlm.nih.gov/articles/PMC11092361, https://reforms.cs.princeton.edu/ (unreachable from here, DNS).
- REFORMS structure: 8 modules: 1 study goals, 2 computational reproducibility, 3 data quality, 4 data preprocessing, 5 modeling, 6 data leakage, 7 metrics and uncertainty quantification, 8 generalizability and limitations; authors report the section or page for each item and apply judgment on relevance [Reported] search summary of arXiv 2308.07832 and the project site.
- REFORMS item 6b (draft wording): "Methods to address dependencies or duplicates between the training and test datasets (e.g. different samples from the same patients are kept in the same dataset partition)" - the item splits.py enforces [Reported] search summary of https://reforms.cs.princeton.edu/draft-paper.pdf; final lettering not confirmed.
- REFORMS adoption: no journal found that requires it; the authors propose journals could require it with submissions and note similar checklists exist mostly per discipline [Reported] searches 2026-10-15 (science.org listing, arXiv). Absence of evidence, not evidence of absence.
- CLAIM 2024 Update: Tejani, Klontzas, Gatti, Mongan, Moy, Park, Kahn, Radiology: Artificial Intelligence 6(4):e240300, published online 2024-05-29 (PMID 38809149); 72-member Delphi panel; 44 items; each item now Yes / No / Not Applicable with page and line encouraged [Reported] search results incl. https://pubs.rsna.org/doi/10.1148/ryai.240300 and https://pubs.rsna.org/page/ai/claim (RSNA unreachable from here, DNS).
- CLAIM 2020: Mongan, Moy, Kahn, 42 items, modelled on STARD [Reported] search results (doi 10.1148/ryai.2020200029; DIR editorial citing "all 42").

### GitHub Actions nativeness and free minutes, as they bear on the engine

- All three engine repositories are private and proprietary [Verified] GitHub API private=true; README.md:16-18 of each.
- GitHub: Actions "usage is free for self-hosted runners and for public repositories that use standard GitHub-hosted runners"; private repositories get 2,000 (Free), 3,000 (Pro, Team) or 50,000 (Enterprise Cloud) minutes a month; Linux 2-core $0.006 and 1-core slim $0.002 a minute; each job rounded up to a whole minute; with no payment method usage is blocked at the quota [Verified] github/docs content/billing/concepts/product-billing/github-actions.md:24-28, 119-141; data/reusables/billing/actions-included-quotas.md; actions-standard-runner-prices.md; content/billing/reference/actions-runner-pricing.md:14.
- Runner size differs by visibility: public repositories' ubuntu-latest is 4 CPU, 16 GB, "free and unlimited"; private repositories' Linux runner is 2 CPU, 8 GB; a GitHub-hosted job may run 6 hours [Verified] github/docs data/reusables/actions/supported-github-runners.md:1-30, 96-104; content/actions/reference/limits.md:45.
- The engine's CI shape: beethoven-qa runs jobs gate (60 min limit), plugin (15), report (60) and six standards jobs plus scorecard; beethoven-agents runs gate (30) and image (45, an Apptainer build); all on ubuntu-latest; the plugin job installs Claude Code 2.1.289 only to run `claude plugin validate` with an empty HOME and no credential [Verified] .github/workflows/ci.yml of qa (lines 24, 30-139) and agents (22-70); standards.yml:38-117.
- Cost: Symphony's design estimates beethoven-qa at 58 or more billed minutes per push (gate 28 min 45 s plus report about 29 min, six standards jobs never timed) against 6-12 for the generic gate, "under 50" pushes a month on Team's 3,000 minutes; the organization is on an enterprise (Enterprise Cloud, 50,000 minutes) [Verified as a document] DESIGN-qa-gate.md:19, 34. At $0.006 a minute, 58 minutes is about $0.35 a push beyond the quota [Inferred].
- Why public would help twice: free minutes, and the gate sizes CrossHair to the cores (`os.sched_getaffinity`), so a 4-core public runner should run the symbolic lane about as fast as the 4-core cloud session (14 min) rather than the 26 min seen on the 2-core private runner [Inferred from CLAUDE.md:72, 400-404 and the runner table].
- What GitHub offers only on public or paid plans: code scanning and Scorecard action are free on public repositories; private ones need GitHub Code Security/Advanced Security, "not bought" here [Verified] beethoven-qa/docs/STANDARDS.md:127-129; DESIGN-qa-gate.md:30, 36.
- Where the engine is not Actions-native: everything that runs Claude Code, a container or the scheduler must run "inside a Slurm job on a compute node", never a laptop or cloud session; GitHub Actions only hosts the deterministic gates [Verified] beethoven-agents/CLAUDE.md:367-368; hub claude_context.md:28.
