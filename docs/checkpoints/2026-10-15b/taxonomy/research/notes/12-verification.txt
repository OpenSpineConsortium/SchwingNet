# Verifying agent-written code and coordination protocols (as of 2026-10-15)

Research worker notes for the Symphony / Beethoven positioning study. Method: the shared WebSearch budget was already exhausted when this worker started (every WebSearch call returned "web search budget is used up"), so every external fact below comes from a primary source fetched directly (raw.githubusercontent.com READMEs and the github/docs repository at commit 12691d2 of 2026-10-15, pypi.org JSON, code.claude.com docs, claude.com blog, shallow clones under /tmp/claude-research/), GitHub's repository search, or the local clones. Grades: Verified = primary source opened; Reported = secondary source (a local note quoting a changelog, a draft comment, another repo's description); Inferred = reasoning from cited facts.

## Takeaways

- The verification ladder is fully populated with free, open tools at every level: property (Hypothesis 6.170.0, MPL-2.0), contracts (icontract 2.7.3, deal 4.24.6, both MIT), symbolic (CrossHair 0.0.111 over z3-solver 5.3.0.0, MIT; Hypothesis can run CrossHair as a backend through hypothesis-crosshair 0.0.31), mutation (mutmut 3.8.0 BSD-3, cosmic-ray 8.7.0), model checking (TLA+ tools MIT, Apalache Apache-2.0, P MIT, Stateright MIT, Kani), interleaving testers (Loom exhaustive, Shuttle randomized) and deterministic simulation (FoundationDB, TigerBeetle VOPR, turmoil, madsim; Antithesis commercial). None of them costs a licence; what costs is compute, which on a public GitHub repository is free on standard 4-vCPU runners.
- What actually gates agent pull requests in 2026 is mostly deterministic scanning plus advisory AI review: GitHub runs CodeQL, secret scanning and an Advisory Database check on code from Copilot's cloud agent and from third-party agents (Claude, Codex) with no GHAS licence; Claude Code Review "never approves or blocks" and its check run never fails; GitHub's AI Scan findings "are advisory" and cannot be used in rulesets. The one AI reviewer that can satisfy a merge rule is Copilot code review, when Copilot approvals are switched on.
- No other public project was found that makes contracts plus symbolic execution the required merge gate for agent-written code, as beethoven-qa does (icontract on every public function, CrossHair + Z3 as a required check, auto-merge, no human gate). The nearest is SpecPylot (FSE Companion '26), which uses an LLM to write icontract contracts and validates them with CrossHair: a generator, not a gate, and it needs an API key.
- No other public project was found that validates a multi-agent coordination protocol by running the implementation's own code exhaustively over interleavings against an oracle written from the spec's text, with a mutation lane proving the checks bite, as symphony-protocol's harness does (93 mutants; 16.7 M states at depth 8 in 2 h 06 min; 19 findings, 18 fixed). The closest 2026 neighbors are small: untyped-ai/untyped (a TLA+ model of an agent harness's tool-call protocol with deliberate bug variants, a vacuity check and recorded-run trace checks; created 2026-10-04) and Specula (coding agents write TLA+ of other people's system code and model-check it; 534 stars, Apache-2.0).
- Both projects measure their own verifiers honestly, which is itself unusual: beethoven-qa reports that only 13 of 165 contract conditions are "confirmed over all paths" at a 20 s bound (the rest are bounded search), and symphony-protocol reports that every counterexample CrossHair found was also found by enumerating Unicode character classes in about 130 ms, and that its first checker caught only 1 of 8 hand-made mutants.
- Price line for GitHub's own gates: free on public repositories (code scanning with CodeQL, CodeQL CLI, Copilot Autofix, secret scanning, push protection, dependency review, standard Actions minutes); on private repositories they are per-active-committer add-ons (Secret Protection, docs example rate $19; Code Security $30 and Code Quality $10 per active committer per month per a local note quoting GitHub's changelogs) plus Actions minutes ($0.006 per minute, Linux 2-core). New AI layers (AI Scan, Copilot code review, Code Quality's AI detections) bill AI credits even on public repositories.
- Agent code is measurably insecure without gates: on SusVibes v1.0 (186 repository-level tasks, ICML 2026), Claude Opus 4.8 in Claude Code passes 83.9% of tasks functionally but only 32.8% both functionally and securely; the best entry on the board (GPT-5.5 in mini-swe-agent) reaches 43.5% secure.
- GitHub-Actions nativeness is what makes the expensive lanes affordable: symphony-protocol's weekly deep lane is a 360-minute job on ubuntu-latest, which for a public repository is a free 4-vCPU, 16 GB runner; the same job on a private repository would bill about $2.16 a run at the 2-core rate, and Beethoven's private gate job (about 29 minutes a run) draws on the paid quota.
- Positioning (inferred): Symphony and Beethoven sit in the "deterministic, required-check" layer of the agent-PR quality stack, under the AI-reviewer layer (CodeRabbit, Copilot review, Claude Code Review) and beside GitHub's scanners, and they verify the coordination protocol itself, which no AI reviewer or SAST tool looks at.

## Findings

### Q1. Tools at each level, and which gate agent code in practice

- Hypothesis 6.170.0 was released 2026-10-15; it is "the property-based testing library for Python" and reports the simplest failing example. [Verified] pypi.org/pypi/hypothesis/json; https://raw.githubusercontent.com/HypothesisWorks/hypothesis/HEAD/README.md
- icontract 2.7.3 (2026-01-29, MIT) gives design-by-contract decorators; it is "directly integrated into CrossHair" and has icontract-hypothesis (1.1.7, last release 2021-07-23) that infers Hypothesis strategies from contracts. [Verified] pypi.org/pypi/icontract/json; https://raw.githubusercontent.com/Parquery/icontract/HEAD/README.rst lines 32-43; pypi.org/pypi/icontract-hypothesis/json
- deal 4.24.6 (2025-11-30, MIT) does contracts, exception and side-effect tracking, property-based tests (`python3 -m deal test`), a static linter and "formal verification"; its Z3 backend deal-solver was last released 0.1.2 on 2023-09-28, so the formal part may be stale. [Verified] pypi.org/pypi/deal/json, pypi.org/pypi/deal-solver/json; https://raw.githubusercontent.com/life4/deal/HEAD/README.md lines 7-28
- CrossHair 0.0.111 (2026-09-28, MIT) "repeatedly call[s] your functions with symbolic inputs" and uses an SMT solver to find counterexamples to contracts; it can also generate unit tests (`cover`) and find behavioural differences (`diffbehavior`); Hypothesis supports it as an optional backend (hypothesis-crosshair 0.0.31, 2026-10-06). [Verified] https://raw.githubusercontent.com/pschanely/CrossHair/HEAD/README.md lines 12-47; pypi.org JSON for crosshair-tool and hypothesis-crosshair
- CrossHair's own limits: "the absence of a counterexample does not guarantee that the property holds"; only deterministic behaviour can be analysed; it "will actually run your code", with audit-hook protections against disk and network access that are "not perfect". [Verified] /tmp/claude-research/CrossHair/doc/source/limitations.rst lines 9-29 (commit 35e504c, 2026-10-02)
- Since CrossHair 0.0.106, `--per_condition_timeout` and `--per_path_timeout` measure process CPU time instead of wall-clock time, to be reproducible on busy CI runners. [Verified] /tmp/claude-research/CrossHair/doc/source/changelog.rst lines 347-362
- Mutation testing for Python: mutmut 3.8.0 (2026-09-12, BSD-3; incremental, knows which tests to run, needs fork(), so WSL on Windows) and cosmic-ray 8.7.0 (2026-08-09). [Verified] pypi.org JSON; https://raw.githubusercontent.com/boxed/mutmut/HEAD/README.rst lines 12-40; https://raw.githubusercontent.com/sixty-north/cosmic-ray/HEAD/README.rst
- Mutation-guided LLM test generation is being reproduced from Meta's ACH (FSE 2025) in small open repositories (testforge, created 2026-09-19). [Reported] GitHub repository search result Luz7818/testforge (description text)
- TLA+ tools: TLC model checker, PlusCal translator and SANY parser ship in tla2tools.jar (Java 11+), managed by the TLA+ Foundation, MIT; every master commit builds the 1.8.0 "Clarke" pre-release. Apalache (Apache-2.0) translates TLA+ to SMT (Z3, CVC5) for bounded model checking and inductive invariants. [Verified] https://raw.githubusercontent.com/tlaplus/tlaplus/HEAD/README.md; .../tlaplus/tlaplus/HEAD/LICENSE; https://raw.githubusercontent.com/apalache-mc/apalache/HEAD/README.md
- P (MIT) models systems as communicating state machines; its README says teams across AWS (S3, EBS, DynamoDB, MemoryDB, Aurora, EC2, IoT) use it, and it now ships PeasyAI, which "integrates with Cursor and Claude Code via MCP" with 27 tools, and PObserve for checking production logs against P monitors. [Verified] https://raw.githubusercontent.com/p-org/P/HEAD/README.md (Impact and What's New sections)
- Interleaving testers: Loom "runs a test many times, permuting the possible concurrent executions ... under the C11 memory model" with state reduction; Shuttle (AWS) is randomized (PCT); Stateright (MIT) is an embedded model checker for Rust actors with a linearizability tester. [Verified] READMEs of tokio-rs/loom, awslabs/shuttle, stateright/stateright on raw.githubusercontent.com
- Deterministic simulation testing: FoundationDB "runs tens of thousands of simulations every night" and estimates "roughly one trillion CPU-hours of simulation"; TigerBeetle's VOPR is deterministic by seed and commit and "one minute of VOPR time is equivalent to days of real-world testing"; turmoil and madsim bring DST to Rust; Antithesis is a commercial "continuous reliability platform" with a Python SDK (assertions, randomness, lifecycle). [Verified] https://raw.githubusercontent.com/apple/foundationdb/HEAD/documentation/sphinx/source/testing.rst; .../tigerbeetle/tigerbeetle/HEAD/docs/internals/vopr.md; .../tokio-rs/turmoil, .../madsim-rs/madsim READMEs; .../antithesishq/antithesis-sdk-python/HEAD/README.md; ivanyu/awesome-deterministic-simulation-testing README lines 41-70
- Kani (bounded model checker for Rust over CBMC) offers a GitHub Action, `model-checking/kani-github-action`, so model checking can be a required CI check. [Verified] https://raw.githubusercontent.com/model-checking/kani/HEAD/README.md lines 46-50
- GitHub's agent gate in practice: when a third-party coding agent (Anthropic Claude, OpenAI Codex, both usable on a Copilot subscription; Claude agent in public preview) writes code, GitHub "automatically scans the generated code", with CodeQL, secret scanning, and new dependencies checked against the Advisory Database for malware and High or Critical CVSS; "Security validation does not require a GitHub Advanced Security license". Copilot's own cloud agent does the same and also gets a second opinion from Copilot code review. [Verified] github/docs content/copilot/concepts/agent-capabilities/about-agents/about-third-party-coding-agents.md lines 50-56, 87-97; content/copilot/concepts/security-governance-and-network-settings/risks-and-mitigations.md lines 20-30; data/reusables/copilot/cloud-agent-validation-tools-intro.md
- Claude Code Review (Team and Enterprise): several agents find, a verification step filters, findings are ranked and posted inline; "A review never approves or blocks the pull request"; its check run "doesn't conclude as a failure"; it reads the diff and surrounding code "without building or running your code"; it follows REVIEW.md from the base branch, never from the pull request. [Verified] https://code.claude.com/docs/en/code-review.md lines 9-11, 77-90, 104-115
- GitHub AI Scan for pull requests (2026): an AI engine for languages CodeQL does not cover (PHP, Shell, Terraform HCL, Dockerfiles, JSP, Blazor); "Findings are advisory. They do not fail the Code scanning check and cannot block pull request merges through ruleset requirements." [Verified] github/docs content/code-security/concepts/code-scanning/ai-powered-security-detections.md lines 23, 34, 58, 73
- Copilot code review can be made a gate: with Copilot approvals enabled at repository, organization and enterprise level, "Copilot can submit an approving review that satisfies your repository's required-approval rule", dismissed when new commits are pushed. [Verified] github/docs content/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review.md line 209
- GitHub Code Quality: deterministic CodeQL rules and Cobertura coverage on pull requests, with "optional merge gating with rulesets" on findings or coverage thresholds; available on Team or Enterprise Cloud. [Verified] github/docs content/code-security/concepts/code-quality/code-quality.md lines 21-46; data/reusables/gated-features/code-quality-availability.md
- Anthropic's own practice (blog dated 2026-07-21): agents run /security-review before opening a pull request; "multiple agents automatically review" each pull request and must "write a proof that their finding is valid"; SAST tools post on pull requests; invariant tests ("user A can never read user B's data"); human approval reserved for regulated or critical codebases, with a risk-weighted sample of automated approvals reviewed; the hard gate is placed "at the test/CI stage", not in a PreToolUse hook; Claude authors about 80% of merged code. [Verified, read through WebFetch's summarizer, so exact figures need a re-read] https://claude.com/blog/how-anthropic-secures-its-ai-native-software-development-lifecycle
- Claude Code's other review layers: `/code-review` runs in the session on any plan; Ultrareview runs a fleet of reviewer agents in a cloud sandbox in 15 to 25 minutes; the security-guidance plugin is hooks (a pattern check per edit with no model call, plus model reviews at turn end and commit) and "None of the layers block writes or commits"; the Claude Security plugin runs a multi-agent scan locally. [Verified] code.claude.com/docs/en/code-review-local.md lines 5-11; ultrareview.md lines 13-19, 136; security-guidance.md lines 73, 114, 174-180; claude-security.md lines 9-19
- anthropics/claude-code-security-review (a GitHub Action) needs a `claude-api-key` input and "is not hardened against prompt injection attacks and should only be used to review trusted PRs". [Verified] https://raw.githubusercontent.com/anthropics/claude-code-security-review/HEAD/README.md lines 40-53
- Qodo's PR-Agent is now "a community-maintained legacy project"; Qodo "offers a free version for open-source projects". [Verified] https://raw.githubusercontent.com/qodo-ai/pr-agent/HEAD/README.md lines 27, 45, 228
- Agent pull requests at scale: the AIDev dataset counts 932,791 agent pull requests in 116,211 repositories to 2025-08-01 (OpenAI Codex 814,522; Copilot 50,447; Cursor 32,941; Devin 29,744; Claude Code 5,137). A draft finding left commented out in its README says agentic pull requests got no explicit review in 58.2% of cases (human 75.3%) and bot reviewers on 20.1% (human 10.0%). [Verified for counts; Reported for the commented-out review shares] https://raw.githubusercontent.com/SAILResearch/AI_Teammates_in_SE3/HEAD/README.md lines 45-80, 96-114 (data older than 2026)

### Q2. Contracts plus symbolic execution as a merge gate; protocol validation by interleavings, oracle and mutants

- beethoven-qa's definition of done: every public function carries icontract contracts, pydantic at boundaries, beartype on hot paths, and "CrossHair + Z3 find no input that satisfies the preconditions and violates a postcondition within the declared per-condition bound"; contracted functions are pure, I/O stays in private or listed functions. [Verified] /home/user/beethoven-qa/CLAUDE.md lines 80-100; /home/user/beethoven-qa/README.md lines 51-56
- beethoven-qa is the merge gate itself: the same gate runs as a pre-push hook and as the required check on main, pull requests open ready, automerge.yml arms auto-merge "and the required checks alone decide", with strict up-to-date checks; "no human gate on a merge". [Verified] /home/user/beethoven-qa/CLAUDE.md lines 106-125
- beethoven-qa measured its symbolic step: 107 of 117 conditions "Not confirmed" at 20 s (2026-10-08); 13 of 165 confirmed over all paths, 152 not confirmed, on 56 targets in 14 min 3 s on 4 cores; 26 min for the lane and 28 min 45 s for the gate job on GitHub's runner, against a 30-minute limit raised to 60. "the symbolic step is a bounded search for most conditions and a proof for the rest". [Verified] /home/user/beethoven-qa/CLAUDE.md lines 386-406
- Tool-interaction faults found by beethoven-qa: importing CrossHair turns icontract's own checks off process-wide, and icontract under CrossHair crashed with RecursionError after about 480 contracted calls; fixed by a runner that initialises icontract first. [Verified] /home/user/beethoven-qa/CLAUDE.md lines 419-436
- beethoven-qa's "SpecPylot loop" (code and contracts, gate, counterexample fed back, until proven; humans review contracts, not lines) exists as workflow scripts that had not been run against a real failure as of 2026-10-08. [Verified] /home/user/beethoven-qa/CLAUDE.md line 102; /home/user/beethoven/qa/QA_ASSESSMENT_2026-10-08.md line 176
- SpecPylot (Ayon and Ahmed, FSE Companion '26, doi 10.1145/3803437.3806427) "annotates Python code with icontract contracts, validates them with CrossHair, and optionally refines the contracts", needing an OpenAI or Anthropic API key or a local Ollama. It is the published form of the loop beethoven-qa names, used as a generator, not as a required check. [Verified] https://raw.githubusercontent.com/ragibayon/specpylot/HEAD/README.md lines 1-20, 229-243
- GitHub repository searches for "crosshair icontract LLM verification" and "crosshair symbolic python claude-code" returned 0 repositories on 2026-10-15; no other contracts-plus-symbolic merge gate for agent code was found. [Inferred: absence in a narrow search, not proof of absence] mcp github search_repositories
- symphony-protocol's harness runs the library's own code, never a copy: the board side against a stateful fake of GitHub's REST API plugged in through the adapter's `opener`, the merge gate over MemoryWorld and a real bare-git world; workers are scripts, not Claude; an oracle "written from the text of spec/PROTOCOL.md, importing nothing from the package" computes what each board run must do, and the run's effects must equal it. [Verified] /home/user/symphony-protocol/validation/DESIGN.md lines 12-19
- Lanes and budgets: fast lane inside the required check "check", adding at most 60 s (suite of 661 tests in 35 s at design); mutation lane about 100 s; deep lane weekly, five hours a search under the job's six; CrossHair by hand; monthly canary on live GitHub (OpenSpineConsortium/symphony-protocol-canary). [Verified] DESIGN.md lines 20-25, 765-772; /home/user/symphony-protocol/.github/workflows/validate.yml (mutants job timeout 30 min, deep job timeout 360 min, cron "37 5 * * 1")
- Exhaustive checker with exact reductions: breadth-first (shortest counterexample first), no pruning at a known violation, time reduced by capping every gap between neighbouring instants at 25 h (exact because every clock rule compares gaps against the one 24 h constant), worker-name symmetry. [Verified] DESIGN.md lines 429-458
- Deep run of record (2026-10-14, 4 CPUs): depth 8, 16,706,180 states in 7,563 s; 2 issues depth 7, 18,787,930 states in 9,494 s; 1,000 soak walks of 200 steps; 200 sampled paths replayed in git with 0 disagreements; 699 guard argument lists re-recorded against git 2.43.0 with 0 differing; 0 violations. [Verified] /home/user/symphony-protocol/validation/runs/2026-10-14/README.md lines 1-20; DESIGN.md lines 514-521
- Mutation lane as the harness's acceptance test: the prototype checker caught 1 of 8 hand-made mutants, 4 of 8 with a 24-hour wait added; the lane now holds 93 mutants, each caught on the shortest trace the lane found. [Verified] DESIGN.md lines 540-557; /home/user/symphony-protocol/validation/README.md line 30
- What it found: 19 findings F1-F19 (for example F3, the push guard passed forced pushes in plain shapes such as a `+` refspec or `-fu`; F4, the clerk could deal one issue to two workers; F7, `--force-with-lease` could take another worker's claim); F1, F3, F5, F6, F10, F11 fixed in 0.4.1, the rest fixed after it, F8 (idleness by committer date) left for the owner. [Verified] DESIGN.md lines 9, 29-49
- CrossHair on symphony-protocol, by hand: 2 properties confirmed over all paths, 6 not confirmed at 20 s, 3 counterexamples (`'00'`, `'\u00b2'`, `+\x00`), 1 tool fault in CrossHair's datetime emulation; every counterexample is a short string that enumerating Python's Unicode digit classes finds "in well under a second" (2,403 names in about 130 ms), so the always-on lane enumerates instead and CrossHair stays out of CI. [Verified] DESIGN.md lines 593-670
- untyped-ai/untyped (MIT, created 2026-10-04): a 155-line TLA+ model of "the protocol between an agent harness and a side-effecting tool" on a durable-execution runtime (Temporal, Inngest, Restate, DBOS, LangGraph), with named bug variants that must violate AtMostOnce, ApprovalBeforeEffect or BudgetHeld, a vacuity check, and recorded runs checked against the spec; its sibling repo receipts reports a LangGraph `@task` that can run again on resume (langchain-ai/langgraph#8039). [Verified] https://raw.githubusercontent.com/untyped-ai/untyped/HEAD/README.md lines 1-35; .../untyped-ai/receipts/HEAD/README.md
- Specula (Apache-2.0, arXiv 2607.25333): coding agents (Claude Code, Codex, Copilot CLI, OpenCode, Pi) write TLA+ specs and invariants of a target system, model-check them and reproduce violations at code level; it keeps a public list of bugs found. [Verified] https://raw.githubusercontent.com/specula-org/Specula/HEAD/README.md lines 10-30; GitHub search (534 stars, 2026-10-15)
- The TLA+ Foundation publishes agent skills (tlaplus/AgentSkills: add a variable, split an action, generate a model from source) and an MCP server inside the VS Code extension, with a headless stdio MCP server prototype in tlaplus/tlaplus PR 1296. [Verified] https://raw.githubusercontent.com/tlaplus/AgentSkills/HEAD/README.md
- Difference that matters (inferred from the above): TLA+, P and Specula check a model of a design or an implementation; untyped checks one agent's harness; symphony-protocol model-checks the shipped Python library itself, over git and a GitHub fake, for several workers racing for claims, and proves its own checks bite with mutants. Industrial practice for distributed systems (AWS with P, FoundationDB, TigerBeetle) shows the technique is established; applying it to the coordination layer of coding agents on GitHub appears new.
