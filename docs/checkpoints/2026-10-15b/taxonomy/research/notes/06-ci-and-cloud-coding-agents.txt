## Takeaways

- Two execution models, and GitHub's own agent sits in the first: (a) the agent runs as a job on the code host's CI runner (Copilot cloud agent on `ubuntu-latest` Actions runners, the Claude and Codex agents inside GitHub, gh-aw, claude-code-action, codex-action, run-gemini-cli, Factory droid-action, GitLab Duo flows on GitLab Runner); (b) the agent runs in a vendor VM and only talks to the host through a GitHub App (Codex cloud, Jules, Cursor cloud agents and Bugbot, Devin, Claude Code on the web and routines, OpenHands Cloud, Augment, Kiro). Even the "vendor" agents inside GitHub (Claude, Codex) are billed Actions minutes, so they run on Actions.
- Compute and inference are paid separately everywhere. Actions minutes are free for public repositories on standard GitHub-hosted runners (and for self-hosted runners); inference is never free. Since 2026-06-01 every Copilot plan bills inference in GitHub AI Credits (1 credit = $0.01): Pro $10/mo = 1,500 credits, Pro+ $39 = 7,000, Max $100 = 20,000, Business $19 = 1,900 pooled per seat, Enterprise $39 = 3,900 pooled.
- Copilot cloud agent and the third-party agents consume both Actions minutes and AI Credits. GitHub's docs say explicitly that Copilot code review minutes stay free in public repositories; for the cloud agent they only say it runs on a standard `ubuntu-latest` runner and draws on the "free minutes" allowance. That the cloud agent's minutes cost nothing in a public repository is an inference, not a documented statement.
- Copilot automations (scheduled or event-triggered cloud-agent runs, the Copilot counterpart of a routine) are not available in public repositories at all; they need a private or internal repository and are billed to the user who created them. gh-aw is the GitHub-supported automation path that does run in public repositories, and it is still public preview.
- No one in the field stops two agents from taking the same work. The common rule is one task, one branch, one pull request, with a person doing the assigning: Copilot can "only work on one branch at a time and can open one pull request per task"; claude-code-action makes a new timestamped branch per issue run; Codex and Jules give each task its own container or VM. GitHub's multi-agent feature is that several agents can be started on one issue so their results can be compared. Real coordination happens inside one vendor, with a lead agent splitting the work: Copilot `/fleet` subagents, Copilot dynamic workflows, and Devin's coordinator session over "managed Devins", each in its own VM.
- GitHub's 2026 answer for many agents on one repository has three layers: the Agents tab and Agents page for starting, steering and tracking sessions across Copilot, Claude, Codex and partner "agent apps"; orchestration inside a session (`/fleet`, dynamic workflows); and in gh-aw the OrchestratorOps pattern plus, since early October 2026, a native Git-backed work queue with Claims (v0.90.3, week of 2026-10-05; "Git-backed fair DAG work queues with claim-scoped effects" in v0.91.4-v0.91.8, week of 2026-10-12). This queue is now Symphony's closest neighbor.
- How gh-aw's queue differs from Symphony (Inferred from its reference). It is a transaction log, `work-queue.jsonl` on branch `work-queue`. A trusted dispatcher hands out Claims to Actions worker runs under a Policy, and the agent never chooses its task. It has no idea of a person's local or cloud session as a claimant, and no file-overlap merge ordering. Its Claude engine needs `ANTHROPIC_API_KEY`, WIF or Copilot inference: "`CLAUDE_CODE_OAUTH_TOKEN` is not supported." Symphony runs Claude workers on the subscription token that claude-code-action and Anthropic's docs support, and it puts every kind of worker under one claim rule (first push of `claude/N`).
- Where the state lives follows the execution model. The CI-native tools keep it in the repository: issues, labels, branches and PRs, plus gh-aw's `memory/*` and `work-queue` branches. The vendor-VM tools keep sessions, plans and logs in the vendor's database and post only PRs and comments back. Symphony is fully repository-native (board on branch `board`, claim files, labels).
- Licenses: the CI glue is open (gh-aw MIT, claude-code-action MIT, jules-action MIT, codex-action Apache-2.0, run-gemini-cli Apache-2.0, OpenHands MIT, SWE-agent and mini-swe-agent MIT, Codex CLI and Gemini CLI Apache-2.0, Pi MIT). The agents that do the work are mostly proprietary: Claude Code, Copilot CLI, Amp and Auggie all say "SEE LICENSE IN" on npm. Every vendor-cloud service is closed.
- Hard limits that shape the design. A Copilot cloud agent session stops at 59 minutes and works in one repository, on one branch, with one PR. A GitHub-hosted job stops at 6 hours. Concurrent jobs on standard runners: Free 20, Pro 40, Team 60, Enterprise 500. gh-aw defaults: 20-minute agent step, 60-minute agent job, 1,000 AIC per run, 5,000 AIC per workflow per day. Claude routines: 100 scheduled runs per hour per account, 30 run-now or API fires per hour per routine.

## Findings

### 1. Where the agent executes

- Copilot cloud agent (renamed from "Copilot coding agent") works "in an ephemeral cloud development environment" and by default "runs on a standard GitHub-hosted GitHub Actions runner (`ubuntu-latest`)"; orgs can switch to larger or self-hosted labeled runners and repos override via `runs-on` in `.github/workflows/copilot-setup-steps.yml`. [Verified] content/copilot/concepts/copilot-surfaces/copilot-on-github.md:54; content/copilot/how-tos/administer-copilot/manage-for-organization/configure-runner-for-coding-agent.md:17-24,45.
- The old about-coding-agent and about-cloud-agent URLs now redirect to "GitHub Copilot on GitHub.com"; the rename to "cloud agent" is visible in docs variables (`copilot_cloud_agent: 'Copilot cloud agent'`). [Verified] copilot-on-github.md:8-21; data/variables/copilot.yml:67. A changelog item mentions the rename in passing (used_copilot_cloud_agent metrics field). [Reported] search: github.blog/changelog/month/04-2026/.
- Third-party coding agents on GitHub are Anthropic Claude ("uses the Claude Agent SDK and can be powered by your existing Copilot subscription") and OpenAI Codex ("use the Codex SDK"). Both are public preview, "subject to the same security protections, mitigations, and limitations as Copilot cloud agent", and installed as GitHub Apps named `anthropic code agent` and `openai code agent`. [Verified] content/copilot/concepts/agent-capabilities/about-agents/about-third-party-coding-agents.md:17,23,50-55,64-69,107-110.
- Agent apps: partner-built agents that are GitHub Apps, "powered by Copilot cloud agent", each with its own prompt, model, tools and MCP servers; the partner authenticates the app with a GitHub-issued JWT. [Verified] content/copilot/concepts/agent-capabilities/about-agents/agent-apps.md:18,32-34.
- Copilot cloud sandboxes (public preview) run a whole Copilot CLI or Copilot app session in "a fully isolated, ephemeral Linux environment hosted by GitHub". This is a separate compute product, not Actions: $0.000024 per compute-second, $0.000003 per GiB-second, $0.005 per GiB-month of snapshot storage, with a $10 monthly preview entitlement through the end of July 2026. [Verified] content/copilot/concepts/security-governance-and-network-settings/about-cloud-and-local-sandboxes.md (Introduction); content/billing/concepts/product-billing/cloud-and-local-sandboxes.md:44,54-58.
- gh-aw compiles a Markdown workflow into a `.lock.yml` GitHub Actions workflow. Its agent jobs are "read-only and sandboxed by default" (AWF firewall), and writes go through separate `safe-outputs` jobs. Built-in engines: Copilot (default), Claude Code, Codex, Gemini (deprecated in favour of the experimental Antigravity CLI `agy`) and Pi. [Verified] gh-aw README.md:16-20; docs/src/content/docs/reference/engines.md:3,19-21.
- anthropics/claude-code-action runs Claude Code on the workflow's runner. It is triggered by `@claude` mentions, by assignment, or by an explicit prompt, and authenticates with an Anthropic API key, WIF, Bedrock, Vertex AI or Microsoft Foundry, or `CLAUDE_CODE_OAUTH_TOKEN` ("Pro and Max users can generate this by running `claude setup-token`"). [Verified] claude-code-action README.md:5; docs/setup.md:10; action.yml:70-71.
- Claude Code on the web: each cloud session runs "in an isolated, Anthropic-managed VM" or on an org's self-hosted environment. GitHub credentials stay on Anthropic's servers behind a GitHub proxy. [Verified] cc-claude-code-on-the-web.md:13,58,370. Routines run on the same Anthropic-managed infrastructure and are research preview. [Verified] cc-routines.md:10-14.
- openai/codex-action runs Codex CLI on the Actions runner behind a "secure proxy to the Responses API" and needs an `OPENAI_API_KEY` or Azure key. Codex cloud (Codex web) is a separate hosted product that runs tasks "in its own cloud environment". [Verified for the action] openai_codex-action README:3-5; [Reported for Codex cloud] search: developers.openai.com/codex/cloud.
- Jules: "a remote AI coding agent from Google Labs powered by Gemini 3 Pro" that "works autonomously in a cloud VM". jules-action only calls Jules from GitHub events with a `JULES_API_KEY`. [Verified] google-labs-code/jules-action README:18-20. Third-party sources disagree on the model (Gemini 3 Pro vs 3.1 Pro). [Reported]
- run-gemini-cli runs Gemini CLI on the runner and authenticates with a Gemini API key ("generous free-of-charge quotas"), Vertex AI, Gemini Code Assist or WIF. [Verified] run-gemini-cli README:53,162-186.
- Factory droid-action: "Everything runs inside GitHub Actions using your Factory API key" (`@droid fill/review/security`, CI Steward). [Verified] Factory-AI_droid-action README:3-10.
- Cursor cloud agents: "each Cloud Agent runs in its own isolated cloud VM that Cursor provisions and tears down". Self-hosted "governed" cloud agents also exist. [Reported] search: cursor.com/docs/cloud-agent/self-hosted.md, cursor.com/docs/account/pricing.md.
- Devin: sessions run in Devin-managed VMs with machine snapshots shared across an org. Large tasks can be handed to "a team of managed Devins working in parallel, each running in its own isolated VM", with a coordinator session that "scopes the work, monitors progress, resolves conflicts, and compiles results". [Reported] search: docs.devin.ai.
- OpenHands has repositioned as "The self-hosted developer control center for coding agents and automations" (Agent Canvas). It runs OpenHands, Claude Code, Codex, Gemini, Pi, OpenCode or any ACP agent "across local, remote, and cloud backends", with OpenHands Cloud as the commercial option. CI use now goes through the Software Agent SDK's composite actions (for example `OpenHands/extensions/plugins/pr-review`). [Verified] OpenHands README:7-10,35; OpenHands/docs openhands/usage/essential-guidelines/sdlc-integration.mdx:122-129.
- SWE-agent: the authors recommend mini-swe-agent "instead of SWE-agent going forward". It is a research agent you run yourself (local, Docker, Codespaces), not a hosted service. [Verified] SWE-agent README:20-24,50.
- Sweep has left GitHub issue-to-PR automation: "We're now building an AI coding assistant for JetBrains". [Verified] sweepai/sweep README:1-4.
- GitLab Duo Agent Platform went GA in GitLab 18.8 on 2026-01-15. With "Allow flow execution" on, agents "execute in CI/CD pipelines and consume compute minutes", and custom flows run on GitLab Runner. [Reported] search: about.gitlab.com/releases/2026/01/15/gitlab-18-8-released/, about.gitlab.com/blog/understanding-flows-multi-agent-workflows/.
- Kiro autonomous agent: one of AWS's three "frontier agents" announced at re:Invent in December 2025. It takes work from GitHub or Jira and returns PRs, and is in preview for Kiro Pro, Pro+ and Power. [Reported] search: kiro.dev/blog/introducing-kiro-autonomous-agent/, press.aboutamazon.com 2025-12.
- Augment: cloud agents on managed VMs ("Cosmos") plus the Auggie CLI (npm @augmentcode/auggie 0.36.0, 2026-08-21, proprietary). [Reported for Cosmos; Verified for npm metadata] search: fast.io/resources/augment-ai-review-2026; registry.npmjs.org.
- Amp (Sourcegraph): CLI and agents "everywhere" (web, CLI, mobile, June 2026); npm @sourcegraph/amp shipped a build on 2026-10-15, proprietary licence. [Reported for product; Verified for npm] search: amplifying.ai/coding-agents/amp; registry.npmjs.org.

### 2. Who pays for compute and how (2026 prices)

- Actions: "usage is free for self-hosted runners and for public repositories that use standard GitHub-hosted runners". For private repositories the included minutes per month are Free 2,000, Pro 3,000, Team 3,000 and Enterprise Cloud 50,000, and minutes are "charged to the repository owner, not the person who triggered the workflow runs". Larger runners are always charged, even in public repositories. [Verified] content/billing/concepts/product-billing/github-actions.md:24-28,121-133; data/reusables/billing/actions-included-quotas.md.
- Standard runner rates: Linux 1-core $0.002/min, Linux 2-core x64 $0.006, arm64 $0.005, Windows $0.010, macOS $0.062; Linux 4-core $0.012 up to 96-core $0.252. Minutes round up per job. [Verified] data/reusables/billing/actions-standard-runner-prices.md; content/billing/reference/actions-runner-pricing.md:14.
- The $0.002/min self-hosted runner platform fee announced in December 2025 for 2026-03-01 was postponed, and the hosted-runner price cuts went ahead on 2026-01-01. The docs still say self-hosted runners are free. [Reported, Verified for docs] search: techzine.eu (GitHub delays paid self-hosting of runners); github-actions.md:24.
- Copilot billing changed on 2026-06-01: "replaced request-based billing with usage-based billing", priced per model per token and converted to AI Credits (1 credit = $0.01). Annual Pro and Pro+ plans keep premium requests until they expire. [Verified] content/copilot/reference/copilot-billing/request-based-billing-legacy/what-changed-with-billing.md; data/variables/product.yml:341-344.
- Plan allowances: Pro $10 = 1,000 base + 500 flex = 1,500 credits; Pro+ $39 = 3,900 + 3,100 = 7,000; Max $100 = 10,000 + 10,000 = 20,000; Business $19 = 1,900 per seat; Enterprise $39 = 3,900 per seat, pooled at the billing entity (100 Business seats give a pool of 190,000), with promotional pools of 3,000 and 7,000. Additional usage is on by default for organizations. [Verified] data/variables/copilot.yml:19-49; content/copilot/concepts/billing-and-usage/organizations-and-enterprises/billing.md (pool and overage sections).
- The features that consume AI Credits include Copilot cloud agent and third-party coding agents. Code completions stay unlimited on paid plans. [Verified] content/copilot/concepts/billing-and-usage/individuals/billing.md:65-75.
- Cloud agent and third-party agents: "Coding agents consume GitHub Actions minutes and AI credits". Under the legacy model each cloud agent session cost one premium request plus "Actions minutes ... from your account's monthly allowance of free minutes for GitHub-hosted runners". [Verified] about-third-party-coding-agents.md:101-103; content/copilot/reference/copilot-billing/request-based-billing-legacy/github-copilot-premium-requests.md:61-69.
- Copilot code review: "Private repositories: Minutes are consumed ... Public repositories: Minutes remain free" (consuming Actions minutes since 2026-06-01). [Verified] github-actions.md:34-39,135; [Reported for date] github.blog changelog 2026-04-27.
- Public-repository cloud agent minutes: no doc page says so directly for the cloud agent. Since it runs on standard `ubuntu-latest` runners and standard runners are free in public repositories, its minutes should be free there, while its AI Credits are always billed. [Inferred] configure-runner-for-coding-agent.md:17; github-actions.md:24.
- Copilot automations: "Each time an automation runs, it starts a Copilot cloud agent session that uses GitHub Actions minutes and GitHub AI Credits. This usage is billed to the user who created the automation." [Verified] data/reusables/copilot/cloud-agent/automations-billing.md.
- gh-aw cost has two parts: Actions minutes ("A typical run includes a short pre-activation job (10-30 seconds) and an agent job (1-15 minutes). Each job also incurs approximately 1.5 minutes of runner setup overhead") and inference from the engine's provider. Copilot inference bills to the organization through `copilot-requests: write` on `GITHUB_TOKEN`; Claude, Codex and Gemini bill to their own provider accounts. The FAQ says the Actions minutes are "free for public repos, metered for private". [Verified] gh-aw docs reference/billing.md:8-61; reference/faq.md:732; GitHub docs about-github-agentic-workflows.md:125-152.
- claude-code-action: "Each run consumes ... GitHub Actions minutes ... [and] API tokens ... If you authenticate with an OAuth token, runs use your Claude subscription instead of API billing." The OAuth token is "available on Pro, Max, Team, and Enterprise plans", but "for a secret shared across repositories, authenticate with an API key ... since an OAuth token is tied to the subscription of the person who ran `claude setup-token`". [Verified] cc-github-actions.md:77,99,303-307.
- Claude Code on the web "counts toward your plan's usage limits ... and there's no separate charge for the cloud VM". Parallel sessions share the account's rate limits "proportionately". Routines draw subscription usage the same way. [Verified] cc-claude-code-on-the-web.md:13,435; cc-routines.md:387-398.
- Cursor: cloud agents are "charged at API pricing for the selected model", and "VM compute for cloud agents will be priced in the future". Bugbot moved from $40/user/month to usage-based billing in May 2026 (average run $1.00-1.50 per a third party). Plans: Hobby free, Pro $20, Pro+ $60, Ultra $200, Teams $40/user. [Reported; sources conflict] search: cursor.com/docs/account/pricing.md, cursor.com/docs/bugbot/legacy-pricing, vantaige.io, jetadmin.io (2026-07-27).

[Reported; conflicting] search: morphllm.com/codex-pricing, verdent.ai/guides/codex-pricing-2026, uibakery.io.

### 3. How work is assigned, parallelism, and what prevents collisions

- Copilot is started from the Agents tab, from an issue (assign "Copilot" under Assignees, picking repository, base branch, custom agent and instructions), from a PR comment (`@copilot`, batched review comments), from Chat, mobile, the IDEs, the REST API, the CLI, MCP, Jira, Slack, Teams, Azure Boards, Linear or Raycast. Once assigned, it "will not be aware of ... any further comments that are added to the issue". [Verified] content/copilot/how-tos/use-copilot-agents/cloud-agent/start-copilot-sessions.md:30-43; use-cloud-agent-on-github.md:69-107,158.
- Limits per Copilot task: "can only make changes in the repository specified", "can only work on one branch at a time and can open one pull request per task", and each session is capped at 59 minutes, which "cannot be extended". It only works with GitHub-hosted repositories, and an incompatible ruleset blocks it unless Copilot is added as a bypass actor. [Verified] copilot-on-github.md:134-146.
- Parallelism: "You can run multiple agent sessions concurrently". The Agents tab can start, watch live logs of, track, steer (each steering message costs AI Credits) and hand off sessions to VS Code or Copilot CLI. [Verified] content/copilot/concepts/agent-capabilities/choosing-and-delegating-agent-work/agent-management.md:23,39-49. No doc I read describes a lock or claim that stops two sessions or two agents working the same issue. [Inferred]
- Agent HQ ("mission control") was announced at GitHub Universe on 2025-10-28 with partners Anthropic, OpenAI, Google (Jules), Cognition and xAI "over the coming months". Claude and Codex reached public preview for Copilot Pro+ and Enterprise in February 2026, and teams can "assign an issue to Copilot, Claude, Codex, or more than one agent to compare results". [Reported] search: github.blog/news-insights/company-news/welcome-home-agents/, visualstudiomagazine.com 2025-10-28, thenewstack.io/github-agent-hq/. As of 2026-10-15 the docs list only Claude and Codex as third-party coding agents (Pro, Pro+, Max, Business, Enterprise; policy-gated) and do not use the names "Agent HQ" or "mission control" in the pages I read. [Verified for the docs list] about-third-party-coding-agents.md:37-40,44-76; [Inferred for naming].
- Multi-agent inside one session: `/fleet` in Copilot CLI or the Copilot app makes the main agent an orchestrator that runs subagents in parallel, each with its own context. GitHub warns this uses more AI Credits and helps only when tasks are independent. [Verified] content/copilot/concepts/agent-capabilities/choosing-and-delegating-agent-work/delegating-and-parallelizing-work-with-agents.md:16-61. Dynamic workflows (public preview) are programs in Copilot extensions that combine deterministic steps with agents run in sequence or in parallel. [Verified] .../dynamic-workflows.md:16-30.
- Copilot automations have four triggers: a schedule (hourly, daily or weekly), an issue created, a PR opened, a PR synchronized. They ignore events from users without write access by default, need a private or internal repository and Pro, Pro+, Max, Business or Enterprise, and anyone with write access can create one. [Verified] about-automations.md:43-63; data/reusables/copilot/cloud-agent/automations-availability.md.
- gh-aw default concurrency is per workflow and issue (`gh-aw-${workflow}-${issue}`) plus a per-engine group `gh-aw-{engine-id}` that "ensures only one agent job runs per engine across all workflows" unless overridden. `queue: max` queues runs instead of dropping them. Concurrency groups serialize runs; they are not claims. [Verified] gh-aw reference/concurrency.md:14-30,73-80.
- gh-aw native work queue: "fair scheduling, immutable task dependency graphs, and worker effects authorized by individual Claims. Its only source of authority is `work-queue.jsonl`", stored "on a dedicated Git branch" (`gh aw work-queue` defaults to branch `work-queue`). Records include Work, Claim ("Authorization for one attempt at a Work item"), Policy, Pool, Reservation, Completion, Result and Release. Defaults: concurrency 16 per pool (1-4,096), pending limit 4,096, 3 retry attempts, 30 s backoff, class weights [8,4,2,1,1]. "The scheduler selects eligible tasks under Policy; the agent does not choose which task receives a Claim." Publication uses `createCommitOnBranch` with `expectedHeadOid` (compare-and-swap). [Verified] gh-aw reference/work-queue.md:6-42,91-101,312-316,541-543; patterns/workqueue-ops.md:8-29.
- gh-aw work queue maturity conflicts across its own docs. The spec's walkthrough says "This is the intended experience of the proposed design, not a feature already implemented", while the reference documents operator commands and the blog says work queues and ledgers "land in v0.90.3" with "Git-backed fair DAG work queues with claim-scoped effects ([#66024])" in v0.91.4-v0.91.8. [Verified, conflicting] gh-aw docs specs/work-queue-specification.md:21-23; blog/2026-10-05-weekly-update.md:3,19; blog/2026-10-12-weekly-update.md:3,34.
- gh-aw OrchestratorOps: "one workflow (the orchestrator) fans out work to one or more worker workflows". Issue checklists, sub-issues, cache-memory and repo-memory are the lightweight queues, and repo-memory resolves merge conflicts with "your changes win". [Verified] patterns/orchestrator-ops.md:8; patterns/workqueue-ops.md:10-16; reference/repo-memory.md:8.
- gh-aw can start Copilot cloud agents as safe outputs: `create-agent-session` (default max 1, up to 10) and `assign-to-agent` (max 1), both needing a fine-grained PAT. [Verified] gh-aw reference/copilot-cloud-agent.mdx:12-30; reference/safe-outputs.md:63,110.
- claude-code-action: "Issues: Always creates a new branch with a timestamp" named `${branchPrefix}${entityType}-${entityNumber}-${timestamp}` with prefix `claude/`. Two runs on one issue therefore make two branches and nothing refuses the second. For PRs it pushes to the existing branch. It keeps one updating tracking comment. [Verified, collision point Inferred] claude-code-action docs/faq.md:103-115; src/utils/branch-template.ts:127; action.yml:22-25.
- Claude Code on the web: "each `--cloud` command creates its own cloud session that runs independently", and routines run "as you" on one account; neither shares state with the other sessions. [Verified] cc-claude-code-on-the-web.md:124; cc-routines.md:55.

### 5. Notes that bear on Symphony and Beethoven

- Symphony's no-API-key, subscription-token path is supported by claude-code-action and documented by Anthropic, but gh-aw excludes it: "`CLAUDE_CODE_OAUTH_TOKEN` is not supported by GitHub Agentic Workflows. Provider-based OAuth authentication (such as billing through a Claude Teams or Claude Max subscription) is not supported." [Verified] gh-aw docs reference/auth.mdx:217-219; engines/claude.md:22; cc-github-actions.md:77.
- gh-aw can run its Claude engine on Copilot inference (`copilot-requests: write`, no Anthropic key), so a Copilot seat can pay for Claude Code in Actions. [Verified] gh-aw engines/claude.md:35.
- Public repositories are where the CI-native model is cheapest. Actions minutes are free on standard runners within the concurrency cap (20 concurrent jobs on Free, 6 hours per job), so the only marginal cost of a Symphony worker in a public repository is the Claude subscription window. Copilot automations are unavailable there, and Copilot agents still spend AI Credits. [Inferred] github-actions.md:24; content/actions/reference/limits.md:45,64-69; automations-availability.md.
- Remote-steering convergence relevant to Beethoven: Copilot CLI "remote control" lets github.com monitor and steer a CLI session that "continues running on your original machine, which must stay online", the same shape as Claude Code Remote Control. [Verified] copilot-on-github.md:75.
- Copilot cloud sandbox compute is about $0.0014 per minute of compute plus $0.00072 per minute for 4 GiB of memory, roughly $0.0022 per minute, against $0.006 per minute for a 2-core Linux Actions runner in a private repository. [Inferred from the Verified unit prices] cloud-and-local-sandboxes.md:54-58; actions-standard-runner-prices.md.

## Claims worth verifying

- That Copilot cloud agent sessions in a public repository consume no billable Actions minutes. GitHub states this for code review, not for the cloud agent; the legacy page says minutes come from the account's free allowance, which would be odd wording if they were always free in public repositories.
- Whether cloud-agent Actions minutes are charged to the repository owner (the Actions rule) or to the user who assigned the task (as automations are charged to their creator).
- Whether gh-aw's native work queue is fully shipped or partly "proposed design". Its own spec and its blog or reference disagree; check v0.92.0 release notes and pkg/workqueue tests.
- Which Agent HQ partners actually run on GitHub on 2026-10-15. The docs list only Claude and Codex; the Universe 2025 coverage named Jules, Cognition (Devin) and xAI.
- Codex cloud limits and the reported container fee; Devin's current plan structure; Cursor Bugbot usage-based pricing; Factory seat plans; Jules model version; Kiro autonomous agent availability. All from secondary sources that conflict.
- That GitLab Duo flows bill CI compute minutes in addition to GitLab Credits.
- Anthropic's position on a shared org secret holding one person's `CLAUDE_CODE_OAUTH_TOKEN`. Anthropic's docs advise an API key for shared secrets, and Symphony's whole cost model rests on the subscription token.
- That GitHub keeps the free tier for public repositories on standard runners unchanged after the postponed self-hosted fee.
