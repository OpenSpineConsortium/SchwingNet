=== [unit mrzzsdjxrm2.18418] heading level 3
The argument, in order

=== [unit mrzzsdjxrm2.18441] paragraph
Keep this order for every audience. The need comes before the mechanism, so the listener knows what the mechanism is for; the limits come before anyone asks, so the rest is believed.

=== [unit mrzzsdjxrm2.18626] list item
The need. Agents that share a codebase get in each other's way. In CooperBench, where each of two agents worked in its own copy and could only message the other, one GPT-5 agent passed 315 of 652 feature pairs where two agents passed 183. The failures were duplicated and contradictory work, not a lack of skill, and chat between the agents did not raise success; in a later, smaller ablation, pairs given a shared git remote or task list did better than one agent, on weak evidence (spec 7.1).

=== [unit mrzzsdjxrm2.18911] list item
The mechanism. Make the forge the coordinator. A claim is the push that creates the branch claude/N, and git lets exactly one of two racing creations win, so no lock server is needed. A board, the release of idle claims and the landing order of overlapping work are GitHub Actions jobs over GitHub's own objects, and a required check decides what merges (spec 2 and 9.1).

=== [unit mrzzsdjxrm2.19284] list item
The economics. On a public repository those jobs run on GitHub's free standard runners and make no model call. The Claude work bills a flat plan, not tokens, and there is nothing to host (spec 9.2 and 9.6).

=== [unit mrzzsdjxrm2.19492] list item
The evidence. The protocol's shipped code was checked over 16.7 million states against an oracle written from its spec, with mutants that prove the checks bite, and found no violation. Building the harness and reviewing the fixes it led to found 19 defects: six are fixed in release 0.4.1, eleven on main but not yet released, one was settled in the spec, and one (F8) is open. What is not yet evidence: no full-scale benchmark of Symphony exists (spec 2; question R1).

=== [unit mrzzsdjxrm2.19791] list item
The limits. Inference is still paid, and one plan's usage window is shared. The terms questions are open, the server enforces a claim only at its creation, and one vendor sets the price (spec 10).

=== [unit mrzzsdjxrm2.19988] paragraph
For a short explanation, use three of the spec's twelve axes, the three the study rests on: who pays for compute and inference (axis 10), how a claim is kept (axis 5), and what decides that work is acceptable (axis 11).

=== [unit mrzzsdjxrm2.20208] heading level 3
For grant reviewers

=== [unit mrzzsdjxrm2.20228] paragraph
Lead with the science, not the software: AI-run research fails in ways its paper cannot show (spec 7.2), so the checks belong inside the run. Then the coordination, as the laboratory's rule of one issue, one branch, one pull request.

=== [unit mrzzsdjxrm2.20462] paragraph
Three sentences to adapt:

=== [unit mrzzsdjxrm2.20489] quote
Studies of AI agents find that two agents splitting work on one codebase, each in its own copy and talking only by message, succeed less often than one, because they duplicate and contradict each other's work, and that AI-run research fails in ways its paper cannot show. Our laboratory runs its agents under a claim protocol in which each piece of work is one issue, one branch and one pull request, and plans to turn reporting checklists such as CLAIM and REFORMS into gates checked over every run's record, so that a tool, not a model, decides whether a result may be reported. One such check is built today; the others are planned.

=== [unit mrzzsdjxrm2.21749] heading level 3
For engineers

=== [unit mrzzsdjxrm2.21763] paragraph
Lead with the mechanism and its failure modes; engineers trust an account that names its own holes.

=== [unit mrzzsdjxrm2.21864] quote
Symphony makes a GitHub repository the coordinator for Claude Code agents. A claim is the push that creates branch claude/N, and git lets exactly one of two racing creations win, so there is no lock server; the board, the release of idle claims and the order in which overlapping work lands are deterministic Actions jobs on GITHUB_TOKEN, and Claude runs only where judgment is needed. The shipped protocol library is checked over every interleaving of two workers, to a depth of eight steps on one issue and seven on two, against an oracle written from its spec, and its known gaps are written down.

What stops a push onto someone else's claim?

=== [unit mrzzsdjxrm2.22525] table 1, row 1, column 1
On GitHub, only the claim's creation is enforced. A fast-forward or forced push onto an existing claim is accepted, since the recommended setup leaves claude/** out of every ruleset so that a release can rename the branch. The local push guard refuses forced pushes and leases onto another worker's claim, and on 2026-10-15 it was found to judge a lease by the session's own directory rather than the clone git -C names, so a lease onto another worker's claim passed from a directory whose clone had neither branch

=== [unit mrzzsdjxrm2.23694] heading level 3
For lab leads

=== [unit mrzzsdjxrm2.23708] paragraph
Lead with what people have to do and what it costs.

=== [unit mrzzsdjxrm2.23761] quote
Your lab's people and agents share one GitHub repository as their to-do list, their lock and their record: each task is one issue, one branch and one pull request, and there is no server to run. On a public repository the bookkeeping runs free on GitHub's machines; the Claude work is paid by each person's own plan, and agents that run inside GitHub share one plan's usage limits. A required check decides what merges.

=== [unit mrzzsdjxrm2.24181] paragraph
What lab leads ask:

=== [unit mrzzsdjxrm2.24203] list item
What does a new person need? A GitHub login, and their own Claude plan for their own sessions.

=== [unit mrzzsdjxrm2.24299] list item
What does it cost? On a public repository, nothing in minutes. On a private one, a monthly quota and then a price per minute: in the spec's illustration, ten one-hour Claude runs a day come to about $90 a month on Team (spec 9.4). Claude plans are separate: Pro is $20 a month, Max $100 or $200.

=== [unit mrzzsdjxrm2.24596] list item
Can it run our science? Not on GitHub's free machines, which have no GPUs. The science runs on the cluster, which is Beethoven's part (spec 9.6).

=== [unit mrzzsdjxrm2.24743] list item
Is it ready? It is pre-release: 0.4.1 is the last release, and the rails for workers that run unattended, among them a cap on Claude runs and the qa check, are not built (spec risks 4 and 6).
