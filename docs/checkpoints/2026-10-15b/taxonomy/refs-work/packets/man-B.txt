# Packet man-B: from the Symphony and Beethoven Taxonomy Manual, sections: 4. Checking a claim; 5. Placing any tool in the taxonomy

=== [unit mrzzsdjxrm2.9844] heading level 2
4. Checking a claim

=== [unit mrzzsdjxrm2.9864] paragraph
Every claim in the spec carries one of four grades, defined in the spec's section 1: Verified, Inferred, Reported or Open. A grade rises only with new evidence, and falls as soon as a source contradicts it. This section is how to move one.

=== [unit mrzzsdjxrm2.10104] heading level 3
Testing a claim, in six steps

=== [unit mrzzsdjxrm2.10136] list item
Write it with its scope. One sentence, with the version, the plan and the date it holds for. "Free and unlimited" is a claim about standard runners on public repositories as of 2026-10-15, not about Actions in general.

=== [unit mrzzsdjxrm2.10356] list item
Write what would refute it, before looking for support. The spec's section 8 gives one refuting observation for each uniqueness claim, and section 11 gives each research question its acceptance criteria.

=== [unit mrzzsdjxrm2.10561] list item
Look for the refutation first. Search by mechanism, not by product name, since a rival rarely uses our words: first push wins, lock branch, claims branch, reaper, idle claim, compare-and-swap with agents, CLAUDE_CODE_OAUTH_TOKEN in a workflow.

=== [unit mrzzsdjxrm2.10806] list item
Run it when it can be run. A claim about git or the protocol is cheapest to settle on a scratch repository. The claim-lock check (research/taxonomy/verify/02) did this and found or confirmed three things the documents did not say: the server enforces a claim only at its creation, the push guard judges a lease by the session's own directory rather than the clone a git -C command names, and the idle clock is the pusher's (the spec's risks 12 and 13).

=== [unit mrzzsdjxrm2.11200] list item
Record the search even when it finds nothing: where you looked, with which terms, on what date. A search that finds nothing makes a claim Inferred, never Verified, and the spec says how far the search went.

=== [unit mrzzsdjxrm2.11408] list item
When the claim fails, narrow it or drop it. Change the spec first, then every talking point that rests on it (section 6).

=== [unit mrzzsdjxrm2.11530] paragraph
A worked case. An early draft of the placement figure said only Symphony puts its agents under an atomic claim. The adversarial search found three systems that have one: gh-aw's work queue (a compare-and-swap on a ledger branch), unsorry (first push wins on a shared claims branch) and agentic-setup (a create-only branch push). The atomic claim moved to the spec's list of what is not unique, and claim U1 now names only the combination, with the observation that would refute it.

=== [unit mrzzsdjxrm2.12927] heading level 3
When a source is out of reach

=== [unit mrzzsdjxrm2.12957] paragraph
This project's sessions cannot open several hosts (section 2). Read GitHub's documentation from the github/docs repository's content files on raw.githubusercontent.com, at a commit you name. Read a paper from its authors' repository where there is one, as CooperBench's PDF was read from cooperbench/website. Leave the rest to claude.ai Research (section 3), then have a thread open each link the report gives. A claim whose only source stays out of reach keeps the grade Reported, with a note of what to re-read.

=== [unit mrzzsdjxrm2.13471] heading level 2
5. Placing any tool in the taxonomy

=== [unit mrzzsdjxrm2.13507] paragraph
Use this for any system someone names as an alternative, a competitor or a partner.

=== [unit mrzzsdjxrm2.13591] heading level 3
The procedure

=== [unit mrzzsdjxrm2.13607] list item
Pin the version. Name the repository and commit, or the product, plan and date. A placement goes stale when the tool ships.

=== [unit mrzzsdjxrm2.13732] list item
Find its claim. Ask one question of the code, not the README: when two of its agents want the same piece of work, what stops the second, and what frees a claim nobody finishes? Most of the differences in the field sit in that answer (axis 5).

=== [unit mrzzsdjxrm2.13976] list item
Put it in a quadrant. Where does the coordination state live, and what does one more agent run cost as the tool is usually run? Those are the two axes of the spec's placement figure.

=== [unit mrzzsdjxrm2.14160] list item
Fill the worksheet below, one cell per axis, each with its source. Not stated is an answer; a guess is not.

=== [unit mrzzsdjxrm2.14269] list item
Score it on the five mechanisms, (a) to (e) of the spec's section 8: yes, partial (say what is missing) or no. Only a yes counts toward what would refute claim U1: four of the five, or (a), (c) and (d) together. A tool that reaches either goes to the spec before anything else.

=== [unit mrzzsdjxrm2.14507] list item
Add it to the spec: a row in the placement table of section 4 if it shares a cell with Symphony or Beethoven, a row in the matching table of section 5, and a line in the prior-art table of section 8 for each mechanism it has.
