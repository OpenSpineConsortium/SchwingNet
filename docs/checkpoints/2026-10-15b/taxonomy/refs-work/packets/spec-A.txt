=== [unit mggj4hxkexp.1332] heading level 3
Symphony: one repository as the shared plane for many agents

=== [unit mggj4hxkexp.1393] paragraph
Symphony makes one GitHub repository the shared state for any number of Claude Code workers: a person's local or cloud sessions, routines, and agents running as GitHub Actions jobs. It has no server of its own. The rules are a Python library with no dependencies (symphony-protocol, public, MIT), vendored into each repository beside eleven workflow files and Claude Code hooks in a whole-template copy, or beside at most three workflow files (board, tidy and metrics) and the symphony plugin's hooks in a protocol-only adoption. Verified: PROTOCOL.md, research note 01.
    links in this unit: "symphony-protocol" -> https://github.com/OpenSpineConsortium/symphony-protocol; "PROTOCOL.md" -> https://github.com/OpenSpineConsortium/symphony-template/blob/main/docs/agents/PROTOCOL.md

Each Claude Code session

=== [unit mggj4hxkexp.3227] paragraph
Claude runs in only three workflows (claude.yml, the work job of workers.yml and four jobs of coordinator.yml), all through anthropics/claude-code-action@v1 on one subscription token, CLAUDE_CODE_OAUTH_TOKEN. Everything else is deterministic code on the workflow's GITHUB_TOKEN, so a worker with nothing to do starts no Claude session. The design rests on about 30 GitHub primitives, among them concurrency queues, branch renames that close a pull request, and environments with required reviewers. Verified: research note 01.

=== [unit mggj4hxkexp.3754] paragraph
Maturity. The library's first commit is 2026-10-10 and release 0.4.1 is of 2026-10-13. Its 1,379 tests and the template's 581 passed on 2026-10-15. A validation harness drives the shipped library through every interleaving of scripted workers against an oracle written from the spec's text: 16.7 million states at depth 8, and 18.8 million with two issues at depth 7, with no violation in the run of 2026-10-14, which searched the library before the fixes of F2, F15, F17, F18 and F19; 93 mutants prove the checks bite. Building the harness and reviewing the fixes it led to found 19 defects: six are fixed in release 0.4.1, eleven more on main ahead of the next release, one (F16) was settled by changing the spec, and one (F8, idleness read from the committer date) waits on the owner (validation/DESIGN.md and known.json). Not built yet: the qa check, the cap of 10 Claude runs a day, the public runtime, the control panel, the account pool, and a benchmark run of Symphony at full scale. Verified: validation run of record, research notes 01 and 12.
    links in this unit: "validation run of record" -> https://github.com/OpenSpineConsortium/symphony-protocol/blob/main/validation/runs/2026-10-14/README.md

=== [unit mggj4hxkexp.4568] heading level 3
Beethoven: protocols, gates and agents for research on a university cluster

=== [unit mggj4hxkexp.4644] paragraph
In the owner's words, beethoven-base and beethoven-sites hold the protocols for grid jobs on Wayne State's cluster, beethoven-research the reproducible CLAIM and REFORMS workflows, and beethoven-qa the checks on code that agents write autonomously, while beethoven-agents and symphony-protocol coordinate the agents; Claude iterates the scientific method inside these frameworks. All of Beethoven is private and proprietary. The repositories' roles and their private, proprietary status are Verified (research notes 04 and 05). That symphony-protocol coordinates Beethoven's agents is the owner's design and is in no Beethoven file yet (Inferred; see the next subsection).

=== [unit mggj4hxkexp.6445] paragraph
Read from the bottom: the substrate is rented or owned by someone else, sessions run where the work is, Symphony decides who holds which piece of work, tools decide whether the work is acceptable, and the study's checklists decide whether the result may be reported.

=== [unit mggj4hxkexp.6712] paragraph
The stack is the owner's design, and its composition is Inferred: no Beethoven repository references Symphony today, and Symphony's own plan rules that no Beethoven repository runs Symphony's code or holds a Claude token. The parts that can be shared are Symphony's Claude-free core (the branch-name claim, the board, the protocol check, the push guard, required checks and auto-merge), because Beethoven forbids a stored Claude token in CI and Symphony's Actions workers need one. Verified: research note 05.
