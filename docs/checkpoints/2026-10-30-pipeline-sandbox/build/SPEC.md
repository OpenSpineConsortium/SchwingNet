## 2. Identifiers

- block id and template id: `^[a-z][a-z0-9_]{1,39}$` (the gate's id shape, so an id may become a word).
- node id: `^n[1-9][0-9]{0,3}$`; nodes sort by their number.

- choice value and every value that can reach an experiment request: `^[A-Za-z0-9][A-Za-z0-9._,-]{0,79}$`.

## 3. contract.json (shape; DATA fills the words)

```
{
 "contract": 1,
 "stages": [{"id": "source", "title": "Source", "what": "..."}, ...],
 "kinds": {"data": "...", "model": "...", "checkpoint": "...", "metrics": "...", "report": "..."},
 "axes": {"N": "samples", "T": "time", "C": "channels", "D": "depth", "H": "height", "W": "width",
          "F": "features", "K": "points", "P": "coordinates of a point"},
 "spatial": ["D", "H", "W"],
 "dtypes": ["uint8", "int16", "int32", "float16", "float32", "bool"],
 "targets": ["none", "level", "mask", "points", "value"],
 "parts": ["train", "validation", "test"],
 "modalities": ["any", "fluoro", "radiograph", "mixed", "ct", "drr", "table"],
 "licences": ["commercial", "commercial-share-alike", "non-commercial", "research-internal", "uncut"],
 "job_classes": ["none", "cpu", "gpu"],
 "today": ["live", "word", "flow", "pending", "planned"],
 "code": ["existing", "own", "planned"],
 "deterministic": ["exact", "seeded", "declared"],
 "needs": ["python", "numpy", "scipy", "nibabel", "torch", "torchvision", "monai", "onnxruntime", "jax", "pymc", "metaflow", "wandb"],
 "glyphs": [<the 32 names of section 9>],
 "limits": {"combinations": 64, "array_tasks": 1000, "nodes": 60, "edges": 120,
            "epochs_most": 200, "hours_most": 48, "manifest_bytes": 16384},
 "probes": [{"name": "frames, 2-D grey 64", "type": <a type record>}, ...],
 "requirements": [{"id": "R1", "title": "...", "rule": "..."}, ...]
}
```

The stage order is fixed and is the prediction's grammar: source, prepare, split, augment, model, train,
calibrate, select, evaluate, analyse, report. `licences` runs from the least to the most restricted use: the
four recipes of data/recipes/ ordered by how many licence classes each admits (commercial admits 1,
commercial-share-alike 2, non-commercial 3, research-internal 5), then "uncut" (no recipe applied). PY's check
holds this list to data/recipes/. `requirements` is the human list of R1..R13 of section 13, shown in the
page's import dialog. `probes` holds at least: frames 2-D grey 64 (N,C,H,W; C=1,H=64,W=64; uint8), frames 2-D
colour 224 (C=3, H=W=224, float32), volumes 3-D grey 96 (N,C,D,H,W; C=1, D=H=W=96; int16), clips 2-D grey
(N,T,C,H,W; T=16, C=1, H=W=64; uint8), a table (N,F; F=32; float32). Each probe type is a full type record
(section 4) with targets "level", classes 27, parts all three, persons true, modality "any", licence
"uncut", sources [].

## 4. The type record

Every port value is a type record with exactly these fields, always all present:

```
kind:     "data" | "model" | "checkpoint" | "metrics" | "report"
axes:     [axis, ...]            ordered axis names from contract.axes; [] for metrics and report
sizes:    {axis: int >= 1}       only axes present in axes; an unknown size is absent
dtype:    a contract dtype or "any"
targets:  a contract target
classes:  int >= 1 or null
parts:    [part, ...]            subset of contract.parts, always in contract order
persons:  bool                   the person key rides along (leakage control)
modality: a contract modality
licence:  a contract licence
sources:  [block id, ...]        lineage: the ids of the source blocks upstream, sorted, unique
family:   string or null         model family, for model and checkpoint
rank:     int 0..3               computed: how many of D, H, W are in axes; never set by an op
trained:  bool
```

The empty type (the start of a source block): kind "data", axes [], sizes {}, dtype "any", targets "none",
classes null, parts [], persons false, modality "any", licence "uncut", sources [], family null, rank 0,
trained false.

Model and checkpoint types stay flat: they keep the axes, sizes, dtype, targets, classes, parts, persons,
modality, licence and sources of the data they were built for. That is how a model "adapts": a classifier's
output type says its stem takes `sizes.C` channels of rank `rank`, and its head has `classes` outputs, all
read from the incoming data's type; and it keeps one chain linear, so growing a pipeline to the right
always pipes one output into one input.

## 5. Block manifest (tools/sandbox/blocks/<id>.json, the file name is the id)

```
{
 "block": 1,
 "id": "train_classifier",
 "version": 1,                         int >= 1 (whole versions only; the owner's rule)
 "title": "Train a classifier",        1..60 chars
 "stage": "train",
 "summary": "...",                     1..120 chars, one line
 "does": "...",                        1..800 chars
 "glyph": "train",                     one of contract.glyphs
 "inputs":  [{"name": "model", "accepts": <pattern>, "optional": false, "what": "..."}],
 "outputs": [{"name": "checkpoint", "from": "model", "ops": [<op>, ...], "what": "..."}],
 "params":  [<param>, ...],
 "rules":   [<rule>, ...],
 "reads":   {"parts": ["train", "validation"]},
 "job":     {"class": "gpu", "hours": "@param.hours", "with_upstream": false, "array": false,
             "cpus": 8, "memory_gb": 64},
 "deterministic": "seeded", "seed_param": "seed", "nondeterminism": "",
 "generic": {"rank": [2], "time": "no", "channels": "any", "sizes": "any", "why": "..."},
 "resolve": "a {family} whose {rank}-D stem takes {sizes.C} channel(s) of {sizes.H} x {sizes.W}; head of {classes}",
 "needs": ["torch", "torchvision"],
 "code": "existing",
 "implemented_by": ["tools/train.py", "flows/experiment.py"],
 "today": {"status": "live", "route": "experiment", "word": "experiment <issue>", "flow": "ExperimentFlow", "note": "..."},
 "experiment": {"epochs": "@param.epochs", "seed": "@param.seed", "hours": "@param.hours",
                "blocks": {"optimiser": "@param.optimiser", ...}, "only": {}},
 "card": null
}
```

- A source block (stage "source") has no inputs and a `card`:
  `{"origin": "...", "where": "...", "count": "...", "persons": "...", "split": "...", "held_out": "...", "licence": "...", "from": ["repo path the facts come from", ...]}`.
  Every other block has at least one input and `"card": null`.
- `generic` is required when the block has an input whose pattern admits kind "data" or "model"; else null.
- `resolve` is optional (null or a string); placeholders are `{field}` or `{sizes.X}` of the first output type;
  a missing value prints `?`.
- `experiment` is null when the block cannot be part of an experiment request; otherwise an object with any of:
  `recipe` (ref), `epochs`, `seed`, `hours` (refs), `blocks` ({Blocks field: ref or literal}), `only`
  ({param: [allowed values]}, the route's limits, e.g. architecture only resnet18). `{}` means the block rides
  along at no cost (the flow does it anyway, e.g. the report).
- A param:
  `{"name": "epochs", "kind": "int", "low": 1, "high": 200, "default": 20, "vary": true, "what": "..."}`.
  kinds and their fields:
  - choice: `choices` (non-empty, unique, value shape of section 2), `default` in choices.
  - int: `low`, `high` (ints, low <= high), `default` int in range.
  - float: `low`, `high` (numbers), optional `above` (true: strictly above low), `default` in range. Every float
    value is written with at most 6 decimals and no exponent (section 8), so a value must equal its own rounding
    to 6 decimals and lie in [0.0001, 1e9) or be 0.
  - bool: `default` true or false.
  - set: `options` (non-empty, unique, value shape), `default` a list in options order, no repeats.
  - names: `pattern` (a regex string, default `^[a-z0-9_]{1,40}$`), `default` a list, no repeats.
  `vary: true` lets a node sweep the param over several values (section 10).
- A rule: `{"when": {"param": <cond>}, "need": {"param": <cond>}, "say": "..."}`; it fails when every `when`
  condition holds and some `need` condition does not. A condition is an object with any of: `in` (list),
  `not_in` (list), `min`, `max` (inclusive), `above`, `below` (strict), `empty` (true: an empty list or
  0 / "" / "none"), `nonempty` (true). An iff rule is written as two rules.
- `reads.parts`: the split parts this block reads from its data. "test" only in stages evaluate and report.
- `job`: class none, cpu or gpu; `hours` a number > 0 or `@param.<int or float param>`; `with_upstream` true
  means it runs inside its upstream node's job (same class) and adds its hours there; `array` true means its
  combinations go as one array job; `cpus` 1..64, `memory_gb` 1..512. Class none: hours, cpus and memory_gb are
  ignored and may be 0.
- `deterministic`: exact (same inputs give the same bytes), seeded (`seed_param` names an int param), or
  declared (`nondeterminism` says what varies and why it is tolerated, at least 20 chars).
- `generic.rank`: subset of 0..3; `time`: any | yes | no; `channels`: "any" or a list of ints; `sizes`: "any" or
  "fixed"; `why` is required (at least 20 chars) whenever the block does not take every rank in 1..3, every
  channel count and every size; it says what the code does today and what it would take to widen it.
- `code`: existing (the code is in the repository: `implemented_by` lists paths that exist), own (an imported
  block: `implemented_by` is exactly ["tools/sandbox/blocks/<id>.py"], that file has a module docstring and a
  top-level `def run(inputs, params, context)`, and tests/test_sandbox_block_<id>.py exists), planned (no code
  yet: `implemented_by` may be empty and `today.status` is "planned").
- `today.status`: live (a page can request it now, through the experiment route), word (a gate word runs it now
  with a fixed id: `word` says which, e.g. "census gold3"), flow (a launched flow runs it inside a fixed plan:
  `flow` says which), pending (built on an unmerged pull request: `note` names it), planned (nothing runs it
  yet; it waits for the pipeline route). `route`, `word`, `flow` and `note` are strings, possibly empty.

## 6. Patterns (inputs[].accepts)

```
{"kind": ["data"], "rank": [2, 3], "time": "any", "has_axes": ["C"], "dtype": ["uint8", "float32"],
 "targets": ["level"], "parts": "split", "needs_parts": ["train", "validation"],
 "modality": ["fluoro", "mixed"], "trained": true}
```

`kind` is required and non-empty; every other key is optional. A type matches when each given key holds:
kind in list; rank in list; time "yes" needs T in axes, "no" needs T absent; every has_axes axis present; dtype
in list or the type's dtype is "any"; targets in list; parts "split" needs parts non-empty, "unsplit" needs
parts empty; every needs_parts part present; modality in list or the type's modality is "any"; trained equal.
Each failed key is one problem with code "type" and `field` set to the key.

## 7. Ops (outputs[].ops)

An output starts from a copy of the type on the input port named by `from` (when given and connected), else
the first connected input in manifest order, else the empty type. The ops run in order:

- `["kind", K]`
- `["set", field, value]`: field one of dtype, targets, classes, modality, family, trained, persons.
- `["size", axis, value]`: the axis must be in axes; a null value removes the size.
- `["axes", [axis, ...]]`: replaces the axes; sizes of axes no longer present are dropped.
- `["drop_axis", axis]`: removes the axis and its size; nothing when absent.
- `["add_axis", axis, before, size]`: inserts the axis before `before` (or at the end when before is null or
  absent from axes); size an int, a ref or null. Nothing when the axis is already present.
- `["parts", [part, ...]]`
- `["licence", value]`: licence = the later of the two in contract.licences (the more restricted use).
- `["cut", value]`: licence = the earlier of the two (a recipe can only narrow what is admitted).

A value is a literal or a ref: `@param.NAME` (the node's effective value of that param), `@in.PORT.FIELD`
(FIELD may be `sizes.X`; null when the port is not connected), `@self.FIELD` (the type being built,
`sizes.X` allowed). An unknown op, field or ref is a problem with code "op".

After the ops, for every output: rank is recomputed; sizes are pruned to axes; parts are put in contract
order; then lineage is merged from every other connected input (sources united, licence the later of the
two, persons true only when both are true); and when the block's stage is source, its own id joins sources.
Sources are sorted and unique.

## 8. Graphs, canonical JSON and the digest

A pipeline spec (a template file has the same shape plus `id`, `about`, `layout` and `expect`):

```
{"sandbox": 1, "name": "...", "nodes": [{"id": "n1", "block": "catalog_v1", "version": 1,
  "params": {...}, "vary": {"param": [value, ...]}}], "edges": [{"from": "n1", "out": "data", "to": "n2", "in": "data"}],
 "layout": {"n1": [x, y]}}
```

`params` may hold only the values that differ from the defaults; `vary` may be absent. The canonical spec is
`{"sandbox": 1, "name": ..., "nodes": [...], "edges": [...]}` (no layout, id, about, expect or template): nodes
sorted by number, each with `id`, `block`, `version`, `params` (every manifest param, defaults filled; a node
of an unknown block keeps its params as given) and `vary` (only params with at least one value, keys sorted,
values in the given order; `{}` when none); edges sorted by (from number, out, to number, in).

Canonical JSON, the same in both languages: `null`, `true`, `false`; a number is an integer when it is whole
(|v| < 1e15), written in plain digits, else written with 6 decimals and its trailing zeros and point stripped
(Python `format(v, ".6f").rstrip("0").rstrip(".")`, JavaScript `v.toFixed(6).replace(/0+$/, "").replace(/\.$/, "")`);
a string as JSON with only ASCII allowed (a non-ASCII or control character is a problem, never written);
arrays in order; objects with keys sorted by code point; no spaces anywhere. The digest is the lowercase hex
SHA-256 of the canonical JSON's bytes. The page computes SHA-256 in plain JavaScript (no crypto.subtle).

## 10. Propagation, combinations and fan

`propagate(spec)` returns `{"order": [node ids], "nodes": {id: {"inputs": {port: type}, "outputs": {port: type},
"problems": [...], "fan": int, "combinations": int}}, "problems": [...]}`.

1. A node whose block is unknown: problem "block" (error), no types. A node whose `version` differs from the
   manifest's: problem "version" (warn).
2. Order: Kahn's topological sort, ties by node number. Nodes on a cycle: problem "cycle" (error) on each,
   left out of `order`, no types.
3. Edges: an `out` the upstream block does not have, or an `in` the downstream block does not have: problem
   "port" (error) on the downstream node; an input port with two edges: "port" (error); a required input with
   no edge: "input" (error).
4. Params: the effective params are the defaults overlaid with the node's; each value outside its kind's
   rules: "param" (error); an unknown param name: "param" (error); a varied param whose manifest says vary
   false: "vary" (error); each varied value checked like a param ("param"). combinations = the product of the
   node's vary list lengths (1 when none); more than limits.combinations: "vary" (error).
5. Rules: checked for the base params and for every combination of the node's own varied values; each rule
   that fails at least once: one "rule" problem (error) carrying its `say`.
6. Types: each connected input type checked against its pattern ("type", error, `field` set). Outputs computed
   by section 7 from the base params (the varied values do not change the types the board shows).
7. Reads: a block reading "test" outside stages evaluate and report: "test" (error); a data input whose parts
   lack a part the block reads: "parts" (error).
8. Fan: fan = (stage is select ? 1 : the largest fan among its connected upstream nodes, or 1) x its own
   combinations. A select node joins the arms; everything else carries them.
9. Graph problems: more than limits.nodes nodes or limits.edges edges: "limit" (error, node null); total
   combinations (the product over all nodes) above limits.combinations: "limit" (error).

A problem is `{"code": ..., "node": id or null, "port": name or null, "field": name or null, "level": "error" | "warn", "text": "..."}`.
The two engines must agree on the sorted list of (code, node, port, field, level); the text may differ.

## 11. Jobs

For each node in `order` whose job class is not none: tasks = its fan. When `with_upstream` is true and its
first connected upstream compute node has the same class, it rides in that job: 0 submissions, and its hours
are added to that upstream row's hours per task. Otherwise submissions = 1 when `array` is true, else tasks.
hours per task = job.hours (a ref read from the base params). Rows: `{"node", "block", "class", "submissions",
"tasks", "hours", "rides_with"}`. Totals per class: `{"submissions", "tasks", "hours"}` where hours = the sum of
tasks x hours per task, rounded to 2 decimals. An array with more than limits.array_tasks tasks: "limit".

## 12. Routes and compile

`compile(spec)` returns:

```
{"digest": hex, "route": "experiment" | "pipeline", "ready": bool,
 "why": [{"code": ..., "text": ...}], "requests": [...], "plan": [...rows...], "jobs": {...totals...},
 "pipeline_issue": {"title": ..., "body": ...}}
```

The experiment route (live today) is tried first. It applies when all of these hold, each failure one `why`:
no error problem ("errors"); every node's block has a non-null `experiment` ("not_mapped"); exactly one node of
catalog_v1 ("catalog"), one of classifier ("classifier") and one of train_classifier ("train"); no block used
twice ("duplicate"); every node reachable from the catalog node by edges ("unconnected"); every `only` holds for
the base and every combination ("only"); every float that reaches the request is 0 or at least 0.0001 with at
most 6 decimals ("float_plain"); the total combinations are at most limits.combinations ("too_many").

Then each combination of all varied params over the whole graph (the product in node-number then param-name
order, values in the given order; one combination when nothing varies) is one request:
- recipe: the mapped value, else "none"; epochs, seed, hours: the mapped values.
- blocks: for each Blocks field in DATA.experiment.fields order, the mapped value; a word `field=value` is kept
  only where it differs from DATA.experiment.defaults (a list joined by ",", an empty list written "none"; a
  number written as in section 8).
- `named` = those words; `title` = `Experiment: <named joined by " " or "version 1 (no block named)">, <epochs> epochs`;
  `hours_word` = Python `f"{hours:g}"` (JavaScript `String(Number(hours.toPrecision(6)))`, the same for
  0.1..48);
- `body` = exactly what tools/experiments_panel.py `issue_body(named, epochs, seed, hours_word, recipe)` returns
  (PY calls it; ENGINE copies its text, both paragraphs, byte for byte);
- `url` = `https://github.com/OpenSpineConsortium/SchwingNet/issues/new?` + form-encoded title, labels
  ("experiment") and body, in that order (Python urllib.parse.urlencode; JavaScript URLSearchParams).
- `lines` = the `key: value` lines of the body, without the marker.
Each request is one GPU job (train and evaluate in one job, grid/experiment-driver.sbatch); jobs.gpu then has
submissions = tasks = the number of requests, hours = the sum of each request's hours.

Otherwise the route is "pipeline", ready false, requests [], and the why list says what kept it off the
experiment route. `plan` is section 11's rows, each with the block's `stage` and `today`. `jobs` is section
11's totals. `pipeline_issue`: title `Pipeline: <name> (<first 12 hex of the digest>)`; body: the line
`<!-- schwingnet-pipeline -->`, a blank line, `digest: <hex>`, `route: <route>`, one line
`jobs: <g> GPU submission(s) (<t> tasks, <h> GPU-hours), <c> CPU submission(s)`, a blank line, then a fenced
```json block holding the canonical JSON, then a blank line and the sentence
`Nothing answers this issue yet: the pipeline route waits on the owner's word (docs/research/pipeline-sandbox/README.md).`
(Both routes fill pipeline_issue.)

## 13. Manifest requirements (the rules an imported block must meet; codes in brackets)

R1 identity [id, field]: block 1, id shape, version, title, stage, summary, does, glyph in contract.glyphs.
R2 ports [port, accepts, op, ref]: shapes of section 5-7; names unique; source stage has no input, every other
   stage has at least one; at least one output; ops and refs valid (a ref names an existing param or port).
R3 params [param]: section 5's kinds; defaults valid; names unique.
R4 rules [rule]: every when and need names an existing param; conditions valid; `say` non-empty.
R5 reads [reads]: parts from the contract; "test" only in stages evaluate and report.
R6 job [job]: class, hours, cpus, memory_gb, with_upstream, array as section 5.
R7 determinism [determinism]: as section 5.
R8 generic [generic]: required when the block takes data or a model; values valid; `why` when narrower than
   everything; each data input's `rank` (when given) equals generic.rank; and the probe test: for every
   contract probe whose rank is in generic.rank and whose time agrees with generic.time, a block whose first
   input admits kind data must accept the probe and compute every output with no problem.
R9 needs [needs]: subset of contract.needs.
R10 code [code]: as section 5 (PY checks the files; ENGINE checks only the shape).
R11 today [today]: status valid; live needs route "experiment" and a non-null experiment; word needs a word;
    flow needs a flow; pending needs a note naming the pull request (`#<number>`); planned needs code planned
    or own.
R12 text [text, size]: every string ASCII with no control character; the manifest's canonical JSON at most
    limits.manifest_bytes bytes.
R13 card [card]: a source block has every card field as a non-empty string (`from` a non-empty list).

`check_manifest(manifest)` returns problems `{"code", "field", "text"}`; the engines must agree on the sorted
(code, field) pairs.

## 14. Prediction (ENGINE; UI shows it)

`predict(spec, anchorId, stats, history)` returns at most 5 `{"block", "score", "why"}`, best first, ties by
block id. Candidates: blocks of any stage but source with an input whose pattern accepts the anchor's first
output type. Score, deterministic: a transition term from template edges and the viewer's history
(`stats[a][b]` and `history[a][b]` edge counts, history weighted 2, smoothed), a stage term (the next stage
after the anchor's that the pipeline lacks scores highest; the same stage low; an earlier stage lowest), a
penalty for a block already on the board (except evaluate, report and analyse stages), and a bonus for a stage
the pipeline lacks entirely. `why` names the strongest term in a short sentence ("after Train, the templates go
to Evaluate held out (3 of 4)", "the pipeline has no split yet"). `stats` = `transitionStats(templates)`.

## 15. ENGINE API (tools/sandbox/engine.js)

One IIFE; `module.exports = SB` under node, else `window.SandboxEngine = SB`. No DOM, no Date, no randomness.

```
