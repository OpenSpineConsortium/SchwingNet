## Where the control panel reads tasks from (settled)

- The panel (openspineconsortium.github.io, assets/js/symphony-panel.js, sortIssues) reads the open issues of one repository through GitHub's API as the signed-in person. It groups by label: blocker; epic or goal (listed together, taken whole by nobody); in-review; claimed; blocked; a worker:<name> label (Given to workers); todo (the Queue); the rest under other. Priority labels p1, p2, p3 (or priority:P1 to P3) order the Queue; the number breaks a tie.
- Its Dependencies tab, and the board's Dependencies section (STATE.md on the branch board), draw each open epic's sub-issues and GitHub's native blocked-by relations as a Mermaid chart, so an ordered task list is seen as one epic with its tasks as sub-issues and each task blocked by the one before it (team.py seed writes relations the same way, tools/sdlc_protocol/adapters/github.py add_blocked_by, POST /repos/{repo}/issues/{n}/dependencies/blocked_by).
- The repository is SchwingNet (the project's own, where the goal lives and the research is confidential); the panel opens it with ?repo=OpenSpineConsortium/SchwingNet. Its labels as of 17:00 UTC: todo, epic, blocked, blocker, claimed, in-review, research, synthesis, owner-act, priority:P1 to P3, worker:Gregory-Schwing-MD-PhD, worker:research-loop.
- What a label starts: the label epic on an open issue whose body has no "<!-- team:plan -->" marker starts coordinator.yml, which runs Claude on the repository's token to plan it into tasks (tools/sdlc_protocol/team.py route). So the epic is created WITH the marker in its body (or with its tasks already written and the marker), or labelled epic only after the planning section is in its body, so the coordinator does not plan it a second time. The label todo starts workers.yml, which runs only the workers of .github/symphony/workers/ that run in Actions; none is registered, so todo starts nothing. An issue body or title with "@claude" starts claude.yml; the issue text must not carry it. research starts nothing by itself (research.yml runs on a schedule and reads issues labelled research).
- A task's body in the Task form's shape: "### Goal", "### Acceptance", "### Files likely touched" (.github/ISSUE_TEMPLATE/task.yml; the panel's formBody writes the same). The board's Overlaps column reads "Files likely touched".
