## Plan

tools/storage_panel.py builds the textbook's storage panel, an interactive figure under docs/textbook/figures/22/, from a committed snapshot of spine-datasets' PLAN.json (its branch storage-feed): the lab volume's and the owner's home's drive use with the target marked, a table of every set with keep, remove, add and place (lab or home) controls, running totals against the 20 TB target and each quota with the planner's own refusals stated in words, the overlap between kept sets, and the selection string in the planner's grammar with a copy button. Its Apply button asks the page's parent window to dispatch spine-datasets' storage.yml, which only opens a request pull request the owner merges, and where no parent answers the page shows the workflow's link and the string to paste; a Refresh button asks the parent for the feed again. The tool's fetch subcommand refreshes the snapshot in docs.yml with the App's read token and falls back to the committed snapshot when the feed is unreachable, and its check subcommand, wired into scripts/check.sh, fails when the committed page is stale. A section of chapter 22 introduces the panel; a memory and a research note record the feed's contract and the parent protocol.
