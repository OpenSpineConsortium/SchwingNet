## Plan

The blocks get a covering set (every option and every interacting pair, 16 runs; strict pairwise on request) as pure logic, a compatibility check that reads a catalog and trains nothing, and plan files whose run folders are named from the configuration. tools/flow.py's run id becomes the hash of the commit, the catalog and the configuration, so a plan run again finds each run's folder and reuses it: a finished run is skipped, a trained one evaluated only, a partly trained one resumed from its last kept epoch with its optimiser state. grid/gate.sh gains the word sweep, which runs a plan file as one GPU job under the owner's go2432 smoke folder, pushing each run to W&B as it ends and rewriting the plan's results after every run, and the status word prints each plan's progress. The notes, the grid README and the memory say so; nothing is dispatched.
