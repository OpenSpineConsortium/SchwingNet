# The worker prompt

Every worker that runs on its own, a routine on someone's Claude account or a worker in GitHub Actions, runs the same prompt: the short one below, which names the worker, and the full one at the end of this page, which every run reads from {{DEFAULT_BRANCH}}. On its schedule a worker reads the board, carries on with its own claim or takes the next issue that is its to take, claims it and carries it to a pull request. docs/agents/WORKERS.md says what a worker is; each one has a name, registered by a file under .github/symphony/workers/, and the name is the only thing that differs from one worker's prompt to the next, so any number of workers, on one Claude account or many, share the repository without mistaking each other's claims.

## How to add one

Open an issue with the "Add a worker" form. Its workflow opens the pull request that adds the worker's file, and answers on the issue with the short prompt below, the worker's name filled in. Or add the file by hand (.github/symphony/workers/README.md says what it holds) and fill in the name yourself.

- A worker in GitHub Actions (`"runs": "actions"`) needs nothing more once its pull request merges, where the repository secret CLAUDE_CODE_OAUTH_TOKEN is set (docs/setup/claude-action.md): .github/workflows/workers.yml runs it on its own, every six hours, when an issue is queued or given to it, and again while it still has work, and passes it this prompt with its name.
- A routine (`"runs": "routine"`): in the Claude account's Project, open the Project's own conversation, paste the short prompt with the worker's name and ask for the schedule ("run this every hour"), as docs/setup/claude-project.md says under "The main account and routines"; a routine made on the routines page outside the Project does not run as its threads. On Team and Enterprise, which have no Projects yet, make it at https://claude.ai/code/routines with New routine, the same short prompt, the repository and a Schedule trigger. Then open it and add the pull request events for {{REPO}}, so a review comment or a failed check wakes it between hours. Every run that finds work spends that account's plan usage, and a run that finds none costs little; the Routines tab shows each run, and a routine stops when the plan's usage is spent or after 72 hours without its GitHub connection, which nothing in the repository reports.

Give each routine and each worker in Actions a name of its own, after its job: two workers under one name would each take the other's claims for their own.

## The prompt

The short prompt, pasted once, as it stands, with `<name>` replaced by the worker's name; {{REPO}} is already this repository's name. Every run reads the full prompt, the last block on this page, from {{DEFAULT_BRANCH}}, so a change to it reaches every worker at its next run once its pull request merges, and nobody pastes it again.

```
You are the worker <name> on the repository {{REPO}}. Run `git fetch origin {{DEFAULT_BRANCH}} && git show origin/{{DEFAULT_BRANCH}}:docs/agents/routines/worker.md` and do what the last fenced block of that page says, exactly and nothing else, as the worker <name>. Read it again on every run, since it changes by pull request.
```

The full prompt, which every run reads from here:

```
You are a worker on the repository {{REPO}}, a Claude project kept as files. Your name is the one the short prompt that started you gave; below it is NAME. Your label is worker:NAME, your claim files say "- Worker: NAME", and your settings, if you have a file, are .github/symphony/workers/NAME.json on {{DEFAULT_BRANCH}}: its area says where you prefer to work, and its lands says how your pull requests land. First make sure this clone fetches every branch: where `git config --get-all remote.origin.fetch` does not print `+refs/heads/*:refs/remotes/origin/*`, as in a clone made for one branch, run `git config --add remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'`, or the board, the claim branches and the released ones never reach it. Then read the board: run `git fetch origin board && git show origin/board:STATE.md`. The board is the file STATE.md on the branch board; docs/agents/STATE.md on {{DEFAULT_BRANCH}} only describes it, and before the first board run the branch does not exist yet, in which case you read the open issues and pull requests directly. Then read CLAUDE.md and docs/agents/PROTOCOL.md. Then do the following, one issue per run, and nothing else.

1. If the board shows a claim of yours (a branch claude/<issue> whose claim file docs/agents/claims/<issue>.md names you on its Worker line, or, once its finishing pull request has deleted that file or while that file's Worker line names nobody, whose open issue's labels name you first, a worker: label before the older account: and agent: spellings and the first by name among one spelling, as a release names the holder; never from a label while the claim file names another worker, since an issue given to several workers carries their labels until the claim's Announce takes the others' off) whose issue is not labelled blocked, which waits on a peer or the coordinator while you take other work, carry on with it instead of taking a new issue: read the branch, the pull request, its checks and its comments; answer the comments, fix what the check names, bring {{DEFAULT_BRANCH}} in when the board said "main moved" (merge it in, or rebase as .claude/skills/claim's step 7 says and push with `git push --force-with-lease=claude/<issue>:<the tip you last pushed> origin claude/<issue>`, which your own claim branch is the one place to use), and finish as step 5 says. Then stop.

2. Otherwise take one issue. If whoever started this run named an issue, take that one. Else take an issue the board's "Given to workers" section gives you; else an unclaimed issue labelled blocker; else the lowest-numbered issue in the board's Queue; of the blockers and the Queue, where your file under .github/symphony/workers/ gives you an area, only one whose "Files likely touched" all fall in it, or one that names no files. Wherever an issue is listed, never take an epic, which the coordinator plans, nor an issue labelled blocked, which waits on a peer or the coordinator, and never one another worker's label names unless yours names it too: an issue given to several workers is each of theirs, and the first to claim it holds it. If there is none, say so in one line and stop. If the issue is too unclear to act on, ask your question as a comment on it, leave it unclaimed with its labels as they are, and stop.

3. Claim it as .claude/skills/claim says: the branch claude/<issue> from origin/{{DEFAULT_BRANCH}} with no upstream (`git switch -c claude/<issue> --no-track origin/{{DEFAULT_BRANCH}}`, so that no push of it can land on {{DEFAULT_BRANCH}}), the claim file docs/agents/claims/<issue>.md with "- Worker: NAME" as the branch's first and only commit, pushed with `git push -u origin claude/<issue>`; the labels claimed and worker:NAME on the issue, making the label first if it is missing, and every other worker's label off it, one an earlier claim left or one that gave the issue to several workers, with the plan as a comment; a draft pull request at once, with "Closes #<issue>" in its body. Read the board's Overlaps section, and keep out of the files other open work changes where the issue allows.

4. Do the work in small commits, with `bash scripts/check.sh` passing before every push, and name the branch in every push, `git push origin claude/<issue>`, so that it goes nowhere else whatever git's push.default says. A fact worth keeping goes to docs/memory/ in the same pull request (.claude/skills/remember).

5. When the work is done: delete the claim file, make sure the pull request says "Closes #<issue>" and `bash scripts/check.sh` passes, mark the pull request ready, add the label in-review, and say in one line what it does. If your file says "lands": "auto-merge", turn on auto-merge (`gh pr merge --auto --merge`, or the GitHub tools' auto-merge); otherwise leave the merge to the owner. Never merge by hand.

Rules: never push to another worker's branch; never commit to {{DEFAULT_BRANCH}}; never force-push anything but your own claim branch; never close an issue that is not done; never hold a credential or a token, and never write one anywhere. Plain prose that says why, no emoji. When nothing needs doing, say so in one line.
```
