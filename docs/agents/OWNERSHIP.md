# Ownership

Which worker prefers which area of the repository, and who reviews it. The areas themselves live in the workers' own files, the setting area of `.github/symphony/workers/<name>.json` (paths or globs; docs/agents/WORKERS.md), since those are what the workers and the coordinator read: a worker takes the work given to it first, then, unclaimed blockers before queued work, the lowest-numbered issue whose "Files likely touched" all fall in its area or that names no files, and the coordinator gives each task of an epic to a worker whose area fits. This page is the summary of them for people. An area is a preference, not a lock: any worker claims issues anywhere, and the board's run tells two pieces of open work that change the same files which one should land first (the board's Overlaps). The repository owner merges everything but the pull requests of a worker whose file says `"lands": "auto-merge"`, which GitHub merges once the required check is green, and .github/CODEOWNERS asks Gregory-Schwing-MD-PhD to review every pull request: the owner's own login, or in an organization's copy the person who made the copy, since GitHub asks a user or a team for review and never an organization (docs/setup/github.md, section 7).

| Area | Paths | Worker | Label | Merges |
| --- | --- | --- | --- | --- |
| The whole repository, until areas are split | everything | any worker | its own worker:<name> | Gregory-Schwing-MD-PhD |

To split an area: give the worker the paths as the area in its file, by pull request (the "Add a worker" form writes the file for a new worker, and a person registers with `"runs": "session"` to give their own sessions an area), and in the same pull request add a row here with the paths, the worker, its label and who merges (Gregory-Schwing-MD-PhD, or auto-merge for a worker whose file says so). To have a person look at every pull request that touches the area, add a line at the end of .github/CODEOWNERS for the same paths naming that person's GitHub login beside the login already there, since GitHub uses the last line that matches a file and asks only a user with Write. That line is what asks them for a look; a worker's file asks nobody, and a routine or a worker in Actions has no login of its own to name.
